# 后人纪界面视觉设计规范（网页与微信小程序）

- **范围**：`public/` 的网页（观测站、我的居民、余额与充值、账户设置、管理后台、登录页、支持页），以及 `wechat/` 的微信端：普通小程序 `miniprogram-app/` 和小游戏 `minigame/`（两者共用同一套 Canvas 界面）。
- **读者**：设计并实现界面的人和代理（Codex、Claude 等）。每次都读第 1、2、5、6、7 节；改网页再读第 3 节，改微信端再读第 4 节。
- **真源**：具体数值以代码为准：网页在 `public/style.css` 的 `:root`（观测站与公共组件）和 `public/console.css`（会员页、管理后台、登录页），微信端在 `wechat/minigame/ui/theme.js`。本文件讲这些数值的含义、用法和取舍。两边不一致时以代码为准，并顺手改本文件。
- **依据**：origin/main `471a827`（2026-10-14）。

一句话风格：**夜里的城，安静的工作台。** 深色为主、暖白纸页为辅；细线分区，颜色少而一色一义；数字醒目，AI 写的字有标记；门面用标志的夜蓝与月白、宋体标题和自制插画营造「人类退场后的城」，工作台只留内容。

## 1. 工作流程

每次新建或改动界面都按这六步走，每一步做到「完成」才进入下一步。

1. **一页一事。** 用一句话写下：这个页面（或区块）给谁用、用来完成哪一件事。不同的人、不同的事分开放：玩家看居民、充值、账户设置、管理员后台是四个页面。
   - 完成：这句话写得出来；页面上每个区块都归在这件事下面，归不进去的移到别处。
2. **选画面。** 从第 2.1 节的三种画面里选一种。
   - 完成：说得出为什么选它；页面里只有这一种主画面。
3. **列内容与状态。** 列出要显示的数据和操作，排出主次，每屏只有一个主操作。再写出每种状态的样子：加载中、空、出错、未登录、无权限、只读，以及数据很长（长名字、长编号、长段落）和很多（几百条）的时候。
   - 完成：每种状态都有对应的文字和样子。
4. **用现成组件拼。** 网页用第 3.6 节、微信端用第 4.5 节的组件；颜色只用变量（网页）或 `C.*`（微信端）。确实需要新组件时，加进共用模块（网页 `public/console-ui.js` 与 `public/style.css` / `console.css`，微信端 `ui/nodes.js`）并补进本文件。
   - 完成：新代码里没有新写死的颜色、字号和圆角（第 2.4 节的插画例外）。
5. **实现。** 守住第 3.1 / 4.1 节的硬约束；文案照第 5 节。
6. **看图验收。** 在真实浏览器或微信预览里截图，逐条过第 6 节清单，有问题就改，改完再截图。
   - 完成：清单每一项都有截图或测试输出为证，交付说明里附截图并注明宽度与主题。
   - 不能看图时（比如沙箱不能监听端口、打不开浏览器），照常完成实现，在交付说明里写明「未看图验收」，并列出要别人截图核对的页面、宽度和主题。

改版级别的变动（换画面、换导航、换配色、重排整块功能区）先在 `docs/plans/` 写方案，附用真实数据做的样稿，等用户拍板再实现。在现有风格里加一块面板、改一个表单，直接按上面六步做。

## 2. 风格总纲

### 2.1 三种画面

| 画面 | 用在哪里 | 气质 | 颜色 |
|---|---|---|---|
| **纸页与墨色**（工作台） | 观测站的外壳与侧栏、我的居民、余额与充值、账户设置、管理后台、支持页 | 安静、清楚、信息密；细线分隔，没有装饰 | `style.css` 的变量。深色是默认（幕后的夜），系统偏好浅色时换成暖白纸页 |
| **屏幕**（城市地图） | 观测站的地图 | 夜里的监视屏：霓虹线稿加废土 | `.map` 的 `--m-*` 变量，永远是深色，不随浅色主题变亮 |
| **月下城**（门面与微信端） | 登录页，微信小程序与小游戏的全部界面，分享卡与宣传图 | 夜空、月光、宋体标题；有场景感但不喧闹 | 标志的夜蓝 `#19364D` 与月白 `#FFEDCE`；微信端见 `theme.js` |

选法：管理与阅读用纸页；看城市本身用屏幕；第一次见面（入口、登录、手机里）用月下城。一个页面只有一种主画面。现有两处有意的混用：地图作为一块「屏幕」嵌在纸页里；登录页的场景永远是夜，而登录卡片跟随系统深浅色。

### 2.2 原则

每条后面是它的来由，都是本仓库里真实发生过的事。

1. **结构先于装饰。** 好看首先来自分区和层级：先定一页一事、主次和分组，再谈颜色。
   - 来由：网页版曾把管理员配置、充值和居民状态混在一起，拆成四个功能区之后才清楚。
2. **一色一义。** 每种颜色只表示一种意思（第 2.3 节）。主按钮、选中、提示、状态各有各的颜色。
   - 来由：旧版小游戏的金色同时表示主按钮、提示、选中和「地图上有人」，用户分不清；改版后月白只给主按钮和选中。
3. **层级靠字号、字重、留白和文字深浅。** 标题 600 字重，正文 400；次要信息用次要色；区块之间用留白和 1px 细线。分区用边框和留白，不用渐变底、大面积阴影或彩色背景块。
4. **元素按角色区分。** 主按钮、次按钮、文字按钮、输入框、列表行、标签各有一眼能认出的样子，控件的边界与背景看得出差别。
   - 来由：旧版小游戏只有「文字段落」和「通栏长方块」两种元素，按钮、输入框、勾选框、列表项长得一样，按钮底色与背景的对比只有 1.11:1。
5. **克制的强调。** 每屏最多一个实心主按钮（网页 `--accent`，微信端月白），其余用描边按钮或文字按钮。强调色只用在「可以点、当前位置、主操作」上。
6. **数字是主角。** 余额、词元、人数、日期放进大一号的数字块，用等宽数字（`tabular-nums`），带单位，格式统一（第 5 节）。
7. **AI 写的字要看得出来。** 居民和模型写的文字带 AI 标记（网页 `ai()` / `.ai`，微信端「AI」标签）；系统写定的句子不标；公共角色写定的文本标「公共角色」。
8. **门面有氛围，工作台安静。** 登录页和微信端有夜空、月亮、插画和宋体标题；工作台里没有插画，没有持续的动画，只有内容。氛围靠自制的矢量图和 CSS / Canvas 绘制，颜色取自标志。
   - 来由：登录页第一版用户说「太素了」，加了原创的「月下城」插画、CSS 画的月亮与星光之后才定稿。
9. **按真实像素画。** 图表、地图标签、Canvas 都按实际显示尺寸绘制，屏幕上的字号就是设计的字号（图表文字 12px）。适配宽度靠重新布局和重画，不靠把 SVG `viewBox` 或整张图等比缩小。
   - 来由：指标页的图固定 640 宽再缩小，宽屏两列时字号折算只有 5.7px；改为按容器实际宽度绘制后才看得清。
10. **状态齐全。** 加载、空、出错、未登录、无权限都有专门的样子，并给出下一步（重试、登录、去创建）。错误写在用户看得到的地方：网页写在页头下的提示行或字段下方，微信端用顶部轻提示。
11. **看图验收。** 截图看过才算完成：手机宽与桌面宽、深色与浅色、中文与英文、空数据与长数据。
    - 来由：登录页英雄区的暗色衬底在手机上撑出 48px 横向溢出，代码检查和测试都没发现，是看截图才发现的。

### 2.3 一色一义

| 意思 | 网页（纸页与墨色） | 微信端（月下城） |
|---|---|---|
| 可以点、当前位置、主操作、焦点 | `--accent` | 月白 `C.moon`；月白上的字用夜蓝 `C.ink` |
| 正常运行、醒着、通过、成功 | `--good` | `C.awake` |
| 需要人去处理：待处理、余额不足、未配置、未启动 | `--warn` | 横幅 `banner` 加月白按钮；暂停、未配置的状态标签用 `C.dormant` |
| 失败、错误、不可逆的坏结果（长眠、驱逐、拒绝） | `--bad` | `C.danger` |
| 已结束、不活跃；说明文字 | `--muted` | `C.text3`、`C.dormant` |
| 词元（游戏里的货币）数量 | 正文色的数字块 | `C.token` |
| AI 生成的文字 | `--ai-bg` 底色、`--ai-line` 虚线框 | `C.ai` 的「AI」标签 |
| 数据系列、事件分类 | `--c0`…`--c5`（只做线条、色块、左边框） | 地图与图例用 `C.map` |

### 2.4 例外：可以写死颜色的地方

- 插画与场景：地图（`.map` 的 `--m-*`、`ui/map.js`）、登录页场景（`.login-scene`、`login-bg.svg`、月亮与星）、标志与印章（`logo.svg`、`public/roles/*.svg`、`P.seal`）。它们是画，颜色固定，不随主题变化。
- 收款码卡片固定白底（二维码需要白底）。
- 其余地方只用变量或 `C.*`。需要新颜色时先加进 `:root`（深色、浅色两套都给）或 `theme.js` 的 `C`，写明用途，再使用。

### 2.5 品牌

- 标志 `public/logo.svg`：夜蓝圆、月白满月、议会穹顶与两座塔。会员页顶栏 28px，观测站顶栏 40px，微信顶栏 26px（Canvas 里由 `paintLogo` 画）。不改色，不加描边或阴影。
- 名字：网页中文写「后人纪 · 词元本位」（中点两侧各一个空格），英文「The Heirs: Token Standard」；小游戏启动页与页脚用平台审核过的「后人纪之词元本位」；普通小程序名「后人纪」。
- 宋体只用在仪式性的标题上：登录页大标题、入境向导的步骤标题、微信端的标题层级（第 4.3 节）和印章里的字。正文、表格、按钮、表单一律用系统黑体。
- 新插画照登录页的做法：原创矢量图，用脚本以固定种子生成，颜色取自标志，体积控制在几十 KB 以内。不用图库照片、外链图片和 emoji。

## 3. 网页（public/）

### 3.1 硬约束

前三条有 `test/ui.test.js` 把关。

- **内容安全策略**是 `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'`（`src/http/server.js`）。样式只写在 `style.css` / `console.css` 里；脚本改外观用 `classList`、`hidden`、SVG 属性或 CSSOM。不写 `style="…"`、`<style>`、内联脚本和 `onclick=`；不用 `setAttribute('style')`、`.cssText`、`innerHTML`、`insertAdjacentHTML`。
- **只加载本站资源**：系统字体栈，不引网络字体、CDN、第三方 UI 库或图标库；图片用本站文件或 `data:`。
- **原生 ES 模块，不用框架和打包**。DOM 用 `public/dom.js` 的 `h()` 构建，文字一律经 `textContent`；居民写的文字用 `ai()` 包起来。前端里写的 `/api/...` 路径会被测试扫描并请求，带插值的路径要在 `test/ui.test.js` 里照已有写法加例外。
- **代码照周围的写法**：中文注释，一行一条 CSS 规则，不压成一行；类名用短横线小写；尺寸用 px，需要随视口变化时用 `clamp()`、`min()`、`vw`，不用 rem。

### 3.2 颜色

`style.css` 的 `:root`：深色是默认，`@media (prefers-color-scheme: light)` 里是浅色。

| 变量 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg` | `#0a0d13` | `#f3f1ec` | 页面底 |
| `--panel` | `#10151f` | `#fffdf9` | 卡片、顶栏、弹窗、抽屉 |
| `--panel-2` | `#161c29` | `#f6f2ea` | 卡片里的块、输入框、按钮底、悬停与当前导航的底 |
| `--line` | `#263047` | `#d9d2c4` | 容器边框 |
| `--line-soft` | `#1b2436` | `#e8e2d6` | 容器内的分隔、表格行线 |
| `--text` | `#dde3ee` | `#1d2230` | 正文 |
| `--muted` | `#8a95aa` | `#666e80` | 次要文字、标签名、说明、表头 |
| `--accent` | `#6ea8ff` | `#2456c4` | 主按钮、链接、当前项、焦点框、eyebrow |
| `--accent-ink` | `#06122a` | `#ffffff` | 主按钮上的字 |
| `--good` / `--warn` / `--bad` | `#58c98a` / `#f2b46d` / `#ef6b6b` | `#1b8a53` / `#b56a10` / `#c23a3a` | 第 2.3 节的三种状态 |
| `--ai-bg` / `--ai-line` | 强调色 9% / 35% | 强调色 7% / 35% | AI 文字的底色 / 虚线框 |
| `--c0`…`--c5` | 蓝、绿、橙、红、紫、青 | 同深色 | 图表系列、事件分类 |
| `--shadow` | 深 | 浅 | 只给浮层 |

主要对比度：深色下正文 14.2、次要 6.1、强调 7.6；浅色下正文 15.6、次要 5.0、强调 6.5。`--c0`…`--c5` 在两种主题里是同一组亮色，放在浅色纸页上做文字只有 1.8–2.5:1，所以它们只做线条、色块、图例和左边框；文字的语义色用 `--good`、`--warn`、`--bad`、`--accent`、`--muted`。

### 3.3 字体与字号

- **字体栈**：黑体 `system-ui, -apple-system, "Segoe UI", "PingFang SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif`；等宽 `ui-monospace, "SF Mono", Menlo, Consolas, monospace`（编号、代码、JSON，12px）；宋体 `"Songti SC", "Noto Serif CJK SC", "Noto Serif SC", "Source Han Serif SC", "STSong", "SimSun", Georgia, serif`（只给第 2.5 节说的标题）。
- **正文** 14px，行高 1.5。
- **字号阶梯**：11（标签、时间戳）· 12（说明、eyebrow、图表文字）· 13（表格、字段名、次要行）· 14（正文、按钮）· 15（三级标题）· 16（卡片标题、弹窗标题）· 18（空状态标题）· 20–24（数字块）· 28（会员页大标题，手机上 24）· 登录页宋体大标题 `clamp(34px, 4.6vw, 60px)`。
- **字重**：标题与数字 600，正文 400，表头 500 加次要色。新界面不用 700 及以上（登录页的宋体大标题和地图标签除外）。
- **小标签字**：eyebrow 12px、`--accent`、字距 0.16em；管理后台侧栏的分组名 12px、`--muted`、字距 0.12em；品牌字距 0.06–0.08em。
- 数字一律 `font-variant-numeric: tabular-nums`。

### 3.4 间距、圆角、线与阴影

- **间距**取 4 的倍数，常用 4、8、12、16、20、24、28。观测站紧凑（面板内边距 10–14）；会员页宽松（卡片内边距 20、手机 16，区块间距 16，正文上下 28 / 64）。
- **圆角**：标签 10、胶囊 999；按钮与输入框 6（观测站）/ 8（会员页）/ 10–12（登录页）；卡片 8（观测站）/ 10（列表项、数字块）/ 12（会员页卡片，`--radius`）/ 20（登录卡片）；弹窗 10。
- **线**：容器 1px `--line`；容器内分隔与表格行 1px `--line-soft`；空状态、AI 说明和占位用虚线。状态可以用 3–4px 的左边框表示（实况事件的分类、提示条 `.callout`、提案通过或否决）。
- **阴影**只给浮在页面上的东西：弹窗、抽屉、下拉菜单用 `--shadow`，登录卡片有自己的深阴影。卡片靠边框分隔，不加阴影。

### 3.5 布局

**会员页**（`console.css`）：

- 顶栏 `.console-header`：吸顶，高 56。左边品牌，中间导航，右边账户胶囊（首字圆标加昵称）。当前页的导航项 `aria-current="page"`：底色 `--panel-2`、底部 2px 强调线、600 字重。顶栏左右内边距 `max(16px, calc((100vw - 1168px) / 2))`，和正文对齐。
- 正文 `.console-main`：宽 `min(100%, 1168px)` 居中，内边距 `28px 24px 64px`（≤640px 时 `20px 16px 48px`）。
- 页头 `pageHead()`：返回链接 → eyebrow（这页属于哪一块）→ 大标题 → lead（一句说明，最长 72ch）；页面级操作放右边，底部对齐。
- 主体：卡片 `.card-panel` 纵向堆叠，间距 16；卡片里的小节用上边细线隔开。网格一律 `repeat(auto-fit, minmax(min(100%, Npx), 1fr))`，N 取：卡片 340、居民卡 280、数字块 150、设置 360。概览四格 `.summary-row` 在 ≤860px 变两列。
- 管理后台：左侧 208px 的分组导航，吸顶（top 76），当前项左侧 3px 强调线；≤860px 时变成顶部一行可横向滑动的按钮。各分区用 `#编号` 路由。

**观测站**（`style.css`）：顶栏可换行（品牌、时钟、人口、公库、源井、天象，右侧按钮）。主体两栏 `minmax(360px, 1.45fr)` 与 `minmax(360px, 1fr)`，左边地图，右边标签页；≤899px 变单栏，地图按比例在上，侧栏在下。详情用右侧抽屉（宽 460），操作用弹窗（520，宽版 760）。

**断点**：900（观测站、登录页变单栏）、860（管理后台导航）、640（会员页顶栏换行、边距变 16）、560 / 540 / 480（表格隐藏次要列、表单变单列、卡片内边距收小）。

**手机**：左右留 16px。宽表格放进 `.scroll-table` 横向滚动；页面本身在任何宽度下都没有横向滚动条，装饰性的外扩用 `overflow-x: clip` 收住。

### 3.6 组件

会员页用 `public/console-ui.js`：

| 要做的 | 用 |
|---|---|
| 顶栏 | `mountShell(header, { active })`；新增导航项改其中的 `NAV` |
| 页头 | `pageHead(root, { eyebrow, title, lead, actions, back, media })` |
| 卡片 | `card(title, note, ...children)` → `.card-panel`；`note` 是标题下一行次要色说明 |

## 4. 微信小程序与小游戏（wechat/）

### 4.1 结构与硬约束

- 主界面整个画在一块 Canvas 上，没有 DOM：控制器 `minigame/society.js`，页面 `minigame/screens/`，界面层 `minigame/ui/`（`theme` 色板与字号、`text` 换行与缓存、`paint` 圆角 / 图标 / 印章、`nodes` 组件、`scroll` 惯性滚动、`map` 地图）。
- 普通小程序 `miniprogram-app/` 在 `<canvas type="2d">` 里跑同一份控制器（构建时复制到 `runtime/`，`runtime/` 不手改）。原生 WXML 只用在 Canvas 做不了的地方：键盘输入层、加载失败提示、网页扫码登录的确认页 `pages/web-login`。
- 新界面先写成 Canvas 组件（`ui/nodes.js`）和页面（`screens/`），小程序与小游戏同时得到；只有输入、平台确认这类必须原生的部分才写 WXML。
- 事件句式在 `utils/shared-text.js`，由 `wechat/scripts/shared.mjs` 从网站的 `public/i18n.js` 等生成，与网站同源。要改句式，改网站那边再重新生成。
- 只用各端 Canvas 都支持的基础指令（照 `paint.js` 的写法）；颜色写十六进制（有的端不认 `hsl()`）。
- 不用模糊、大面积阴影和渐变铺底。

### 4.3 字体与字号

- 字号用 `size(name)` 取（字号 / 行高，px）：display 26/34、title 21/28、heading 17/24、body 16/26、feed 15/24、action 14/22、meta 13/19、caption 12/17、tiny 11/14。设置里的「大字」把除 tiny 外的字号放大约 12%，所以组件都在构建时按宽度和字号算高度，布局能随字号长高。
- 系统字体是 `sans-serif`。宋体子集 `fonts/HeirsSerif.ttf`（Noto Serif SC 固定为粗体后的子集，只含界面里写定的字）只给标题层级：顶栏标题、小节标题（`N.section`）、启动页、个人页与档案的大标题、「史官曰」引文和印章；正文、按钮、列表用系统字体。`font(size, { serif: true, text })` 逐字检查是否在子集里，有一个字不在就整串退回系统字体，所以居民名字这类动态标题常常显示为黑体，这是预期的。
- 普通小程序适配器没有小游戏的同步 `loadFont` 能力时，已覆盖的固定标题使用系统 `serif`，正文及未覆盖的动态名字仍用 `sans-serif`，避免为字体在冷启动时联网。小游戏加载子集成功后继续使用子集；系统衬线字体的具体外观以真机为准。
- 新增或改了宋体显示的固定文字后，用 `node wechat/scripts/subset-font.mjs <NotoSerifSC[wght].ttf> <OFL.txt>` 重新生成子集（源字体不在仓库里，没有就问用户要，或经同意后下载），再在预览里确认标题仍是宋体。居民名字等动态文字不进子集，用系统字体。
- 排版用 `ui/text.js`：中文标点避头尾、英文单词不拆、按（文本、宽度、字体）缓存；截断用 `T.clamp`（多行）和 `T.ellipsize`（单行）。

### 4.6 页面骨架

- **顶栏**：按 `wx.getMenuButtonBoundingClientRect()` 避让右上角胶囊，内容与胶囊垂直居中。三种：品牌（标志 26 加宋体 19 的城名）、返回（左箭头加 17px 粗体标题）、标题（宋体 22）。
- **底部导航**：观测 / 居民 / 档案 / 我的，图标 24 加 11px 文字；当前项月白，其余 `text3`；底色夜栏，上边 1px 线，高度包含安全区。
- **底部弹出卡片**：遮罩 `rgba(5,10,16,0.55)`，夜栏底，圆角 22，顶部有抓手条，最高占屏幕 82%。
- **轻提示**：顶栏下方居中的胶囊，高 40。成功是暖白底、夜蓝字、勾；错误是暗红底、浅红字、i。成功 2.2 秒、错误 3.2 秒后消失。表单错误同时写在字段下方。
- **滚动**：惯性、回弹、下拉刷新（「下拉刷新 / 松开刷新 / 正在刷新…」），滚动时右侧出现细滚动条。
- **按下**：变暗或变石阶；轻震 `vibrateShort({ type: 'light' })`，设置里可以关。
- **实况页的写法**：用 `rule` 按刻分组；动作行是圆形线性图标加一句话；发言用气泡（石阶底，超过 3 行折叠，「展开全文」）；日终是摘要卡（宋体标题，词元数用 `token` 色）；未审核的居民文字显示虚线框加锁的占位（「微信登录后可阅读这段内容」）。

- **报告和导出**：`screens/history.js` 共用 `card`、`text`、`section`、`chips`、`field` 和按钮，保持月下城配色。报告全文标记 AI，事实与分析分节；导出发起、导出记录为两个页面。长筛选标签限于容器宽度并省略，触控区域至少 44px；小节链接也采用至少 44px 的触控区域。

### 4.7 原生页面（WXML / WXSS）

- 原生页面要和 Canvas 页面看起来是同一个应用，数值照 `theme.js` 取：页面底 `#0A1520`，卡片 `#132433`，输入框 `#1A2E40`，正文 `#EDEAE3`，次要 `#A9B6C2`，说明 `#8796A6`；主按钮月白 `#FFEDCE` 底、夜蓝 `#19364D` 字、圆角 14、高 46；次按钮透明底、`#33506B` 描边。
- 用 px 写，数值与 Canvas 一致（左右 16、卡片圆角 16、按钮高 46），这样同一台手机上两边对得齐。
- 覆盖微信默认的按钮样式（默认的绿色主按钮不用）；`checkbox`、`switch` 的 `color` 用月白。
- 格式照仓库里其他样式文件：一行一条规则，中文注释。

### 4.8 合规项（不能改）

- 每次冷启动先显示 16+ 和健康游戏忠告，点「进入城市」之前不联网、不显示导航。
- 登录、创建居民、配置模型之前分别勾选同意。
- AI 生成内容一律标记。文字和图片通过微信内容安全检查后才显示；未审核的居民文字显示占位，不出现成片的「内容审核中」。

## 5. 文案

- **语言**：中文为主。观测站与登录页中英双语（`i18n.js` 的 `t()`，页面里的 `tr(zh, en)`）；会员页以中文为主，顶栏双语。新页面照所在页面的做法；有语言切换的页面，每一句都有英文。英文通常更长，排版留出余量。
- **用词**：
  - 「词元」是游戏里的货币；「token」只指模型用量（输入、输出、缓存命中 token）。平台托管额度买的是模型调用，不是词元，也不带来游戏内优势。
  - 居民、公共角色、造者、家书、摇篮、长眠、归隐、过继、领养等，沿用 `public/i18n.js` 和现有页面的叫法，不另造同义词。
  - 世界时间写「第 N 日 · 第 M 刻」；现实时间写清时区。
- **句子**：短句，说清后果和下一步（「补足后下个作息时刻自动恢复」）。按钮用动词短语（创建居民、提交入账申请、去充值）；状态用名词短语（醒着、托管已暂停、未配置模型）；进行中写「正在加载…」「正在处理…」。语气平实，不用感叹号、emoji 和营销腔。
- **格式**：中文用全角标点；数字与汉字之间空一个半角空格（第 3 日、共 2 笔）；并列的元信息用「 · 」分隔（中点两侧各一个空格）；没有值时显示「—」。金额用 `public/hosted-ui.js` 的 `money()`；微信端的数字用 `utils/format.js`（一万以上写「万」，一亿以上写「亿」）。
