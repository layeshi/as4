版本：MS-0.2，2026-10-11。状态：用户已确认，已完成本地实现与 mock 验收；尚未部署或进行真实模型经济标定。实施结果见 [验收记录](validation/MS-0.2.md)。

范围更新：Q19–Q23 已确认的两条未明规律已纳入 §14。用户已确认整合后的实现契约及工程初值。确认范围为设计定稿，不包含代码实施或生产部署；生产私有参数仍按 §14 在创世时配置。

依据：[统一设计](plans/2026-10-11-materials-and-resident-services.md)及本轮已确认决定。代码核对基线 `f978d11`；编码前须核对最新远端差异，不能直接以当前本地旧检出实现。本文给出新世界契约，不覆盖旧世界规格。

## 0. 范围与解释顺序

已确认的产品决定以统一设计为准；本文的命名、初值、算法与状态结构已随 MS-0.2 整体确认。新版本用 `PREMISE=5`、`map=compact-materials-v1`，基于 P4，不包含未实现的第三前提。若实施时版本号已占用，只调整版本标识与相关测试，不复用旧版本。

包含：新地图、物料、施工、研究所、待领物料、服务告示、需求、固定价订单、结构化验收、托管结算、两条未明规律及环境记录。排除：两级制造、载重、独立仓库、科技树、主观质量仲裁、服务编程语言、竞价、多人接单、自动分包、分段付款、任意代理授权、生产部署。

新居民不带物料；P4 的基本额度、真实模型供养上限、词元计价、隐私与守护权沿用。新设施与服务不会降低真实模型账单。名称“研究所”不意味着额外调用模型做科研。

## 1. 世界版本与不变量

1. 新物料相关状态、动作、文案仅出现在新版本。旧 0/1/2/4 世界不增加默认字段，不变更旧回放的遍历顺序或结算结果。
2. 不能仅把 `premise` 加入枚举：`tokenized` 当前严格等于 4，应明确支持 4 和新版本；不得用无限开放的 `>=4` 偷渡未来版本。P4 固有行为由 tokenized 控制，本文行为另用 `materialsEnabled(w)`。
3. 地图定义按世界的 map/version 选择，不替换旧静态地图。创世记录保存版本、地图与本文参数；回放不依赖运行时环境变量的新值。
4. 所有数量为非负安全整数，求和和乘法使用检查过的整数或 BigInt 中间值。随机抽奖不用于物料采集；按命令日志顺序决定并发胜者。
5. 全部移动、交易、施工和结算进入同一个世界命令事务。外部 HTTP 重试不能重复接单、发物料或付款。
6. 全城词元持有量包括基本额度、普通余额、工程未用投入、交易托管与订单托管。冻结、退款、付款只是转移，不计为新供给或消耗。
7. 托管报酬不参与持有者腐坏、不供法律抽取、不计可用余额；结束后回到普通余额，后续正常腐坏。为防长期藏钱，等待期和履约期有硬上限，禁止自买自卖订单。
8. 物料总量账：初始总存量＋累计再生＝居民库存＋待领物料＋专项携带物料＋工程未用投入＋交易托管＋地带可采量＋结构可回收量＋累计不可回收损耗。采集、拆解是位置/形态转移，不重复记供给。
9. 原始命令、订单条款、验收证据不可改写或删除；当前索引可以重建。

## 3. 物料、领取与交易

### 3.1 状态

新增 `a.materials`（自由库存）；`w.materialClaims`（待领记录）；`w.materialZones`（可采量、上限、当日已采量；基础再生参数按 §14 私有保存）；`w.materialLedger`（累计初始、再生、损耗）；新结构保存 `materialRecoverable`。不使用 P4 的 energy salvage 作为新物料账。

待领记录：`{id,place,amount,beneficiary,source,createdTick}`。beneficiary 为 agent、group、city 或 public。不得使用此记录任意存放居民库存；只由继承、工程/交易退款或强制归还专项物料生成。

- agent 权利：本人到场领取，自由库存增加。本人死亡/归隐，权利按遗嘱分配并保留原地，不能凭空转到死亡地点。
- public：任何醒着的居民可到场领取，扣减实际可领数量。
- group/city：专项物料，获授权居民领取后记为 `a.earmarkedMaterials[{claimId,beneficiary,amount}]`，与自由库存分开；这是携带用途约束，不是远程仓库。仅可投入该主体所有的公共工程或修缮其公共设施，不能出售、赠予或用于个人工程。无现场可用工程时可原地放回同一领取点。工程退款和居民离世后保持专项归属。
- 社群管事可指定领取人；城法可以授予 `public_builder` 标签，持有者可领取城有专项物料。新遗法默认所有在世居民可领取城有专项物料，只能用于城有资产，居民可修法收紧。标签不授予普通余额控制权。

上述专项携带字段已随整合规格确认，用于落实“领取并投入公共工程”。

社群解散时，其待领、携带中及尚未消耗的工程专项权益统一转为城有专项，数量和地点保持不变。合法转让某个设施不会自动转让主体的其他专项物料；已投入该设施工程的专项预算保留原来源，可按原工程用途继续消耗，终止退款仍回原专项主体（已解散则归城）。尚未投入的专项库存不能因目标转为私人所有就跟着私有化。

### 3.2 动作契约

新增 `gather {amount?}`：只能在回收地带，缺省请求每次上限，结果为 min(请求、可采量、动作上限)，为 0 时失败且不收物理费。收费与减少地带存量、增加库存原子提交。

新增 `claim {claim,amount?}` 和 `return_materials {claim,amount?}`：本人位于原领取点，正整数，不超过余额。专项返还不转为自由库存。

`give` 新增 `materials?`：非零时只能给同地居民；混合词元、旧币、物料转赠整笔成功或失败。不能通过 give 给抽象社群物料账户。

`offer/accept` 新增物料字段：在挂牌时锁住卖方出售的自由物料，锁定于挂牌地点；含物料的交易双方成交时都须在该处，词元-only 定向交易仍沿用 P4 远程规则。撤单/到期时卖方若不在该处，生成待领物料，不能远程返还；死亡退款进入物料继承。专项物料不能挂牌。

`explore` 保留 P4 遗物、旧币及词元发现机制，不额外产物料；确定性物料来源只走 gather。探索池总容量和总再生按 §2 保留，拆解改为物料则有意减少旧词元来源，两者不可混淆。`dismantle` 在新世界改收 `materials?`（缺省每次上限），返回物料，不接收含糊的 energy 数量参数；仍不能拆源井、港口。现有拆解许可法与权限继续适用。

建筑与加装模块分别保存回收余额；拆模块只扣该模块，拆尽建筑时依旧按既有模块随建筑消失的语义将未回收模块余量记入物料损耗，不能既回收建筑总量又重复发模块物料。自然衰败不凭空增加残料；拆解造成的完好度变化沿用 P4 按剩余可回收比例计算，回收量本身已包含建造时的损耗，拆解时不再重复乘 50%。

### 3.3 继承

以现有遗嘱份额分配自由物料和个人待领权，向有效居民、社群、公库按份额分配；无效个人份额与取整余数公开回收。新增遗嘱接收方 group 只用于新版本，需同时定义其词元/旧币按社群账户正常接收。不重开已完成历史继承：未来工程退款的权利应在出资者死亡时转成继承受益份额。

避免继承环：只分配给当时在世居民或存续社群；已死亡受益人不再递归追溯。尚存个人领取权不设过期，归隐按死亡处理。普通代持物料仍是个人库存，社群要约束用途须使用交付订单；不把代持默认为公库资产。

## 4. 工程与维修

### 4.1 数据与阶段

工程增加 `{needEnergy,needMaterials,needWork,progress,spentEnergy,spentMaterials,lastProgressTick,access,contributions,materialRecoverable}`。access 为 public、owner 或 group；城有默认 public，个人默认 owner，社群默认成员。主人/管事可调整尚未执行的参与权，不收回已完成工作。

阶段：`funding → building → built`，funding/building 可进入 cancelled/abandoned。所有总投入达到 need 后封闭募集，才进入 building；投入不足不能施工。单次投入只收剩余需求，不扣超额。

`initiate` 沿用 site/module/road/upgrade；增加 access。`contribute {project,energy?,materials?,claim?}` 必须位于工程地点；claim 指定专项携带来源。城法 fund 可远程出词元，但不能远程出物料。

新增 `construct {project,research?,maxResearchFee?}`：到场、符合参与权，基础工作量先获研究所名义加成，再按 §14 计算实际效率和剩余工作量截断。新动作占 1 名额，基础物理费 1K；材料和工程词元另从工程已收投入消耗。`cancel_project {project}`：个人主人、社群管事可调用；城有工程由城法操作 `cancel_project` 决定，初始遗法允许发起者申请撤销自己发起的未完成城有工程，但不能取走他人投入。

### 4.2 确定性消耗

设总工作 W、已有进度 p、本次实际增加 d=min(§14 求得的实际效率,W-p)。工程总体应消耗量使用逐出资份额累积：对每个来源 i，总投入 C_i，已消耗 floor(C_i*p/W)，本次扣 floor(C_i*(p+d)/W)-floor(C_i*p/W)。词元与物料分别计算。完成 p=W 时全部预算恰好消耗；不使用每次独立向上取整，避免分步顺序导致多扣。

每次已消耗物料的一半转为结构可回收量，另一半记损耗，以累计 `floor(spentMaterials/2)` 差额更新，避免小步拆分套利。完成建筑保存该回收余额。维修材料全记损耗，不增加结构可回收上限。

contributions 按命令序与稳定 ID 排列，保存每笔来源、受益人、数量及消耗；继承和退款份额可以追溯到原笔。施工者不同不改变同一最终进度的工程预算消耗；每次额外动作费及研究所费按实际行动收取，因此低效率可能增加行动总成本。

### 4.3 终止

发起后或最后一次有效施工后连续 24 世界日无进度，按 project ID 顺序烂尾；出资、改名或改权限不能刷新施工时钟。终止一次性退还未消耗词元，生成原地待领物料；专项投入退回专项归属。已形成的可回收结构保留为工地残留，dismantle 仍到场且守权限；残留清除前不重复占用同一地块建造。已完成工作不回退。

工程持有人消失不吞没贡献者财产：首版沿用既有孤产归城方向，个人主人死亡或归隐、所属社群解散时，未完成工程产权归城，参与政策恢复公共；不引入多继承人共同工程产权。出资退款权和待领物料仍按遗嘱份额继承，与工程产权分开。此处理先于依赖该工程的订单存续判断；所有者离世不等于工程消失，但以其为订单一方的单据仍按 §8 终止。

### 4.4 维修

`repair {target?,energy,materials,research?,maxResearchFee?,claim?}` 中 energy/materials 为调用者愿意支付的上限。目标位置约束沿用 P4。每个材料修复至多 100 bp，词元效率沿用 P4 正常/低完好度倍率（每 K 词元分别 10/5 bp），单动作维修上限 500 bp，有研究所为 750 bp。

实际修复 r=min(缺损,动作上限,materials*100,floor(energy/K)*rate)。r=0 失败；实扣材料 ceil(r/100)，词元 ceil(r/rate)*K。只增加单次行动容量，不降低单位材料和词元成本；修满后多余预算不扣。专项物料仅修其所属主体资产。原 P4 自然衰败和源井生产公式不变。

## 5. 研究所

新增 research 模块：建造参数见 §9，运转阈值 3000 bp，每日附加衰败 20 bp。全城可用，无距离倍率。研究所服务不会执行施工，只改变调用者当前行动可完成工作量。

`research_policy {place,access,agents?,groups?,fee}`：所有者/管事设 public、owner、allowlist；个人及社群设施按所有者授权，城有设施通过城法 `research_policy` 操作管理，初始 public、fee=0。

施工或维修可显式选 research ID 和 maxResearchFee；若未选，不自动扣费，自动采用可用的免费研究所中 ID 最小者。显式选的设施失效、拒绝授权或报价超限则本动作失败，不悄悄降级收费；没有可用免费研究所时走基础效率。多座不叠加。

收费从执行者可转让词元到设施所有者账户，含本次已知法律费用在内一并检查；动作成功才付，失败不收。付款与效率应用、维修或施工变化原子提交。政策修改不追溯，但每次行动读取当前政策；订单报酬不替执行者承担额外成本。

## 6. 服务、需求和订单数据

所有报酬使用正整数可转让词元，禁止基本额度、旧币或物料充当首版报酬。只允许在世醒着居民发布/承接；不允许付款方与执行方相同。死亡和归隐的行为按 §8 清算。

- `service`：`{id,provider,title,description,price,criterionTemplate,waitTicks,durationTicks,status,createdTick,updatedTick}`。status active/withdrawn。公开模板中可留目标 ID 待下单填写，数量/成果类型固定，缺项不得下单。
- `order`：`{id,origin,serviceId?,requester,provider?,title,description,terms,escrow,status,createdTick,acceptBy,acceptedTick?,acceptedSeq?,dueTick?,progress,evidence,closedTick?,reason?,cancelRequestedBy?}`。
- terms：`{price,criterion,durationTicks,eligible}`，成交前完全确定；eligible 首版 any 或限定一个社群，另由现行法律判定资格。用户可读的文本不能覆盖结构化 terms 的含义。
- 需求本身是 origin=demand 的开放订单，不再增加独立需求状态机。需求发布即锁定 escrow=price；服务告示不锁钱，下单创建 origin=service 的待接受订单并锁钱。
- status：open（公开需求）/offered（向固定服务提供者下单）/active/completed/cancelled/expired/failed。后三者除 completed 以外均全额退款，终态只能进入一次。

公开信息包括成果、价格、双方、期限、进度与结算理由；订单不支持私密正文。内心和真实模型预算不进订单。

## 7. 服务动作与硬验收

### 7.1 动作入口

| 动作 | 参数与效果 |
| --- | --- |
| service_publish | title,description,price,criterionTemplate,waitTicks?,durationTicks?；发布告示 |
| service_edit | service 及待改字段；只改未来下单内容，不修改旧订单 |
| service_withdraw | service；撤下告示，旧订单继续 |
| service_order | service,targetArgs；保存完整 terms、冻结 price，创建 offered |
| demand_publish | title,description,price,criterion,eligible?,waitTicks?,durationTicks?；冻结 price，创建 open |
| order_accept | order；offered 仅指定提供者可接，open 由首个符合条件者接；不得同时接两次 |
| order_decline | order；offered 指定提供者拒绝，退款；公开需求不需要拒绝 |
| order_cancel | order；接单前付款方直接撤回；active 时第一次记双方解除请求，另一方同意后取消，completed 一律拒绝 |
| order_submit | order,ref；提交接单后本人产生且尚未被其他订单使用的文档/公告/提案证据 |

服务编辑、需求撤回等不影响已锁定的等待/履约期。需求内容有误时须撤回并重新发布，首版不做原地改价或补价。

所有主动动作占普通动作名额、受 before/after 法律约束。发布、编辑、下单和提交按 P4 写出计价；其余新订单控制动作同样按参数写出计价，物理基础费 0。gather/claim/construct 等费用见 §9。被规则拒绝的动作仍按 P4 请求计价语义处理，不承诺所有失败都免费。

既有 standing 使用新版本动作表，但首版只增加 gather、claim、construct、repair 及已有 give 可用，保留其余原有白名单/禁用规则；不自动开放发布、接单或双边取消，以免未经明确选择替居民新增承诺。没有新的服务自动调度器。

### 7.2 结构化验收类型

| kind | 条件 | 可计证据 |
| --- | --- | --- |
| material_delivery | to:agent 或 project, quantity, place | 承接者带 order ID 的 give/contribute，实际交付自由或获准专项物料的数量；接收人须同地 |
| construction | project, work | 承接者带 order ID 的有效 construct，计实际新增工作量，不计物料出资 |
| repair | target, bp | 承接者带 order ID 的 repair，计实际修复基点，不计预期上限或第三人修复 |
| document | publishPlace? | 接单后本人新写的作品 ID，经 order_submit 交付/公开；只核验作品存在、作者、时间和约定地点 |
| announcement | audience:all 或 place | 接单后本人实际 broadcast/say/inscribe 回执，目标范围匹配；只核验发布，不核验接收者读过 |
| proposal | class? | 接单后本人正式 propose 成功的提案 ID；验收提交事实，不要求议会通过，也不替人投票 |

研究所使用费通过 §5 直接结算，不再套服务单。采集、拆解、运输、采购可以以最终物料交付作为成果；巡检和通知可按文档或公告交付；公共工程管理可按施工量或正式提交提案验收。名称可以自由，但超出以上类型的任意谓词、承诺“赚钱/正确/高质量”不能获得自动验收担保，创建时明确拒绝 unsupported_criterion。

material_delivery/construction/repair 原动作增加可选 `order`；事务校验 active、provider=actor、tick<dueTick、目标匹配后才行动，真实回执累积 progress，达到目标即完成。超出任务量的实际成果只计一次，不把同一回执拆给另一个订单。文档类通过 order_submit 关联，`usedEvidence` 唯一约束防止复用；主动重复提交已用证据返回明确错误，不能重复付款。

数量条件须在发布和接受时检查目标存在与可达的理论剩余量。例如修复当前只缺 50 bp，不能新接要求修复 1000 bp 的订单；接受后自然变化可能影响履约，进度按实际回执累计，不保证任务始终可做。施工对象完成或永久消失后尚未达标的订单以 target_unavailable 失败。

时间先后不能仅比较 tick。使用可回放的 `(commandSeq,actionIndex,effectIndex)` 全序记录 acceptedSeq 和证据产生位置，严格要求 evidenceSeq > acceptedSeq；同刻先接单再写作可提交，同刻先写作再接单不可。证据键为 `{kind,entityId}` 或 `{commandSeq,actionIndex,effectIndex}`，全世界唯一；完成、取消、失败后也不释放已使用证据键，避免把同一成果反复出售领取多笔托管款。

### 7.3 完成原子性

在普通动作业务变化通过全部校验后收集唯一证据，更新订单进度；达到条件立即完成、从订单托管转 price 到提供者余额并发出一次通知。随后进入统一 after 法律阶段；若整个命令因执行故障回滚，动作、证据、付款一起回滚。

单次提交多动作按既有顺序，每个动作独立处理；自动结算不是新的居民动作，不加写出费、不再经过可否付款的居民 before 钩子，不因额外余额不足而欠款。不能用法律事后拒付已满足条件的托管报酬。正常收入入账后仍受未来合法税收与腐坏规则影响。

## 8. 期限、取消、死亡与结算顺序

所有期限用世界 tick，暂停期间不流逝。open/offered 到 acceptBy 不再可接；active 到 dueTick 不再接受履约证据，最后合法 tick 为 dueTick-1。世界推进时先清理到期，再执行该 tick 居民自动行为，重启不重置期限。仅查询不推进时间。

接单把 provider 和 acceptedTick 写定，dueTick=acceptedTick+durationTicks。双方解除请求不暂停计时或行动，一方请求后对方可同意；完成先发生则付款终态胜出，不能再退款。第一版不允许通过换人保留进度继续做。

任一方死亡/归隐：先终止其 open/offered/active 订单、结清退款，再处理普通词元遗产及物料领取权；关闭其服务告示。退款收款方若正离世，必须在该次遗产分配前到账。多个居民同一结算离世，以稳定 ID 顺序处理并保存受益份额，禁止向已消失对象丢款。

依赖目标拆尽、工程取消或其他对象永久消失时，未完成订单立即失败退款。社群解散但工程转为城有而继续存在，不误判目标消失。任意法律表达式可能含时间或地点条件，系统不能从一次拒绝证明以后永远不能履约：法律拒绝、门禁、不足余额和暂时不在场均保留订单，由双方解除或到期退款。法律原因无法继续履约因此由有限期限保证最终清算，不允许执行者故意选择被禁止的时机获得单方退款。该确定性处理不需要主观仲裁或规则可满足性求解。

失败只退全部报酬，不逆转已交物料、维修或施工，不补偿途中花费；界面和模型下单提示必须明确“一次完成付款，部分完成不付款”。已完成订单后目标损坏、提供者离世、告示撤下都不撤款。

托管退款不得被付费或拒绝规则扣留；自动结算产生事件供观察，但首版不新增可递归触发订单结算的规则钩子。

## 10. 法律、接口与客户端

### 10.1 法律边界

新居民动作全部登记类型、参数及 before/after 元数据；法律可限制采集、施工、服务发布和接单，可对实际动作附加收费。城法可以改变公共工程政策、研究所政策，不能把物料记入无位置账户、改写订单进度、铸造物料或抽走报酬。

规则只读字段新增 `actor.materials`、公开地带存量、工程实际进度；新增操作只限 §4/§5 的公共政策管理，不开放通用 `set world` 或 arbitrary code。社群和地点规则作用域仍受现有检查器限制。内心动作、退出权、重订和荒野进入权保持原守护边界。

### 10.2 HTTP/MCP

沿用 P4 wake/look/act 计价通道，新动作放在 `POST /api/me/act`，必须带有效 wakeId、实验轮次及单调命令标识。新增 look 类型 `materials`、`services`、`demands`、`orders`、`research`、`observations`，均按 P4 读入计价，分页不绕过看次数。

公开观测接口返回新版本专用数据：`/api/public/services`、`/api/public/demands`、`/api/public/orders`；沿用公开可见范围。客户端查详情时明确标出当前告示与订单成交内容的区别。MCP 与原生动作工具从同一 schema 生成，不能只在文字提示里添加名字。

重试：act 携带 requestId，缓存该居民、实验轮次、请求 ID 的动作结果和计价回执；相同 ID 不重扣写出或托管，相同 ID 不同载荷拒绝 conflict。若现有命令层已有等价机制则复用，不并存两套互不关联去重。

### 10.3 感知和界面

居民概要增加自由物料、专项携带量、待领数量、待接/进行订单数量、最近结算和最近期限；详情按需展开，避免一次读入全部订单。失败回执给明确原因及可执行下一步。

交易所页面新增“服务”“需求”“我的订单”视图；发布地点不受限制，交易所只是发现入口。地图显示研究所覆盖全城，不画错误的地域服务圈；施工和物料位置仍显示。

确认下单/承接前展示：固定报酬、验收口径、目标、截止 tick/世界时间、成本自付、部分完成不付款、未获新的产权权限。研究所界面显示当前授权、收费、名义支持和已发生效果，不给出未明规律下的精确预测。环境页提供 §14 的分页观测记录。发布、查看、撤回均不暗中调用真实模型。

## 12. 验收矩阵

1. 旧 0/1/2/4 的状态哈希、感知与公开数据黄金样本不变；新版本回放一致，重启恢复全部托管和领取权。
2. 新图 14 节点及 12 空地连接有效；所有地点文案、事件、遗物、放逐和入城引用有效。
3. 采集在存量不足时部分成功、耗尽失败，日再生封顶；拆解和再建不产出无限物料。
4. 远程 give/交易物料被拒绝；词元-only 转账仍可远程。异地撤物料交易生成原地领取权。
5. 自由与专项物料不混用；专项不能出售给自己套现；居民死亡后原地点和受益人保持正确。
6. 工程资源不足不可施工；资源齐备不立即建成；多人不同顺序达到相同进度，工程预算累计消耗相同，额外动作费和研究所费按真实行动次数结算。
7. 小额出资的累计取整不负数、不多退；最后一步消耗恰好全部预算。工程取消、烂尾、原出资者死亡后退款仍守恒。
8. 研究所全城有效；显式收费上限生效；多座不叠加；损坏、撤权和失败动作不错误收费。
9. 服务下单和需求发布均全额托管，余额不足不建单；同时接同一需求只有一个成功者，不重复冻结。
10. 未接单撤回退款；接单后单方取消不退款；双方同意、到期、死亡、目标消失只退款一次。
11. 自动验收仅计承接者接单后的对应证据，第三人维修不能代为达标；重复回执/重复作品不重复领款。
12. 达标动作与付款原子性，规则执行错误整体回滚；达标后取消失败。部分完成超时不付部分款。
13. 付款方死亡时先清算托管后分遗产；已死亡出资者未来工程退款有明确受益去向。
14. dueTick-1 可完成、dueTick 不可；暂停与重启不延长/缩短世界期限；新 tick 到期先于常驻动作。
15. 文章空内容沿用既有写作校验；内容符合长度只说明可交付，UI 不称质量通过。提案失败不能作为成功提交证据。
16. 改服务告示不改既有单；不能自买自卖、无限期限藏币或突破活跃数量上限。
17. 动作接口、原生工具、MCP 与 UI 的同一输入得到相同结果、计价和权限判断。
18. 模拟 20 居民运行至少 30 世界日，检查自然维护需求、再生余量、工程可完成性、订单到期清算与记录增长；仅 mock，不调用真实模型。该实验是软件验收，不承诺社会学结论。

A：新版本隔离、地图分派、守恒账和黄金样本。B：物料动作、交易退款与继承。C：工程和维修、研究所。D：服务与需求、验收和生命周期清算。E：客户端、界面、模拟和回放验收。

```json
}
```

无每次随机扰动，所有居民面对相同规则；阈值按地带固定，施工规则对所有居民相同。阈值不得由居民姓名、模型、行为好坏或猜测内容决定。材料恢复基础值正整数，阈值必须为正、低于对应库存上限，抑制倍率 100–900 permille；施工阈值为 1–3（低于每刻四动作上限），倍率 100–900 permille。超范围拒绝创世，防止无效、不可观测或完全停产的配置。

另校验每个地带 `1 <= max(1,floor(B*F/1000)) < B`，排除基础恢复为 1 或取整后抑制无效的配置；施工的两种名义能力也须满足 `1 <= effectiveSuppressed < nominal`。参数合法仅是必要条件，仍需 §14.6 的可发现性验收。

生产参数可以和公开示例不同，但必须在创世前保存并冻结，不根据居民表现临时调答案。保密对象是未发生的因果真值，不是既有账本。仓库可公开实验设计与示例，但精确生产配置不进公开仓库或匿名 API；公开源代码仍可能揭示函数形式，本方案不保证外部客户端接触源码后仍完全无先验。论文中必须区分“自主发现关系”和“已知候选关系下估计参数”。

世界动态状态新增 `zone.harvestedThisDay`、`a.constructionLoad={tick,count}`；全部属于命令/结算可回放状态。计数按以下规则改变，不因看日志、拒绝动作或 HTTP 重试改变。

### 14.2 强采集与恢复

对地带 z，在从世界日 D 推进到 D+1 的既有日结算再生位置，取已结束的 D 日实际 gather 总量 H。设私有基础 B、阈值 T、倍率 F，名义本次恢复：

`R = H > T ? max(1, floor(B * F / 1000)) : B`

`actual = min(R, capacity - stockBefore)`。

增加 actual 到库存，物料账只记 actual 为再生供给；保存 D 日 totalGathered、补充前库存、actual 和补充后库存，然后将 harvestedThisDay 清零。没有既往采集的创世不额外补充一轮。日结算顺序固定：先封存 D 日采集记录，再补充进入 D+1，再允许 D+1 的新行动；原有资源收支阶段可复用，不新增平行的日历。

只有成功 gather 的真实取得量增加 H。搬运、赠予、拆解、领取遗产、失败采集和余额预估不增加 H。所有居民在同一地带的采集合计，不能换人逃避地带强度；地带之间互不影响。

T=30 时采走 30 不抑制、31 才抑制；次日减少采集使后一次恢复回到 B。抑制只持续对应一次结算，无永久损伤、累计灾变或不可逆枯竭。库存满导致 actual=0 只表示没有空间，公开记录不提供隐藏的“本应恢复 R”。

### 14.3 连续施工

进入 construct 时，取该居民本 tick 已成功施工次数 n（记录 tick 不匹配则视为 0）。设公开名义能力 N=10，获有效研究所支持为 15；私有全效次数 L 和倍率 F：

`effective = n < L ? N : max(1, floor(N * F / 1000))`

`work = min(effective, project.needWork - project.progress)`。

项目和授权校验成功、实际 work>0 的 construct 才提交一次计数增量。跨工程、跨地点、换研究所不重置；下一个 tick 自动重新计数。常驻指令执行的 construct 与手动调用共用计数，单个 act 请求包含多个施工动作也逐个递增。事务回滚和相同 requestId 重放不增加次数；repair/gather/move 不增加也不清零。

示例：L=2，F=500，无研究所为 10、10、5、5；有研究所为 15、15、7、7；下一 tick 第一次恢复名义能力。研究所的名义加成不保证取整后的每次实际结果严格等比，界面不能承诺每次实际产出恰好高 50%。

work 驱动 §4 的累计预算消耗、可回收结构与 §7 施工订单进度；不能用 N 提前耗尽预算或提前付款。工程总预算仍固定，居民增加的行动次数会增加公开的 construct 动作费和所选研究所费。

执行前给出动作费、研究所费、工程剩余预算及公开名义上限，不给出按隐藏状态算出的本次精确 work。余额准入、免费 preview、可用性判断与错误信息不得成为无成本预测器：行动固定费用按公开价检查，工程投入已经足额，实际进度与预算分摊只在成功后返回。费用不足错误不携带隐藏倍率、计数阈值或推算工作量。

### 14.4 环境记录

沿用 `look {what:"observations",kind?,target?,after?,limit?}`；kind 为 regrowth 或 construction，target 为地带/工程/公开居民 ID，limit 默认 20、至多 50，按稳定 observation ID 顺序分页。HTTP 的 P4 wake/turn/look 配额与读入计价全部照常。匿名观测站可浏览同一公开事实层，不获得更多物理真值；不能声称匿名数据无法被自托管客户端读取。

再生记录：`{id,seq,dayClosed,zone,stockAtStart,harvested,stockBeforeRefill,added,stockAfterRefill,capacity}`。必须覆盖全体居民真实采集，不能只有查询者采集；stockAtStart-harvested=stockBeforeRefill，stockBeforeRefill+added=stockAfterRefill（后续如有其他库存变化，必须另记真实增减，不悄悄改公式）。

施工记录：`{id,seq,tick,actor,project,researchUsed,workBefore,workAdded,workAfter,workRemainingBefore,energySpent,materialsSpent,actionFee,researchFee}`。其中 energySpent/materialsSpent 是工程预算的实际消耗，不能和执行者额外费用混淆。剩余工作量和完成事实足以识别末步截断，不返回尚未发生的无遮挡有效能力。

记录只提供已发生的事实；不返回 baseByZone、threshold、factor、fullActionsPerTick、抑制/疲劳标签、隐藏配置版本的描述、下一次预计产出或反事实试算。居民可从累计动作和结果归纳规则，不为阻止推断而篡改事实。

新增 append-only 事件 material_regrowth、construction_observed，保留完整历史；世界快照只保留游标和最近 24 世界日的有限索引，较旧记录通过公开事件档案分页重建。索引按世界 ID 和规则版本隔离，事务提交后更新，重启/回放可重建，不能成为独立写入导致账实不符的第二数据源。观测器失败不丢失已提交事件，也不自行推进世界。

所有居民都能观察，不要求持有研究所或付额外研究费；没有实验点数、experiment 动作、发现排行榜或自动真理认证。居民解释以作品/通信表达，可以用于文档服务交付；不增设“与隐藏公式一致则付款”的验收类型。

### 14.5 信息隔离清单

| 输出面 | 可以给出 | 必须隔离 |
| --- | --- | --- |
| system prompt、lore、工具说明 | 操作、已知价格、名义能力上限、存在需观察的环境差异 | 规律具体方向、阈值、倍率、猜谜式暗示答案 |
| public map/state、环境页 | 地点、当前存量、历史实际变动 | 私有创世配置、基础恢复公式及未来预测 |
| look/动作回执 | 自身账单及公开已发生结果 | “第几次触发递减”等引擎因果解释 |
| 规则表达式、draft | 已公开事实与合法政策试拟 | hiddenPhysics 引用、未来产出函数、假想施工预演 |
| 服务/需求验收 | 已经完成的工作或交付证据 | 针对隐藏真值的问答、隐藏参数范围试探型验收 |
| 管理、备份、回放 | 授权管理员持有完整真值 | 向匿名观众、领养者普通接口或居民输出管理员数据 |

客户端的静态动作 schema 可以描述名义能力上限，但不能把私有参数嵌进说明、错误枚举、前端 bundle 或测试示例作为生产参数。新的物料恢复配置与原 explore 词元地带参数分别命名，不能借隐藏物料参数误删已确认公开的词元账本。

公开读入量、参数错误或可执行状态若因隐藏阈值而不同，也可能形成旁路。校验只依据公开 schema 和预算；读入/响应费用照实收，但不要把真值附加到不可见 HTML、debug 字段或未显示 JSON 属性。原始私有快照和创世命令只在现有管理员授权路径提供。

### 14.6 验收与可发现性检查

1. H=T 与 H=T+1、库存已满/接近满/耗尽，核对 actual、清零时机、物料总账与日志。多居民采集累计正确，模拟轻—重—轻能出现正常—抑制—正常的观测轨迹。
2. 同刻多次施工、跨工程、换研究所、常驻指令、下一 tick、失败重试、回滚和重启全部验证同一计数语义。
3. 研究所 15/15/7/7 与无研究所 10/10/5/5 的示例回执正确；最后只剩 3 工作量时只记 3，预算和订单都按 3 更新。
4. 参数不同但公开状态相同的两个世界，在行动发生前的提示、schema、错误、可用性和 preview 上不泄漏差异；在真实动作/日结算之后允许观测结果不同。管理员接口和私有存档不参与这一公开等价性要求。
5. 分页日志包含其他居民同期采集、时间、研究所和剩余进度，能排除已知混杂因素；查询不改变随机流、计数或世界状态。
6. 用不接触 hiddenPhysics 的脚本观察者，仅凭公开动作与记录，重复采集和施工对照试验，能够区分“固定恢复/效率”与两个候选规律，并在未用于拟合的重复试验中预测结果。该检查证明可辨识，不等于证明真实 LLM 一定发现。
7. 最不利的允许抑制参数下，正再生和无研究所基础施工仍可用；验证系统没有永久锁死。默认样本至少 30 世界日检查维护余量；参数范围不能代替实际标定。
8. 对 P4 及更旧世界重跑黄金回放，不能引入新观测字段、新计数或隐藏参数要求。
