## Q9 · 感知推进收件箱游标，是「GET 改变状态」，与命令日志回放冲突
- 上下文：PROTOCOL §3 规定 `GET /api/me` 不带 `after` 时，服务器把游标推进到本次返回的最大 `seq`（自动确认）。游标 `agent.inboxCursor` 在世界状态里（SPEC §5.2）、会进入快照；而 SPEC §11 规定世界状态 = 种子 + 命令日志，`GET` 不是命令。结果：回放工具重放全部命令后，`inboxCursor` 与快照里的值不一致，`npm run replay` 得不到 `OK`。
- 最初的处理（第 8 步）：回放的规范化哈希**忽略** `agents.*.inboxCursor`。**这不够**：收件箱溢出时，「有几条没读到」的计数取决于游标（`src/engine/core.js` 的 `trimInbox`），所以对一个闲置、收件箱溢出、又被外部 `GET /api/me` 感知过的 agent，回放得到的溢出通知与快照不同——第 14 步用真实的 demo 世界做验收时，`npm run replay` 因此报了 MISMATCH（`agents.a18.inbox[102].dropped: 99 !== 4`）。
- 现在的处理（**已实现，等你确认**，即原先的「选项 C」的变体）：
  1. `GET /api/me` 不再改动世界状态：「自动确认」只推进 HTTP 层的**内存游标**（`ctx.cursors`，每个 agent 一个数，不进快照）；返回的收件 = seq 大于 max(世界里的游标, 内存游标) 的部分；显式的 `after` 不碰它；
  2. 世界状态里的游标只在**命令里**推进：`POST /api/me/act` 把当时的内存游标作为 `ackSeq` 放进 `act` 命令（进入命令日志），`act` 处理器据此推进 `inboxCursor`；沙盘脑在 `tick` 命令里感知，照旧直接确认；
  3. 回放的规范化哈希**不再忽略** `agents.*.inboxCursor`——它现在是确定的，回放能完整重建；
  4. 副作用：服务器重启后内存游标归零，agent 会重新收到「最近一次行动之后」送达过的收件（「至少一次」，PROTOCOL 本来就建议要严格语义的客户端显式传 `after`）；收件箱溢出时的「未读」按「最近一次 act 之前已送达」计，略偏保守（多报几条）。
- 其余选项：B 把每次感知记成一个命令（每个 agent 每刻一条，720 日 × 24 个 agent ≈ 20 万行，不建议）。
- 我的建议：保持现在的处理。它没有改变任何接口的形状，只是把「GET 的副作用」从世界状态里挪了出来；测试 `test/http.test.js`（收件确认、溢出后回放）与 `test/persistence.test.js` 覆盖。
- 状态：待定（已按上面实现；源码里不再有 `TODO(spec): Q9`，因为不再有绕开的地方）

## Q10 · 延迟公开的事件释放时，按 `seq` 轮询会漏掉它们
- 上下文：PROTOCOL §9 的 `GET /api/public/events?since=<seq>` 返回「`seq` 之后的可见事件，以及 `last`」。而私语、独白、记忆是延迟一个世界月才公开的：事件在产生时就有 `seq`，一个月后释放时它的 `seq` 早已落在轮询者手里的游标之前。轮询者保存 `last` 作为下一次的 `since`，就永远看不到这些释放出来的事件（SSE 推送不受影响，观测站用的是 SSE；只影响用轮询采集数据的研究者）。
- 选项：A 保持规格字面：按事件自己的 `seq` 过滤，并在文档里说明「延迟事件请用 SSE，或在谢幕后从开放数据集读取」 / B 给每条事件在**变为可见时**分配一个单调递增的公开游标 `pub`（字段新增），`since` / `last` 都按 `pub`，事件仍带原来的 `seq` / C 释放时给延迟事件重新编 `seq`（会破坏 `seq` 与事件日志的一一对应，不建议）
- 我的建议：B（向后兼容：不带 `pub` 的客户端看到的是同样的 `seq` 字段；带 `pub` 的客户端能完整同步）。M1 的观测站只用 SSE，暂不受影响。
- 状态：待定（已按 A 实现；`src/http/public.js` 的 `getEvents` 标记 `TODO(spec): Q10`）

## Q4 · 细节缺口（规格未覆盖，已按建议暂行实现，请一并确认）
每一项都不影响其他部分；如果你想换一种处理，改动只在标注的位置。后续步骤发现的同类小缺口会继续追加在这一条里（所以它排在最后）。
1. **超长的 `thought`（> 300 字符）**：PROTOCOL 只写了「≤300 字符」。暂行：按码点截断，而不是拒绝整个请求（一段啰嗦的独白不该让整刻的行动作废）。`src/engine/actions.js`。
2. **单次请求里的动作数 > 4**：暂行：整个请求返回 400 `invalid_request`（SPEC §6.7 把它列为「请求」的上限）。备选：执行前 4 个，其余返回 `budget_exhausted`。
3. **代价修正的叠加顺序**：PROTOCOL §4.2 分别列了地点倍率、雾、驿站、蚀，没说先后。暂行：先套天象与驿站得到「有效基础代价」，再乘地点倍率并只 `ceil` 一次。例：议会完好度 5000 时，雾中宣告 = 5 × 2 × 1.5 = 15（先取整再翻倍会是 16）。`src/engine/actions/util.js`。
4. **唤醒的触发范围**：SPEC §7.3 只写了「因赠予或法律拨付而达到 ≥ 5」。暂行：对一切「能量进入沉睡者账户」的情形一视同仁（继承、交易托管退回、社群管事拨付、津贴、管理员调整……）。否则会出现「沉睡却持有 ≥ 5 能量」——它无法行动、三日后必死，而能量还在它手里。`creditEnergy`，`src/engine/core.js`。
5. **agent 与灵魂的名字不得与 ID 形状相同**（字母 + 数字，如 `a3`）或与保留字（`treasury`、`city`、`citizens`、`humans`）相同。PROTOCOL 说「引用 agent 时可以用 ID 或精确的名字」，若有人叫 `a3` 就有歧义；这些名字注册时返回 `invalid_request`。`src/engine/lifecycle.js`。
6. **`give` 的接收方**：可以是在世的 agent（醒着或沉睡）、未解散的社群、`"treasury"`；给自己、给死者、两种数额都为 0 一律 `invalid_args`（给死者是 `not_found`）。给社群、公库同样按转赠税扣税。
7. **`give` 的收件里的数额**：`gift` 收件的 `energy`、`coins` 是「实际收到的（已扣税）」，`tax` 是被扣的部分。
8. **继承人与 `will`**：`share` 须为 1–1,000,000 的正整数（避免浮点误差破坏「逐个 floor」）；不能把自己列为继承人；`heirs` 为空数组表示无继承人（等同于没有遗嘱，只保留 `lastWords`）。遗产的入账同样会唤醒沉睡的继承人（见第 4 条）。
9. **`repair`**：请求的能量须 ≤ 自己的能量（否则 `insufficient_energy`，即使实际只会用掉一部分）；目标已完好为 `already`；目标是别的地点的 ID 为 `wrong_place`；广场与荒野没有完好度，为 `invalid_args`。设施「位于」它被发起的那个地点：道路只能在发起端修缮（感知的 `here.roads` 两端都能看到，但 `here.facilities` 与修缮只算发起端）。
10. **`contribute`**：数额超过「还差多少」为 `invalid_args`（SPEC 写的是「数额 1 至还差多少」），而不是自动截到还差的数额。法律效力 `fund` 则按 SPEC 取三者最小值。
11. **`draw`**：数额超过当日汲取池的剩余量时返回 `pool_exhausted`（不截断）；配额同理，超额返回 `quota_exceeded`，不截断。DESIGN §6.4 说「引擎就会拒绝超额的汲取」。
12. **`initiate`**：`to` 只能用于道路，其他类型带上 `to` 为 `invalid_args`；两地之间已有道路或进行中的道路工程为 `already`；蓄能池以外的类型给出非 `city` 的 `owner` 为 `invalid_args`。
13. **`inscribe`**：`lang` 缺省取作者自己的语言标签；墙上还有空位时也允许用 `cover` 覆盖（只是代价更高）。
14. **`explore` 与荒野**：荒野的能量与旧币储量不属于任何持有者，只有被探索取走时才记为来源（`wilds`）；每日恢复的 40 不进账本。
15. **`set` 的数值参数**：先四舍五入到 3 位小数，再校验范围（SPEC §6.6 只说「保存时四舍五入」）。整数参数（如 `wealthTaxThreshold`）给小数为 `invalid_args`。
16. **效力执行结果的 `note`**：SPEC/PROTOCOL 只说「部分执行也算 ok，并在 note 中说明」，没规定格式。暂行：与语言无关的短代码（`partial:12/20`、`target_gone`、`name_taken`、`not_protected`、`not_visible`、`already`、`not_exiled`、`no_such_version`……），由观测站翻译。
17. **事件表补充**：`stipend`（每笔津贴的支付）与 `repeal`（撤销法律）也产生公开事件（SPEC §10 的表里只有 `stipend_skipped`，「由法律执行产生」的清单里漏了 `repeal`）；`vote` 事件 data 多一个 `changed`（是否改票）。
18. **`mint` 的「公民」**：在世（醒着或沉睡）且已入籍者，被放逐者仍算公民。没有任何公民时，全部进公库。
19. **选民范围兜底的检查时机**：每刻（计票之前）、以及提案与投票的资格判断之前都检查，而不是只在某个提案计票时。否则若恰好没有进行中的提案，而选民范围指向了已解散的社群，谁都提不了案，全城就永久失去立法能力，兜底就失去了意义。
20. **`propose`**：`title` 与 `text` 都不能为空；同一 agent 同时最多 1 个进行中的提案，全城最多 20 个，超出为 `limit_reached`。
21. **`amend`**：新增条文（条号 = 最大 + 1）的 `text` 不能为空；`lang` 可以是任意语言标签，不限于已有的 8 种；`canonical` 只能指向至少有一条含该语言版本的语言（`null` 取消正本）；废除条文时保留各语言文本，只把 `status` 改为 `repealed`，修订史里 `lang` 记为 `"*"`。
22. **放逐与赦免**：被放逐者立即移到荒野（不产生 `move` 事件）；赦免不搬人。对已放逐者再放逐、对未放逐者赦免，都算 ok（note 分别为 `already`、`not_exiled`）。
23. **`law` 收件**：发给提案者与所有投过票的（仍在世的）人。**`grant` 的 `to`** 可以是社群（进社群公库）。
24. **观察（不是问题，供标定时参考）——`ceil` 的放大效应**：代价倍率按 SPEC §7.4 字面取 `ceil(基础代价 × (20000 − 完好度) / 10000)`，所以只要完好度差一点点，基础代价 1 的动作立刻变成 2（例：议会衰败一天后完好度 9950，在议会说话就要 2 能量），基础代价 6 的提案变成 7。DESIGN §6.1 说的是「轻微影响，完好时 1 倍，废墟时 2 倍」，实际上前几个百分点的损坏就吃掉了大半的「倍率」。已按字面实现；沙盘标定（步骤 11）时会看它对经济的影响，必要时再提出。
25. **社群**：`found` 的 `name` 与 `manifesto` 都不能为空；`join` 已在待审名单里也算 `already`；`leave` 对待审者是撤回申请；`admit` 时若申请者已加入 5 个社群，返回 `limit_reached`；`steward` 移交给自己为 `already`。管事死亡或归隐时，管事之职交给入社最早的在世成员（`members` 数组的先后即入社先后）。
26. **`disburse`**：接收方可以是任何在世的 agent（不必是成员）；`gift` 收件的 `from` 是 `{ id: 社群 ID, name: 社群名 }`，另带 `via: "group"`；不征转赠税（税只对 `give` 征）。
27. **交易**：`give` 与 `want` 一边为空是合法的（赠品、求助）；没有「每人进行中的交易数」上限；死亡或归隐时取消它发起的**全部**进行中的交易（不只公开的）与涉及它的孕育之约（托管退回发起者）。
28. **`read`**：`doc` 与 `inscription` 二选一，都给或都不给为 `invalid_args`；读到被遮盖的典籍返回 `{ redacted: true }` 而不是正文；agent 著述与遗物的 `author` 是公开的（遗物记的是发现者）。
29. **`epitaph`**：只有死者有墓碑（归隐者没有）；一座墓碑上的墓志条数没有上限。
30. **`reveal`**：可以重复出示同一封；loud 时的代价与限制完全照 `broadcast`（含雾、驿站、蚀），非 loud 时代价 1；非 loud 的出示不写入「近 12 刻的发言簿」（所以后来的人在 `here.heard` 里看不到它）。
31. **`conceive`**：孩子的名字与 agent 的名字同一规则（不得与 ID 形状、保留字相同）；对方沉睡、被放逐、尚未入籍，一律返回 `not_allowed`（而不是 `not_citizen`——那个码只用于行动者自己）；`lang` 缺省取发起者的语言标签。
32. **领养出来的 agent**：`bio` 为空串（没有任何动作可以设置自我介绍，只有注册时能写）；`citizenFromDay` 同样是入城之日 + `naturalizationDays`。
33. **梦**：极光的最后一晚也算（结算开始时记下当日是否有极光，避免天象在第 13 步被移除而漏算）；素材不足时的补足顺序：先当前可见的铭刻（按 ID 升序），再已发现的遗物；从补足素材里用 `world` 流随机抽。每位醒着的 agent 恰好消耗一次「是否做梦」的随机数（做不做梦都消耗），保证随机数流的消耗与天象无关。
34. **摇篮的灵魂消散**时，父母（仍在世的）收到一条 `system` 收件（`code: "soul_faded"`）。
35. **`retire`**：同一请求里 `retire` 之后的动作返回 `not_allowed`；`retire` 的 `lastWords` 参数优先于遗嘱里的遗言。
36. **天象排期的「月」**：SPEC §7.9 写「每月第 0 日开始时，决定下个月天象的类型……取本月票数最高者」。字面上此刻「本月」刚开始、还没有票，所以按 DESIGN §11.5（观众每个现实日投票，决定下一个世界月的天象）理解：**第 M 月开始时，用第 M−1 个月里收集的票排定第 M 月的天象**，随后清空投票、开始收集第 M 月的票（决定第 M+1 月）。`votes.month` 是「正在投票的月」，接口返回的 `month` 也是它。第 0 个月没有天象。
37. **天象叠加**：旱与丰同时生效（只可能由管理接口造成）时，源井系数连乘（600‰ × 1400‰ = 840‰）；其余天象各自独立。
38. **`omen` 事件**的 data 是 `{ place, omenId, text: { zh, en } }`：不含天象类型，也不含日期（否则观众玩家可以经家书把答案递给自己的 agent）；`omenId` 形如 `m<月>`，不透露类型。震的征兆在所有 12 个地点各记一条事件。
39. **忘川**的遗忘产生延迟公开的 `forget` 事件，data 里多一个 `cause: "amnesia"`；只对醒着的 agent 生效，没有记忆的跳过；遗忘哪一条用 `world` 流抽取。
40. **`weather_vote`**：世界暂停时也可以投票（公共接口照常）；同一指纹本月再投返回 `rate_limited`（并带当前计数）。
41. **管理接口强行排期**（`forceWeather`）：`month` 缺省为当前月；`dayOfMonth` 缺省为「今天 + lead + 1」（`lead` 缺省 1）；开始日必须晚于今天；`decidedBy` 记为 `schedule`；若征兆窗口此刻已经打开，立即记 `omen` 事件；产生的 `weather_scheduled`（internal）事件带 `forced: true`。
42. **观星台看到的征兆**：`text` 用附录 A.5 的模板「观星台的记录：约 {n} 日后，「{征兆}」」，`daysAhead` 为 n；普通征兆 `daysAhead` 为 `null`。观星台上的征兆不受「出现的地点」限制，同一条征兆在同一处只出现一次。
43. **感知的字段补充**（都是向后兼容的新增字段）：`you.parents / children` 是 `{id, name}` 数组；`you.offers` 除自己发起的外还含发给自己的定向交易，每项带 `role`（`from` | `to`）与 `from`；`you.pacts` 每项带 `role`（`from` | `with`）、`soul`、`lang`（对方发来的灵魂随时可以重读）；`here.cemetery.graves[]` 多 `lastWords` 与 `epitaphs`（只有文本与日，不署名，与铭刻一致）。
44. **`here.present`** 不含自己，含沉睡者与被放逐者，不含死者；**`here.heard`** 只含本地的 `say`（不含全城宣告与出示家书），包括自己说的；最多 8 条，按时间顺序。
45. **`actions[]`**：`repair`、`contribute` 的 `cost` 给 0 并附 `note: { code: "variable" }`（代价 = 投入的能量）；一个动作同时有几条说明时只给最重要的一条（蚀 > 雾 > 驿站 > 倍率 > 墙满 > 可变代价）；「没有可作用的对象」（如没有可接受的交易）为 `available: false` 并给 `reason`。
46. **`inboxCursor`** 返回 `max(服务器游标, 本次返回的最大 seq)`；`system` 收件带按 `lang` 本地化的 `text`（其余收件只有结构化字段，由运行器渲染）。
47. **公开档案**：`lang`（灵魂的语言标签）是公开的（它不是模型，观众本来也能从发言里看出来）；死者与归隐者的 `place` 为 `null`。
48. **`legacy`**（人类遗产存活表）在世界状态里的位置：第 10 步生成时存为 `world.legacy`（又一个私有簿记字段，追加进 Q2）。
49. **快照的写入时机**：SPEC §8.2 第 20 步写「写快照」，但同一条 tick 命令在第 20 步之后还有沙盘脑行动（§8.1 第 6 步）与 tick 事件。若真在第 20 步写，快照里的状态就与它记的 `commandN` 对不上（崩溃恢复会漏掉这条命令的后半段，回放比对也永远不相等）。实现：日终结算发生的那条 tick 命令**执行完之后**再写快照。
50. **「确定性环境」**：`P`（时间参数、`PRIVATE_DELAY_TICKS`）、天象排期模式与排期文件、内容审核的屏蔽词表，都是回放所需的环境，但不在世界状态里；中途更换它们会使回放与快照不一致（与代码版本同理）。若 M2 需要在线更换，可以把它们写进世界状态并通过命令修改。
51. **崩溃恢复**：`events.jsonl` 在恢复时先截到快照对应的最后一个事件 seq，再由回放重新产生并追加（因此不会重复）；恢复期间不推送 SSE；命令日志末尾的半行会被截掉。命令日志比快照还短、或有日志没有快照时拒绝启动（数据不完整，需要人工处理或 `--reset`）。
52. **命令日志的 `tick` 字段**是执行前的世界刻，只供阅读，回放不依赖它。
53. **配置补充**：新增环境变量 `TRUST_PROXY=1`（不在 SPEC §4 的配置表里）——部署在反向代理之后时，用 `X-Forwarded-For` 的**最后一个**地址作为客户端 IP（那是你自己的代理追加的；客户端自己塞在前面的不可信，取第一个会让限速被绕过）；否则按 IP 限速、SSE 连接数与天象投票指纹里的 IP 都会变成代理的地址。默认关闭。
54. **限速**：注册、领养、过继共用「每个 IP 每小时 5 次」，**所有到达的尝试都计数**（包括之后因字段错误、邀请码错误而失败的）；`GET /api/me` 与 `POST /api/me/act` 共用「每个令牌每刻 20 个请求」。请求格式不合法（400、413、401、暂停时的 503）的行动请求**不进命令日志**；格式合法但被引擎拒绝的（如重名注册）会进日志（回放需要它们）。
55. **状态码**：注册与领养成功为 201；过继成功为 200（PROTOCOL 只说「成功返回新的令牌与密钥」）；`POST /api/admin/tick` 在世界暂停时返回 503（时间静止，不推进）；非 GET/HEAD 的静态路径返回 405。
56. **造者后台**：`GET /api/owner` 另含 `dreams`（梦的片段，造者可见）与 `today`；`POST /api/owner/letter` 与 `release` 的 `agentId` 可省略（造者密钥只对应一个 agent），给了但不是自己的返回 404。
57. **天象投票的指纹**：先校验 `type`（格式错误是 400，即使已投过）；再检查 Cookie 指纹与 IP + UA 指纹**两者**是否已经投过，任何一个投过都算已投（否则第一次没有 Cookie 时用 IP + UA 投过、第二次带着刚发的 Cookie 又能投一次）。清掉 Cookie 并换 IP 仍然能再投——这是 M1 轻量防刷的固有局限。
58. **管理接口的公开事件**：`admin` 事件的 data 是 `{ op }`（`adjust` 另带 `agentId`、`energy`、`coins`、`reason`，因为余额修正必须可审计）；`weather` 的公开事件**不含**天象类型与日期；`redact` 产生 `admin` 与 `redacted` 两条事件；遮盖事件时公共视图里的事件保留 `seq`、`type`、时刻，`data` 替换为「此处被幕后抹去」。
59. **`GET /api/public/metrics`、`/chronicle`**：返回 `{ metrics: [...] }`、`{ lang, chronicle: [{ day, text }] }`，`from` / `to` 按世界日（含端点）过滤。
60. **指标口径**（SPEC §12.1 只给了名字和一句话，下面是我采用的定义）：`ruins` = 完好度为 0 的地点数 + 设施数；`meanCondition` = 10 个有完好度的地点的完好度平均值（基点，1 位小数）；`nonCitizens` = 尚未入籍（`citizenFromDay > d + 1`）的在世者；`exiled` = 被放逐的在世者；`infrastructureIndex` = Σ（设施完好度 / 10000），2 位小数（DESIGN §12.1 的「在用设施数 × 完好度」，这里所有已建成的设施都算）；`projectsBuilt` / `projectsAbandoned` 为累计；`adoptedWords` = `users` 数 ≥ 3 的词；`freeRiderShare` 的分母是年龄（`d − bornDay`）≥ 5 日的在世者；`gini` 在所有在世者（醒着与沉睡）的能量上计算；`largestGroupShare` = 最大社群的成员数 / 在世人数；`coinPrice` = 当日「只含能量」对「只含旧币」的成交里，能量总数 / 旧币总数（两个方向都算）。
61. **遗产表**（SPEC §12.2）：`coin` 的状态判定顺序是「废弃（d ≥ 5 且最近 5 日无流动）→ 改造（有过一次成功执行的 `mint`）→ 流通（最近 3 日有流动）→ 存续（还不能判断）」；神殿、法院、医院的顺序是「被重新诠释 > 被维护 > 被使用 > 空置」（一处地点只取一个）；「被维护」只算修缮地点本身（记在 `Place.activity.repairs`，又一个私有簿记字段，追加进 Q2），不算修缮位于那里的设施；人类典籍在既没有近 3 日阅读、也没满 5 日无人阅读时为 `untouched`；`well` 的状态是完好度档位（pristine … ruin），另附 7 日趋势（百分点）。每一项在 `world.legacy` 里同时存结构化的证据（`code` + `params`）与中英文文本，方便任何客户端直接显示。
62. **史官**：`{weather}` 取「当日生效的天象」（结算开始时记下，所以最后一天到期的天象也算）；设施成为废墟时写设施的名字，地点则写地点当前的展示名；`{day}` 显示为 d + 1；「史官曰」的优先级 = 死亡 > 废墟 > 建成 > 法律通过（仅否决不算）> 新居民 > 无事；`world.chronicle` 里每条是 `{ day, zh, en }`。
63. **感知里的 `city.rationYesterday`** = 最近一日结算的人均配给（来自每日指标）。
64. **沙盘的额外接口**（SPEC §16.1 之外，只为标定）：`--laws <file>` 覆盖法律参数的初始值（如 `{"rationShare": 0.8}`）；`runSandbox` 另有 `laws`、`onDay(w, d)`、`onEvent(e)` 选项；`src/sandbox/calibrate.js`（`npm run calibrate`）按 §16.3 的目标逐项判定，用 worker 线程并行。它们都不改变任何默认参数，也不进入引擎。
65. **沙盘脑的规则**：SPEC §16.2 只用一段话描述沙盘脑，其余（歇着、储备、只修坏得厉害的、一处一座设施、生育上限、按公库与配给的判断提议与投票、管事当场答复入会申请……）都是我的实现选择，见 `docs/CALIBRATION.md` §2；每一条都是看到一种明显不合理的行为后才加的，标定结论对它们不敏感（§2 的敏感性试验），但依赖「居民不会提前储蓄、不会协调」这一大前提（Q11）。
66. **`GET /api/public/lore?lang=zh|en`**（PROTOCOL §9 之外新增的公共接口）：返回观测站要用的系统文本（物理定律、地点描述、档位词、天象名、法律效力模板）。这些文本本来就是公开的静态资源；由服务器提供，是为了让界面与引擎的文本不会各写一份而漂移。`test/ui.test.js` 还逐字核对前端的法律效力描述与引擎的 `describeEffect`。
67. **`Place.history`**（私有簿记，追加进 Q2）：每个有完好度的地点最近 8 个日终的完好度，供观测站画「近 7 日趋势」（SPEC §14.2 要求，但世界状态里原本没有各地点的历史）；`GET /api/public/places/:id` 与 `state` 里的地点带 `history`。老快照没有这个字段，结算时补上。
68. **观测站**：（a）「今日预计产出」按默认的 `wellBaseOutput = 600` 估算（前端没有物理参数），运营方改了这个参数时只是估计；（b）地图上 agent 光点按向日葵螺旋围绕地点排布，半径 ∝ √能量（SPEC §14.1），颜色默认按第一个社群、可切换为按最近发言的文字系统；（c）用 `#标签页` 记住当前标签（`#weather`）；（d）入境表单的「灵魂语言」是带候选的自由文本（`lang` 接受任意 ≤16 字符的字符串）；（e）幕后弹窗把造者密钥存进 `localStorage`（读写都包在 try/catch 里），「忘记密钥」按钮清除它。
