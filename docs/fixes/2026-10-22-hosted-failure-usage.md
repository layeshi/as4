# 托管自动停用时保留失败用量

平台托管version=2遇到401/403/404，或连续第三次调用失败时，会在onUsage中停止运行器。此前先调用controller.abort，再用新的aborted状态判断本次调用是否被主动取消，导致触发停用的真实失败没有进入居民和账户的用量记录。

修复在onUsage入口保存取消状态。自动停用继续执行，但不会把已经完成的失败重新归类为主动取消；主人暂停或关闭运行器造成的取消仍排除在提供者失败统计之外。

回归测试使用真实RunnerManager、工具循环、UsageStore、轨迹及临时文件，模型提供者使用模拟实现。覆盖：

- P6下401/403/404，以及P7下403自动停用时，调用和失败均记录一次。
- P6/P7连续三次500均记录，第三次触发停用；前两次仍可继续运行。
- 居民和账户两份内存/磁盘记录一致，轨迹保留失败，托管余额与预留正确。
- 主人暂停及关闭运行器导致的请求取消不计作提供者失败。

修复前新增8项测试中，6项因`0 != 1`或`2 != 3`的计数差异失败，2项取消对照通过。修复后托管集成与用量专项共35项通过：

```sh
node --test test/hosted-integration.test.js test/runner-usage.test.js
```

全量`npm test`：2163项中2162通过、0失败、1项跳过；该跳过项在修复前的发布验收中已存在。执行环境为Node.js v22.14.0。`git diff --check`通过。

改动基于`334a53b9b3250ae616c33b18ef702731d8b822fc`，其运行器源码与此前确认缺陷的生产版本`88a6d11`一致。修复不涉及世界状态结构或历史命令解释；最终发布结果另记于发布记录。

此改动不迁移历史用量。过去已漏记的失败需要另行依据可靠轨迹重建，不能从余额或当前失败次数推算补齐。该修复也不代表403来源、其他模型超时或停机耗时问题已经解决。
