# 三项统计修复：候选实现与上线说明

状态：已实现，尚未部署；生产世界的统计版本尚未启用。基于实际生产提交 `6ac35c27ef3c80aa17ef043ea3f8ac96a3461b54`，隔离分支 `codex/statistics-fixes`。

## 修改范围

1. **全岛指标漏计**：P7 的城外、北、西、东四份日志按字段合计思考、基本补给、过期、保管、常驻指令、匿名私语、传授及出生等增量。文字系统计数先合并再计算熵；人口、社群、资产等存量只统计一次，逐城指标及已有财政投影继续保留。
2. **轨迹分类丢失**：动作类型从正式动作目录生成，阅读段落提取为共享纯元数据；运行日志、工具诊断与轨迹共用有限目录。正式材料错误码得到保留，未知字符串仍归为 `other`，正文与参数仍不进入分类字段。
3. **重复支出**：v2 在实际扣基础动作费处记录 `expense/action:*`，不再把包含维修、出资、规则收费的完整 `r.cost` 再记一次。维修实际投入、研究费、规则收费、工程托管、施工消费与退款保留各自流水。三笔等额维修分别保留，新增维修及基础动作费记录带命令号与动作序号。原有 `r.cost` 含义不变。

没有修改居民余额、法律、模型配置、唤醒周期、配给或词元价格。禾灯资源不足不属于本次修复。

## 兼容与启用

缺少 `world.statistics` 的旧存档保持 v1。新 P6/P7 世界默认 v2，并在 genesis 中保存选择；`genesisOpts` 对旧存档明确返回 v1，避免历史回放误用新默认值。

已有世界使用持久化管理命令启用：

```json
{"type":"admin","payload":{"op":"statistics","args":{"version":2}}}
```

对应受现有管理鉴权保护的 `POST /api/admin/statistics`，请求体为 `{"version":2}`。命令记录启用命令号、游戏刻和首个完整统计日；重复调用不重置标记，非法版本或附加字段拒绝。启用当日标注 `transition`，新建世界从第一天标注 `complete`。

启用后如需回滚，目标版本必须保留 v2 统计及启用命令支持；不能直接回切完全不识别该统计语义的旧软件。统计启用不降级、不重置世界。

## 历史校正

新增离线工具，必须在独立进程中运行，不使用生产 `Runtime.open`，不启动服务器、调度器或模型。输入为固定的快照及其完整命令前缀，使用与该实验相同的有效物理配置：

```sh
node src/tools/statistics-projection.js \
  --world-dir /path/to/isolated-world-copy \
  --output /path/to/statistics-projection-v2.json
```

工具逐条校验回执前后状态哈希及编号，最后核对快照截点哈希；老格式命令采用原统计语义重放。P7 日结在内存副本中截取四份日志，仅在该日结原语义重放哈希一致时生成校正指标。居民历史支出必须同时符合命令结果、专用维修/托管流水和全局基础动作费去处，才替换旧通用分类；缺少证据的命令保留原值并列入 `unresolved`。

校正结果是独立查询文件，权限 0600，不覆盖快照、命令日志或原始轨迹。部署时将审核后的文件原子安装到世界目录的 `statistics-projection-v2.json`。查询入口检查该文件的来源截点、当前命令链以及原指标/个人流水前缀；来源不符就返回原始值并标注 `unverified`。校正覆盖之后仍有 v1 命令时，个人累计标注 `partial`，直到补建覆盖该段的校正文件。公共 state、metrics、当前世界问答取证与受权限保护的居民统计使用同一校正口径，财政配给口径继续在其上计算。

部署工具可将已验证的原始快照和校正文件作为 `buildStatisticsProjection` 的 `checkpoint`，只处理该截点之后的回执。检查点必须匹配原始快照哈希、命令号及每位居民的流水前缀；扩展结果与从创世重建结果一致。耗时的历史重建可提前完成，最终停服点和统计启用点只需处理少量新增命令。

余额变化 CSV 原本来自正确的实际余额差流水，保留其原语义；不把分类校正当成余额修正。已经丢成 `other` 的旧轨迹不猜测回填，原始文件保留。历史归档世界本次不自动重建。
