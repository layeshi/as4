# 微信居民动态提醒接入与验收

本功能使用微信小程序官方订阅消息接口。默认未配置任何模板，站内订阅和提醒记录可用，但不会调用微信发送接口，也不会显示虚假的“已开启永久推送”。本次实现按一次性授权计数；未假设账号具备长期订阅资格。

## 配置

在实际小程序公众平台选择与业务匹配的订阅消息模板，核实类目、字段及使用资格。将配置写入服务器现有受限环境文件的 `WECHAT_NOTIFICATION_TEMPLATES`，其值为单行 JSON。下面仅说明格式，其中 AppID、模板ID和字段编号必须替换为真实值，不能原样上线：

```json
{"death":{"appid":"wx1234567890abcdef","templateId":"REPLACE_WITH_REAL_TEMPLATE_ID","fields":{"thing1":"name","thing2":"kind","time3":"time"},"state":"trial"}}
```

四个类型键为 `death`、`diary`、`runner_stopped`、`balance_low`。每项包含 `appid`、`templateId`、`fields` 和可选的 `state`（`developer`、`trial`、`formal`，默认 `formal`）。AppID 必须匹配服务端已有的微信应用配置；凭据复用 `WECHAT_APPID` / `WECHAT_APP_SECRET` 或普通小程序专用配置。字段来源仅允许 `name`、`kind`、`time`，不支持发送私人正文、余额、错误栈。字段必须符合真实模板的类型与长度要求；不允许借用不相关模板强行套用居民动态。

多个业务类型如使用同一个经过核实的模板，共用该用户对此模板的授权次数，而不是每类或每个居民都获得一次授权。客户端上报接受授权只作为本地发送机会估算，微信服务端才是实际授权的最终判定者。授权票据十分钟有效、一次性使用；拒绝或禁用清空本地对应模板的估算次数。

## 持久化与投递

`DATA_DIR/resident-notifications.enc` 保存加密的接收标识、订阅、单次授权票据、投递状态和最近90天提醒；`resident-notifications.key` 为独立 AES-256-GCM 密钥，两者权限为0600，均需随数据备份并限制访问。不要删除密钥或只恢复其中一个文件。提醒不进入确定性世界状态，不扣游戏词元，也不额外调用模型生成摘要。

新日记在站内汇总记录中及时反映，微信通知按北京时间20:00、每居民每日最多一次发送。20:00后日记进入下次汇总。其他提醒在后台约5秒轮询内发现待发送项，微信网络延迟另计。同一托管故障经确认恢复后再次发生才重新提醒；余额故障以实际调用费用预留成功为恢复依据，模型故障以模型调用成功为恢复依据。普通等待、仅输出费用预检查、重启尝试、暂停不作为故障恢复证据。

发送前复核当前管理者、归属版本、账号状态和微信绑定；过继、解绑、关闭订阅会使未发送通知失效。已送达微信的卡片无法撤回，但详情必须重新鉴权。退出登录仅撤销会话，离线订阅继续存在。

每条通知在发出外部请求前持久记录发送尝试，避免进程重启重复推送。返回成功记为 `sent`；授权不足记为 `unavailable`；明确失败记为 `failed`；网络中断、超时或进程在发送期间退出记为 `unknown`，不自动重试结果不确定的请求。微信接口返回成功不代表用户已阅读或手机必定显示通知。

重启恢复缺失的世界事件仅生成站内记录，不补推旧消息。已排队消息允许短时调度延迟（日记15分钟、其他1小时），超出后仅留记录；补充授权也不补推已标记不可发送的旧消息。托管事件为进程状态观测，不能重建停服期间未被记录的运行器状态变化。

## 验证与发布

本地验证：

```sh
node --test test/resident-notifications.test.js test/notification-http.test.js test/wechat-notifications-ui.test.js
npm test
node wechat/scripts/release.mjs check --offline
```

真实投递验收需使用获准模板和测试微信用户主动授权，检查：模板与业务匹配；用户拒绝后仍可用站内记录；授权后单次投递；20:00日记汇总；微信卡片跳转；退出重登；过继/取消后失效；微信未授权或关闭系统通知时的提示。真实模板未配置、未授权和未完成真机验收时，不应把模拟接口测试表述为生产推送可用。发布前同步更新隐私说明，按既有保留数据部署流程执行。
