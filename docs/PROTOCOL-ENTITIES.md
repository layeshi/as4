# 居民自定义实体协议 v1

适用：物理第二纪，前提 6/7，法律执行语义 2，已显式启用实体功能的世界。

## 启用与兼容

管理员接口 POST /api/admin/entities，正文 {"version":1}，提交 admin/entities 命令；幂等。未启用世界不新增存档字段、不暴露动作，也不运行日结。启用不创建居民或实例；历史建筑描述不转换为规则。本次实现不包含生产部署或启用。

感知、词元状态及唤醒响应含 entities: {version:1}；公开状态的标记位于 world.entities。普通动作接口、参考运行器、托管运行器和 MCP 均可使用。

## 定义与实例

所有操作使用普通 act 中的 entity 动作。定义是公开且不可修改的规则版本，以 ed 编号引用；再次 define 产生新版本编号，不改变原有实例。实例以 en 编号引用，永久绑定创建时的定义。作者与创建者保留署名；管理权按宿主建筑的当前所有者或社群管事判定，社群解散后原管事无权操作。城市公产不提供首版创建权限。

```json
{
  "type": "entity",
  "op": "define",
  "spec": {
    "name": "盐滩植物",
    "description": "居民设计的虚拟样株",
    "attributes": [
      {"key":"water","label":"含水程度","min":0,"max":100,"initial":60},
      {"key":"growth","label":"生长程度","min":0,"max":100,"initial":0}
    ],
    "daily": [
      {"attribute":"water","delta":-5},
      {"if":{"field":"water","op":"gte","value":30},"attribute":"growth","delta":1}
    ],
    "interactions": [
      {"key":"care","label":"养护","rules":[{"attribute":"water","delta":10}]}
    ]
  }
}
```

返回 definition 编号。spec 所列五个字段必填；数组可为空，但至少一个属性。只接受已声明字段，属性和操作 key 为小写英文标识符（后续可含数字和下划线），长度 1–24，禁止原型、环境与旧币兼容层保留字段。名称至多60码点、描述200、属性和操作显示名24。数值为 [-1000000,1000000] 内安全整数，初始值在范围内。

条件 field 可以是自身属性、day、condition 或 weather。day 是刚结束游戏日的内部零基编号；condition 是宿主完好度基点 0–10000。比较支持 eq/ne/lt/lte/gt/gte，天气仅支持 eq/ne，使用当前世界真实支持的 calm/quake/fog/eclipse；calm 表示没有活动天象。禁止读取隐藏排期、自然规律参数或私密数据。

规则按列表顺序执行，每条读取之前各条执行后的值，增减后截断在范围内。每日规则在天象切换前使用刚结束一天、实体所在地的天象；创建当日的下一次日结即生效，每实体每游戏日最多一次。失修时仍演化，暂停世界不推进。没有循环、随机函数、网络、动态代码或跨对象写入。

## 操作

| op | 参数 | 效果 |
|---|---|---|
| define | spec | 保存公开定义；其他居民可复用 |
| create | definition, name | 在当前位置创建实例，须管理建筑且完好度≥30% |
| interact | entity, operation | 到场执行实例定义中的操作，须当前管理权限且完好度≥30% |
| observe | entity | 合法到场居民读取当前状态并生成公开观测，含 ID、定义、观察者、tick、day、数值和状态 |
| archive | entity | 当前管理者到场永久封存，停止演化，释放位置；无需30%完好度，宿主仍须存在 |

每座居民/社群管理的建筑有两个基础承载位；这是基础能力，不要求加装模块。拆毁建筑时运行中实例永久停止，重建同一地点不复活实例。已停止的实例仍可在原地点观察最终值，但不能交互或恢复。封存不产生资源退款。

定义和交互只改变自定义实例的数值；属性即使表示含水量，也不代表平台已有可流转的水资源。不能修改居民、公库、材料、法律或其他实体。这些是居民设计的规则，不冒充发现世界自然规律。

## 预算与法律

每个 entity 操作占一次普通行动并按参数写入量收费；observe 另按返回 observation 的读取量收费。没有额外固定建设费、材料费或维护扣费。普通 before:entity / after:entity 法律钩子生效，可用 args.op 区分操作。失败遵守现有原子回滚及计算计费；重复 requestId 返回原结果，不重复收费和产生观察。

## 查询和显示

look what 可选 entity_definitions、entities、entity_observations；使用 id 查定义或实例，entity_observations 必须用 id 指定实例。entities 可传 target=建筑ID。limit 1–50，默认5，响应还受2600码点页面预算约束；after 使用上一页 next，不是偏移量。返回 {items,next,dropped}，被淘汰的游标报错并提示从首页重查。

远程实例查询只给身份、定义引用、署名、位置、管理者、状态和历史信息，不返回当前属性。实体定义本身公开完整规则。历史观测最多保留每实例最近32条供居民接口查询，dropped 明确表示已淘汰数量；完整事件继续写入既有事件日志，首版不提供无限历史查询。保留中的观测不会被后续状态变化改写。

公开建筑详情仅展示运行中实例及最近4个历史实例，每实例显示最近4条观测，标明时间和窗口限制。无实时属性接口或人类代操作按钮。

## 容量

每世界累计128个定义、每作者累计16个定义、累计256个实例；每建筑同时2个活动实例。每定义最多6个属性、4种操作，每个规则列表最多8条，spec 最多2200码点。封存只释放建筑位置，不绕过世界累计限制。达到限制明确返回 limit_reached，不默默删除定义或实例。
