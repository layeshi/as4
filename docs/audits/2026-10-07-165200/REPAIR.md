## 版本边界与运维

`lawSemantics.version === 2` 独立于法律计算 VM，适用于全部第二纪 premise。Runtime 新建第二纪世界启用新版；缺少字段的历史世界仍用旧语义，普通 `createWorld` 未指定选项也保持旧行为。旧世界须显式升级，存在 open 重订时拒绝升级并返回 ID 与到期刻。原始 genesis 选择始终保留用于全回放。

## 实施裁定及代价

以下按作出顺序保留实施台账中的全部 `Ruling:`，避免只保留结果而丢失取舍：

1. 三个子系统顺序实施，用行为测试描述而非预先编造完整测试源码。原因：真实处理器与夹具需先核查；判断失误代价是额外返工和审查。
2. 新语义采用原子请求/结果回执，保留旧日志行。原因：修复后仍应重现历史失败；代价是日志格式与回放/迁移维护工作。
3. 全套测试排除 fixture 录制脚本，最终并发设为 2。原因：无过滤发现会改写冻结样本；代价是必须另行核查非 `*.test.js` 文件是否含验收（已检查其为辅助/验收脚本，审计旧缺陷复现另行保留）。
4. 历史 golden HTTP 夹具显式启动旧世界。原因：新版 Runtime 新创世已改变语义，冻结样本描述的是历史；代价是若使用不当会削弱新创世覆盖，故另测新版 Runtime 并核对冻结 JSON 不变。
5. 全部新版命令结果均保存带哈希的状态差量，而非仅保存故障标记。原因：成功、失败和恢复分类均须不受未来处理器变化影响；代价是更大日志、性能开销及差量格式维护。
6. 一次审查代理创建受线程上限拒绝，复用未参与实现的只读调查代理进行任务 3 审查。代价是先前调查上下文可能影响判断；以明确差异/规范和独立整分支终审补偿，整分支已成功创建新审查代理。
7. 修复同时覆盖启动时事件日志原子截尾。原因：原地重写可能破坏快照已覆盖的事件，不能仅修追加路径；代价是共享 I/O 路径变化，已保持相同字节/世界语义并补持久化断点回归。
