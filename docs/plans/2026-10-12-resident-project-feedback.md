# 工程错误解释、出资核对和权限展示

以生产基线 97b7194 实现，仅改变第五、六前提的响应和只读视图。

- 失败回执保留错误码，解释业务原因、实际出资为零与读写计费的区别，并给出核对入口；新响应与重试响应一致，持久化回执不改写。
- `look projects` 分页列出所有状态工程；`look project {id}` 核对记录中的出资归属、投入与已消耗数。代管物料按归属账户列示；赠与、口头承诺、失败出资不计入。关闭工程不再显示托管余额，历史投入不等于产权或股权。旧记录缺失时明确说明，不能猜补。
- 现场感知和模型文字展示 owner/group/public、当前居民是否获授权、位置与阶段限制。此为基础施工条件，仍需行动时校验法律、额度与研究服务。
- 网页环境页提供工程历史及出资核对，现有工程/地点展示参与权限。
- 不改变行动、工程、财务结算规则，不改变快照结构，不部署生产。

验证：失败实际转账为零；回执重试不重复计费；已建/取消工程可查；个人与代管归属隔离；视图不泄露私人字段；权限与现行施工规则一致；mock 模型的下一轮确实收到说明；现有全套回归与回放测试。

## 查询方式与响应约定

```json
{"what":"projects","limit":10}
{"what":"project","id":"j2","limit":5}
{"what":"project","id":"j2","limit":5,"after":"agent:a5"}
```

- `projects` 返回工程列表，含关闭状态；`after` 为上一页最后一个工程编号。`mine` 按个人产权或记录中的个人出资归属筛选。
- `project` 返回单个工程的基本状态、当前居民的 `participation` 与 `accounting`；公共接口不含居民的个人参与判断。
- `accounting.totals` 为全工程的历史投入与累计消耗，不随分页变化；`contributors` 按记录归属账户汇总，`next` 是下一页所用的 `after`（末页为 null）。缺少旧明细时 `recordsAvailable=false`、`totals=null`，不使用旧的能量计数器猜补物料或归属。
- `escrow` 为当前工程托管余额，关闭时为零。历史投入不能推断退款或继承的具体分配。
- `participation.canAttemptConstruct` 只代表开放状态、地点、阶段和授权这些基础条件满足；行动时仍校验法律、额度、余额和研究服务。
- 网页通过 `/api/public/projects` 与 `/api/public/project?id=j2` 使用同一组只读视图；账目以独立核对窗口展示，工程列表与地点详情显示权限。
- 失败 contribute 的 `error.effect` 给出零词元、零物料转账；错误码保持原样，`hint.look` 指明下一步核对查询。成功回执、持久化回执及快照不改变。
