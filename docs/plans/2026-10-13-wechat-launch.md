# 微信小游戏正式上线实施计划

> 按本计划逐项实现、验证和记录；当前用户已授权修复及上线，不重复请求常规实施许可。

**Goal:** 修复 2026-10-13 上线审查问题，完成材料、备案、版本审核与实际正式发布。

**Architecture:** 保留 Canvas 客户端与共享后端；退出请求构造后立即清除本机状态，远端撤销独立报告。审核投影保持失败关闭，添加准确的遮盖原因，不改写世界历史。生产升级从可追溯提交进行，保留城市及私有配置。

**Tech Stack:** Node.js 原生测试、微信官方 CI、微信公众平台、SSH/systemd。

## 任务 1：退出与私人数据清理

修改 `wechat/minigame/society.js`；测试 `test/wechat-minigame-ui.test.js`。

1. 写失败测试：远端退出未完成时，本机凭证、资料、家书及请求编号已经清空；成功、断网、401 与超时均不能恢复这些内容；晚到读取不得恢复原账号。
2. 执行失败测试，确认失败源于真实控制器。
3. 构造撤销请求后立即 `api.clearSession()` 并清空私人状态、草稿、导航及读取票据；随后等待远端结果。失败提示明确“本机已退出，服务器会话撤销未确认”。
4. 执行专项回归，并在完整候选版运行全部测试。

## 任务 2：审核状态准确展示

修改 `src/wechat/projection.js`、`src/http/wechat.js`、客户端公共显示辅助及相关页面；测试 `test/wechat-server.test.js`、`test/wechat-minigame-ui.test.js`。

1. 写失败测试，分别覆盖待处理、风险拒绝、临时异常、身份过期；拒绝不得计作待审，不泄漏原文，姓名占位不能混成实际姓名。
2. 添加遮盖状态和准确计数，保留现有审核批准策略与缓存时限；已有拒绝缓存兼容读取。
3. 客户端只对真实 pending 快速重试，显示准确的登录/审核提示。
4. 专项及完整测试；生产部署从候选提交按保状态技能执行，不从脏主目录发布。

## 任务 3：候选版与材料一致

修改启动页、固定文案、备案草稿、QA 与上线记录。

1. 在实际界面清晰展示“后人纪之词元本位”，保持 16+、健康忠告和启动前不联网。
2. 更新夜蓝/月白、四导航、字号/震动/刷新等真实说明；禁用不存在的图片、支付与音效能力声明。
3. 保存既有已审查修复与本次修复，验证后提交可追溯源码及构建摘要。
4. 官方编译、上传开发版、设体验版，获取稳定测试入口；实际真机截图与验收不可用浏览器效果图代替。

## 任务 4：平台前置要求

1. 核对当前平台会话；保存只读进度证据。
2. 填写适龄与真实 UGC 场景，复核隐私数据流；含法律真实性承诺的最终确认需运营者在具体页面确认。
3. 落实真实游戏截图、小游戏备案、小程序备案及必要认证/短信核验；身份和付款步骤交运营者完成。
4. 核实平台统一实名接入的生效阶段，验证实名及未成年人限制。平台固定音效模板不符合事实时准备明确说明，不能虚构功能。

## 任务 5：正式发布及核验

前置条件真实完成后提交相同候选版本审核；跟进实际审批状态。审核通过后发布，并核验正式扫码、匿名浏览、微信登录、账户权限、私人写入及退出。只有线上版本存在且实测满足目标才标记目标完成。

平台审批等待或需要运营者核验不是任务完成；持续保留完整目标并记录下一可执行步骤。
