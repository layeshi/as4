# 微信端实验助手改版方案

状态：已实现（2026-10-18）。Codex 在工作树 `.claude/worktrees/wechat-assistant`（分支 `claude/wechat-assistant-redesign`，基于 origin/main `fa39bf7`）按本方案实现，Claude 审查并看图验收后补了几处：分支只列历史分支、提示里的动作靠左、对话时间右对齐、额度说明折成两行、微信端城名也过内容检查。推定处见文末，用户可改。

## 一页一事

给登录的人类用户：**在微信里向实验提问，读懂回答**。问和答是主角；对话列表、问题范围、额度是配角，平时收起或缩成一行。画面沿用月下城（`wechat/minigame/ui/theme.js`，`docs/VISUAL-DESIGN.md` 第 4 节）。

## 现在的问题

依据：origin/main `fa39bf7` 的 `wechat/minigame/screens/assistant.js`（52 行）与 `wechat/minigame/assistant.js`（111 行）。

1. **一屏一长列。** 额度、世界元信息、对话按钮、「本次问题范围」整组控件（记录类别、分支、城、居民标签、历史居民 ID、法律、起止日、两种密钥）、问答、依据全文、输入框、「刷新 / 重新验证」「删除此对话（立即生效）」、页脚说明，全在同一个滚动列表里。输入框在最底下，要翻过整组范围控件才能提问。
2. **说明文字多。** 顶部「AI 分析仅供观测 · 回答通过审核后展示」、额度行里的模型名、三行世界元信息、「居民对象 · 未指定」、「P6/P7 按账号管理权验证；旧世界按其原有密钥验证。」、页脚「每条消息保存 30 天……」、未登录时的说明句。
3. **区域不分。** 每段对话是一个描边大按钮；问题和回答是一样的卡片，只靠「你」「实验助手 · AI 生成」名字行区分。
4. **元信息是原始串。** 「w · 纪元 1 · 分支 75b643ab · 第 1 日 / 运行中 · 数据截至 2026-10-18T09:35:00.000Z」；恢复时间用 `toLocaleString()`。
5. **回答是纯文本。** Markdown 原样露出 `**`、`|`；依据是一排「来源 [S1] 标题」描边按钮，点开的依据全文接在页面最底部。
6. **私人记录必须选居民。** `questionScope()` 抛「请选择需要查询的居民」；另有「历史居民 ID（填写后优先使用）」自由输入框。服务端已按 ADR 0027 支持不选居民。
7. **对话列表全叫「实验对话」。** `src/http/assistant.js` 对微信请求把 `status` 与对话里的标题一律改写。
8. **叫法与网页不一。** 微信写「来源」，网页已改叫「依据」。

## 已定的决定

| 编号 | 决定 |
|---|---|
| W1 | 只改微信端实验助手这一屏（`wechat/minigame/`，小程序与小游戏共用）及其控制器，加 W10 的服务端改动；不动网页界面、管理后台、其他微信页面。 |
| W2 | 画面用月下城，结构照网页版：问答为主，其余收起或缩成一行。 |
| W3 | 一屏三态，都在 `tab = 'assistant'` 里切换，不 `push` 新页面（`push()` 会调 `clearSecrets()`，把助手状态和密钥全清掉）：对话列表态、对话态、依据态。 |
| W4 | 提问区贴底（`page.footer`），只在列表态与对话态出现。 |
| W5 | 问题范围平时缩成提问区里的一行摘要，点开是底部弹出卡片（`app.sheet`），不换页。 |
| W6 | 回答按与网页同一套 Markdown 安全子集排版：把网页的解析部分拆成不依赖 DOM 的纯模块，生成 CommonJS 副本给微信端（沿用 `shared-text.js` 的生成与校验办法），Canvas 上另写渲染。 |
| W7 | 统一叫「依据」；正文里的 `[S1]` 变成可点的依据标号。 |
| W8 | 私人记录不选居民 = 你当前管理的全部居民（ADR 0027）；删掉「历史居民 ID」输入框，居民一律从 `status.branches[].residents` 里按名字选，默认「全部居民」。 |
| W9 | 说明文字只留额度一行。 |
| W10 | 微信端的对话标题过微信内容检查：通过就显示（取法同网页 Q16），审核中、未通过、需要微信登录或检查不可用时显示「实验对话」。 |
| W11 | 合规不变（`docs/VISUAL-DESIGN.md` 4.8）：只显示审核通过的文字；生成中、审核中、失败、已停止、未展示的回答都不显示正文与依据标题；AI 回答一律带「AI 生成」标签；密钥只在内存，切后台清除。 |
| W12 | Codex 实现，Claude 审查与看图验收。 |

## 各区块

### 顶栏

- `page.top = { kind: 'back', title, back }`：`society.js` 的 `paintNav` 改为用 `top.back || { type: 'back' }` 作返回动作；其他页面不传 `back`，行为不变。
- 列表态标题「实验助手」，返回沿用 `{ type: 'back' }`。
- 对话态标题是对话标题（还没取到时写「新对话」），返回回到列表态。
- 依据态标题「依据 S1」（取依据标号；没有标号时写「依据」），返回回到对话态，并还原进入依据前的滚动位置。

### 列表态

- 顶部留白后一行「向实验提问」（heading 字号，`C.text2`，居中），不加说明。
- 有对话时：小节「最近的对话」（`section(W, '最近的对话', { small: true })`），下面一张卡片，每段对话一行：左边标题一行省略号（action 字号，`C.text`），右边时间（caption，`C.text3`；今天写「15:26」，更早写「10-17」，用本机时区）；行高至少 44，行间 `C.divider` 细线；点按打开对话。服务端最多给 100 段，全部列出，页面自然滚动。
- 没有对话时只有「向实验提问」。

### 对话态

- 首行：左边状态标签（`paintChip`）：「世界已暂停」`C.dormant`、「世界已结束」`C.text3`、问题范围选了历史分支时「历史分支」`C.dormant`；右边文字按钮「删除」（`danger`，点按区至少 44×44）。没有标签时这一行只有「删除」。不放「刷新」：页面已有下拉刷新（`pull: true`）。
- 问题：靠右的气泡，最宽为可用宽度的 80%，石阶 `C.raised` 底、圆角 16、内边距 12 × 14，body 字号，保留换行；不带名字行和状态。审核中写「内容审核中」，未展示写「问题未展示」（都用 `C.text3`）。
- 回答（只在 W11 允许显示正文时）：占满宽度的 `N.card`（城影底、1px `C.line`），左上 `paintChip(ctx, 'AI 生成', …, C.ai)`，下面是 Markdown 渲染结果，最后是底注。
- 底注（caption，`C.text3`）：「依据 S1 S2 · 第 12 日 · 截至 09:37」。S1 等是可点的依据标号（月白字，点按区上下扩到 44），打开依据态；截至时间用本机时间，不是今天时写「10-17 09:37」；没有依据时省掉「依据…」这段。
- 其他状态不挂 AI 标签，只放一条提示（小卡片，左侧 3px 色条，meta 字号，动作是月白文字按钮）：

| 状态 | 样子 | 动作 |
|---|---|---|
| 生成中 | 回答卡片里只有 AI 标签和「正在生成…」（`C.text3`），不显示任何正文 | 提问区按钮变「停止」 |
| 审核中（`pending` 或 `moderation.pending`） | 不用卡片，一行「内容审核中」（`C.text3`） | — |
| 需要微信登录（`moderation.loginRequired`） | 色条 `C.moon`：「微信登录后可阅读」 | 前往登录 |
| 未展示（`withheld`，或 `moderation` 的 `rejected`、`unavailable`） | 色条 `C.dormant`：「内容未展示：权限已变化或审核未通过」 | 刷新、重试（计 1 次） |
| 失败 | 色条 `C.danger`：「生成失败 · {服务端 error}」 | 重试（计 1 次） |
| 已停止 | 色条 `C.text3`：「已停止 · 回答不完整」 | 重试（计 1 次） |

- 问答之间间距 16，不加分隔线。
- 打开对话、发出新问题后滚到最底；轮询带来新内容时，原本在底部（距底 48 以内）就跟到底，否则不动。

### 依据态

- 标题（heading，`C.text`）是依据名称；依据未通过检查时写「依据」，正文位置显示对应提示（沿用 `moderationNotice`）。
- 元信息一行（caption，`C.text3`）：「世界 p7-20261016 · 第 2 纪 · 分支 75b643ab · 第 12 日 · 截至 09:37」。
- 正文放在石阶底卡片里：以 `{` 或 `[` 开头的结构化记录用等宽 13/19（`monospace`），保留行首缩进，长行换行；其余用 feed 字号（15/24）。
- 依据审核中时沿用现有轮询（1.5 秒一次，最多 50 次）。

### 提问区（`page.footer`）

顶边一条横贯全宽的 1px `C.line`。从上到下：

1. 出错时一行错误（caption，`C.danger`，一行省略号）；没有错误时不占位。
2. 范围行：左边是整行可点的范围摘要（action 字号，`C.text2`，末尾「▾」），点开范围卡片；右边是带入对象的标签「居民 岚 ×」「法律 l8 ×」（点 × 清除）。放不下时摘要先省略。
3. 输入行：左边输入框（石阶底、圆角 14、高至少 46、最多显示 3 行，多出省略；空时显示占位「例如：三城公库最近为什么差这么多？」`C.text3`），点按打开原生输入层（`field` 动作，`name: 'assistantText'`，`multiple: true`，`max: 4000`）；右边按钮宽 72、高 46：平时是月白实心「提问」（本屏唯一的实心主按钮），草稿为空、处理中、助手不可用或次数用完时变暗不可点；生成中变描边「停止」，始终可点。
4. 额度一行（caption）：「今日剩余 18 / 20 次 · 北京时间零点恢复 · 失败、停止和重试也计次」（`C.text3`）；次数用完写「今日次数已用完 · 北京时间零点恢复」，助手不可用写「助手暂不可用」，这两种用 `C.text2`，输入框与「提问」一并禁用。

摘要文字与网页 `summaryText()` 相同：公开记录且没有其他限定时写「范围：全部公开记录」；否则从记录类别（「公开记录」「我的居民私人记录」「管理员私人研究」）开始，只列与默认不同的部分，用「 · 」连接：「历史分支 75b643ab」、城名、世界日（「第 10–12 日」「第 10 日起」「至第 12 日」，起止相同时「第 10 日」）。例：「我的居民私人记录 · 北城 · 第 10–12 日」。居民和法律不进摘要，显示成右边的标签。

### 范围卡片（`app.sheet = { kind: 'assistantScope' }`）

- `screens.sheet` 现在只画地点卡片：改成按 `app.sheet.kind` 分派，`assistantScope`、`assistantDelete` 交给实验助手的页面模块，其余照旧。
- 从上到下（间距 12）：
  1. 标题行：`section(W, '问题范围', { small: true, link: { label: '恢复默认', action } })`。「恢复默认」把记录类别、分支、城、居民、世界日恢复默认并清掉两种密钥，保留带入的法律。
  2. 记录类别：`segmented`「公开记录 / 我的居民 / 管理员研究」。「管理员研究」只在 `app.user.role === 'admin'` 时出现（用户对象里没有 `role` 就不出现）；「我的居民」只在所选分支是旧分支或分支里有 `managed` 居民时出现；当前所选不再可用时退回「公开记录」。旧分支 = `!(premise >= 6)`，`premise` 缺失也算，与网页 `public/assistant-ui.js` 的 `legacyBranch` 相同。
  3. 世界与分支：有历史分支（`branches` 里 `active` 为假）或已选了某个分支时才出现：`chipStrip`「当前世界」+「{worldId} · 第 {epoch} 纪 · {id 前 8 位}」。
  4. 城：世界有 `cities` 时才出现：`chipStrip`「三城」+ 各城名。
  5. 居民：`chipStrip`「全部居民」+ 所选分支的居民（没有分支数据时用 `status.residents`），按名字排序；「我的居民」时只列 `managed` 的；「我的居民」且是旧分支时不出现（造者密钥已认定是哪一位）。已选的居民不在当前列表里时仍保留并排在最前（与网页相同），可在提问区的标签上点 × 清除。
  6. 世界日：一行「第 [ ] 日 至 第 [ ] 日」，两个窄输入（`assistantFrom`、`assistantTo`，从 1 开始，留空为全部）。
  7. 造者密钥（`secret`）只在「我的居民」且是旧分支时出现；管理密钥（`secret`）只在「管理员研究」时出现。都只存在 `app.form`，沿用 `clearSecrets()` 与切后台清除。
  8. 「完成」：描边按钮，占满宽度，关闭卡片；点遮罩也关闭。
- 卡片最高占屏幕 82% 且现在不能滚动：在 iPhone SE（375 × 667）上最长的组合（「管理员研究」带历史分支，或「我的居民」带旧分支与造者密钥）也要放得下；放不下时压缩间距，或让卡片内容可以滚动（改 `paintSheet`），不要砍控件。
- `chipStrip` 在卡片里也要能横向滑动。现在打开卡片时触摸只用来点按和关闭，需要时改 `society.js` 的触摸处理并补测试。

### 删除确认（`app.sheet = { kind: 'assistantDelete' }`）

标题「删除这段对话？」（heading），下面一行两个按钮：「删除」（`danger`）与「取消」（描边）。点「删除」走现有删除流程（先清屏再请求），然后回到列表态。

### 回答的 Markdown 子集（W6）

1. **纯解析模块。** 把 `public/assistant-markdown.js` 里的解析拆到新文件 `public/answer-markdown.js`：只导出 `parseAnswer(text, labels)`（`labels` 是本条回答依据标号的集合），返回块列表的纯数据：段落、标题、列表（可嵌一层）、引用、分隔线、代码块、表格（带每列是否数字列）；行内有文字、粗体、斜体、行内代码、依据标号。不 import 任何东西，不碰 DOM。`public/assistant-markdown.js` 改成基于 `parseAnswer` 建 DOM，对外接口（`renderAnswer`、`citeChip`、`caretNode`）与行为不变：`test/assistant-markdown.test.js` 原样全过（只加测试，不改已有断言）。
2. **生成副本。** `wechat/scripts/shared.mjs` 增加生成 `wechat/minigame/utils/answer-markdown.js`（CommonJS：去掉 `export`，末尾 `module.exports = { parseAnswer }`，文件头注明由脚本生成、不要手改）；`release.mjs` 在 prepare 时写入、在 check 时比对，与 `shared-text.js` 一样。生成的文件提交进仓库。
3. **兼容性。** 这个模块要在微信各端的 JS 引擎上跑（iOS 用系统 JavaScriptCore，旧系统不认新语法）：不用正则后行断言、命名捕获组、`s` 标志和 `\p{…}`；不用 `Array.prototype.at`、`Object.hasOwn`、`structuredClone`、`String.prototype.replaceAll` 等较新的内建方法（现有的 `item.subs.at(-1)` 改成下标写法）。写一条测试扫描这个文件里的这些写法。
4. **Canvas 渲染。** 新文件 `wechat/minigame/ui/answer.js` 把块列表变成 `N.*` 组件：
   - 段落：`N.rich`，body 字号（16/26）；粗体加粗；斜体按普通字显示；行内代码用 `C.label` 色；依据标号是月白字的可点片段（`{ type: 'assistantSource', id }`），点按区上下扩到 44。`rich` 只支持同一字号且点按区等于行高：按需给它加选项，不要另写一套排版。
   - 标题：三级 17/24 粗体、四级 16/26 粗体、五级 15/24 粗体，`C.text`。
   - 列表：每项左边 20 宽的「•」或「3.」，其后是正文；第二层再缩进 20。
   - 引用：左边 3px `C.lineStrong` 竖条，缩进 12，正文 `C.text2`。
   - 分隔线：1px `C.divider`，上下各留 8。

## 状态

| 状态 | 样子 |
|---|---|
| 未登录 | 内容区「登录后向实验提问」加月白「前往登录」；没有提问区 |

| 助手不可用 | 额度行写「助手暂不可用」，输入框与「提问」禁用；已有对话照常可读 |
| 次数用完 | 额度行写「今日次数已用完 · 北京时间零点恢复」，输入框与「提问」禁用 |

| 世界暂停 / 已结束 / 历史分支 | 对话态首行的状态标签 |
| 出错 | 提问区最上面一行错误；依据态与未登录时用现有轻提示 |
