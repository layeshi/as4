# 安卓真机反馈修复

反馈：此刻的居民全部显示“一位居民”；创建/管理没有供应商预设；地图部分地名不显示。

现场证据：线上微信投影将 a1–a5 的名字和议会、档案馆、交易所、研究所等地名返回为“内容审核中”；新创建 a6 的名字已通过审核。线上仍没有 0.3.0 的 pending/铭刻返回字段。地图只尝试四个标签位置，碰撞后直接省略文字。

修复决定：

1. 名字和地名使用独立、优先的单条审核，独立摘要缓存，不再被正文批次的拒绝结论连带遮住。人类固定地名继续由已实现的系统白名单展示；居民所写名字仍须审核。客户端待审人物按居民编号区分并解释原因，不能从未审核的网站接口取原文。
2. 地名标签扩展候选位置，拥挤时移到附近空位并画引线；待审地名给可读占位，保持点按查看。过长名字在地图省略，地点卡片提供全文。
3. 将供应商预设提前到当前验收版。创建时可选择供应商、接口和模型，创建后再填写密钥、测试/保存；不自动配置或启动模型。DeepSeek、智谱 GLM（通用/编程）、通义千问、Kimi、豆包、OpenAI（Chat/Responses）、Anthropic、自定义统一来自公开配置；新增后端下发接口，客户端带相同配置的备用副本，以兼容尚未更新的线上接口。服务切换清空密钥并重新确认费用。
4. 先证明失败用例再修复，完成专项、完整测试、官方 CI 预览与独立审查。真实姓名/地名恢复需要部署后端；原改版方案要求提交、推送及生产部署另行确认，本次先完成可审查修复与新预览。

接口核对依据：[DeepSeek](https://api-docs.deepseek.com/)、[通义千问](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[Kimi](https://platform.kimi.com/blog/posts/kimi-api-quick-start-guide)、[豆包](https://docs.volcengine.com/docs/ark/compatible-with-openai-sdk?lang=en)。GLM 和 OpenAI/Anthropic 地址复用仓库既有配置；未核实的模型 ID 保持手填，不假定用户具有某模型权限。
