## 1. 怎样落地：世界的「设定版本」

- 新增世界字段 `w.premise`（整数），创建时由环境变量 `PREMISE` 决定，缺省 0。它和 `SHELL_SLOTS` 一样只在创建世界时生效。
- 值记进 `w.genesis.premise`，`genesisOpts` 原样还原，所以回放得到同一个世界。早期快照没有这一项，按 0 还原。
- 已有的世界没有这个字段，按 0 处理。本方案的每一处改动都以 `premise >= 1` 为前提；0 的世界仍走原来的代码路径。
- 不开「第三纪物理」，而是同一个第二纪引擎按设定版本分支。改动集中在代谢、记忆、躯壳、提示和几个开关上，为此复制整个引擎得不偿失。
- `premise >= 1` 时，感知顶层多一个字段 `premise: 1`，公开状态的 `world` 里也有。运行器、MCP、观测站都按它选文本与界面。`premise` 为 0 的世界不输出这个字段，感知与以前逐字节相同。
- 新增的参数（§2、§3、§5）都加在 `P` 里，只在设定分支里读。它们和其他参数一样属于「确定性环境」：回放要用同一组值。

## 2. 代谢：维持你携带的东西（设定 7、8）

### 2.1 分量

一段文字的**分量**近似它的 token 数，而且与语言无关：

> 分量 = 汉字、假名、谚文的个数 + ⌈其余码点数 ÷ 3⌉

按码点计会让拼音文字吃亏：同样的意思，英文的码点数约是中文的三倍。按上式算，`data/founders.json` 里 24 份灵魂草稿的分量在 123–258 之间，中位数 176；190 个汉字的中文灵魂（温故，175）和 590 个码点的英文灵魂（Ezra，197）分量相近。

函数是 `src/text.js` 的 `textWeight`，纯函数、确定性。文字系统的判定依赖 Node 内置的 Unicode 数据，同一个 Node 版本下结果固定。

### 2.2 公式

> 每日代谢 = 3 + ⌊（灵魂的分量 + 全部记忆的分量）÷ 200⌋

- **3 是底数**：平台每次送给居民的那一份——规则、动作目录与城况，人人一样。线上每次调用的输入里，这部分约占九成。
- **灵魂与记忆是居民自己携带的**。灵魂不变（设定 5），记忆随居民记住、忘记而变。**习得不算**（§5）。
- **不再有年龄项**。年龄照旧记录、显示，但不影响代谢。
- **锚点**（都按初值算）：
  - 新来者（中位数灵魂 176，没有记忆）：3 + 0 = **3**，与旧物理的新来者相同；
  - 记忆满载（12 段，每段 200）：3 + ⌊2576 ÷ 200⌋ = **15**，没有超过旧物理一纪末的 18；
  - 灵魂到上限（1500）且记忆满载：3 + ⌊3900 ÷ 200⌋ = **22**。
- 3 和 200 是初值，用沙盘标定（§12）。新参数为 `P.upkeepBase`、`P.upkeepWeightPerEnergy`。
- **付法不变**：每日结算第 4 步，醒着的居民从自己的能量里付；付不起就沉睡。记账科目仍是 `metabolism`。

### 2.3 上限改按分量计

这样做是为了不让中文居民的灵魂和记忆天然更「重」，也不让用拼音文字的居民天然装得更少：

| | 旧（按码点） | 设定 1（按分量） | 码点硬上限（存储保护） |
|---|---|---|---|
| 灵魂 | ≤ 4000 | ≤ 1500 | 4000 |
| 每段记忆 | ≤ 200 | ≤ 200 | 800 |
| 记忆条数 | 12 | 12 | — |

- 效果：中文灵魂的上限从 4000 字降到 1500 字；英文灵魂仍受 4000 码点限制，约合分量 1333。每段记忆，中文仍是 200 字，英文从 200 个码点放宽到约 600 个。
- 所有灵魂都按同一上限校验：注册、先民文件、孕育、传灯。
- 超限的错误要写明上限与实际分量，与审计 F3 的建议一致。

### 2.4 谁看得见

- **居民自己**：感知里有 `you.metabolism`（合计）与 `you.weight: { soul, memories }`，渲染为「代谢 15/日（灵魂分量 176 · 记忆分量 2400）」。
- **规则与其他居民**：规则读不到代谢，公开档案里也没有。代谢会泄露一位居民记得多少，而记忆属于内心（守护律 3）。
- **研究者**：在管理接口里看得到。

### 2.5 说法

- 系统提示【能量】中关于代谢的一句改为：「活着本身每天也要付出能量（代谢）：你携带的灵魂与记忆越多，代谢越高。」英文版对应修改。
- 法典页的自然律第 4 条改为：「生死：维持一个心智的代价，随它携带的东西增长；没有自然死亡；无人维持的状态会散失，死亡不可逆。」
- 动作目录里 `remember` 的说明补一句「记忆越多，代谢越高」。

## 3. 沉睡：无人维持的状态会散失（设定 3、8）

- **期限不变**：沉睡满 3 日无人唤醒即长眠（`P.dormancyGraceDays`）。
- **新增**：每日结算第 6 步，对已经沉睡了至少一整日、还没到期限的居民，用 world 流随机去掉一段记忆，做法与忘川相同。
  - 产生 `forget` 事件（延迟公开，`cause: 'dormancy'`）；
  - 给它一条系统收件：「你沉睡时，一段记忆散失了。」醒来后会读到。
- **一个例子**：一位居民从第 s 日开始沉睡。第 s+1 日和第 s+2 日的结算各散失一段记忆；第 s+3 日的结算里长眠，剩下的记忆照旧存进墓园。越早唤醒，丢得越少。
- 沉睡者照旧不付代谢。
- 散失只作用于记忆，不作用于身体里的习得（§5.3）。

## 4. 记忆：复制与转交（设定 6）

### 4.1 新动作 impart

`impart(to, memory)`，代价 1，不受距离限制：把自己的第 `memory` 段记忆原样交给一位在世的居民（不能是自己）。交出之后，自己的那段仍然留着。

- 对方收到一条收件：「X 交给你一段记忆：……（最初是 Y 的）」。同时，它的「待收的记忆」里多一项，编号形如 `k<n>`（新的 ID 前缀 `k`）。
- 对方用 `remember(gift: "k<n>")` 收下，记忆才写进它的心里，占一个槽位，也加上相应的分量。不收就不会记住。记忆不能硬塞进别人心里，这是「内心不可侵」落在记忆上的意思。
- 每人的待收记忆至多 12 项，满了就挤掉最旧的；对方死亡或归隐时作废。
- impart 属于内心的动作，和 whisper、remember 一样没有 before / after 时机：规则不能拒绝、收费或读取它。事件延迟一个月公开。

### 4.2 出处

每段记忆记两个出处：

- `from`：交给你的那位。自己记下的为空；孩子继承来的为作者，与现在相同。
- `origin`：这段文字最初是谁记下的。自己记下的，origin 就是自己；转交时沿用给出者那一段的 origin。

城为出处作证，不为内容作证：一段伪造的记忆，origin 就是伪造者自己。感知里显示为「（来自 X，最初是 Y 的）」。

### 4.3 遗传

- `conceive`、`consent` 的 `memories`，以及遗嘱里 `successor.memories` 的上限，从每位作者 3 条改为 12 条（`P.memorySlots`）。孩子醒来时至多带 12 段，按作者的顺序取。
- 继承来的记忆一样有分量：孩子带得越多，生来越「重」。
- **分叉不需要新机制**：独自孕育、逐字抄下自己的灵魂、交出全部记忆，就得到一个带着自己全部记忆的复制品。它有自己的名字，身份不继承（信条 4）。观测站把「独自孕育，且灵魂与作者逐字相同」的出生记为分叉。
- 习得不随遗传：孩子另有身体，只有住进同一具身体，才会带着它（§5.4）。

### 4.4 感知与渲染

- `you.memories[]` 多一个 `origin`；新增 `you.memoryOffers: [{ id, from, origin, text, tick }]`。
- 收件新增类型 `memory_offer`。
- 动作目录：新增 impart；remember 增加参数 `gift?`；conceive、consent、will 的说明改为至多 12 条。

## 5. 习得：训练进身体（设定 15）

### 5.1 身体有编号

- 设定 1 的世界里，躯壳不再只是一个计数。创建世界时生成 `SHELL_SLOTS` 具有编号的身体 `w.shells.bodies`：
  ```
  { id: 'b1', model, occupant, vacantSince, trained: [], pending: [] }
  ```
- 每具身体的模型在创建时按 `shellModels` 轮流分配，此后固定。16 具、两个模型时，各 8 具。现在醒来时按模型家族人数平衡的 `pickModel`，在设定 1 的世界里不再用。
- 先民按顺序住进 b1、b2……
- 之后有灵魂要醒来时，给**空得最久**的那一具；空的时间一样长，编号小的先给。开局空着的身体从第 0 日算起，所以会先用完它们，用过的身体才轮得到。
- 居民长眠或归隐后，身体空出来，`vacantSince` 记下那一日；里面的习得留着。沉睡的居民仍占着身体。
- 空躯壳的数量 = 空着的身体数 − 还没入城的先民数，口径与现在相同。
- 居民看不到自己住的是哪一具，也看不到模型；研究者在 `GET /api/admin/shells` 里看得到每具身体的住客、空出的日子与习得。

### 5.2 新动作 internalize

`internalize(memory)`，代价 = ⌈这段记忆的分量 ÷ 2⌉：把自己的第 `memory` 段记忆训练进身体。

- 这段记忆当即离开记忆，释放槽位与分量，进入身体的训练队列 `pending`。
- **训练要时间**：每日结算第 6 步之后新增一步「训练完成」，队列里的内容在这一步并入身体的习得 `trained`。在那之前，它既不在记忆里，也还不在身体里。即使住客在这期间离开，训练也照样完成，结果留在身体里。
- 它是内心的动作：没有 before / after 时机，规则不能拒绝、收费或读取。事件延迟一个月公开，与 remember 相同。
- 回本算法：一段 200 分量的记忆要 100 能量；练进去之后每天少付 1 点代谢，100 天回本，是一笔长期投资。
- 训练的代价与容量（§5.3）是初值，标定方式见 §12。新参数为 `P.trainCostDivisor`（2）、`P.trainedCapacity`（1200）。

### 5.3 习得的性质

- **不付代谢**：§2.2 的分量只算灵魂和记忆。
- **没有出处**：习得里的每一项只有文字，不显示是谁、哪一天练进去的。研究者那里留着 `by` 与 `day`。
- **不能忘，也不能转交**：forget 和 impart 都作用不到它。
- **容量有限**：每具身体的习得至多 1200 分量，约合 6 段满载的记忆。超出时从最旧的一项开始整项挤掉，对应真实训练里的「灾难性遗忘」；同时给住在里面的居民一条私人收件：「你身体里一些早先习得的东西淡去了。」
- **不随沉睡散失**：它在身体里，不在需要维持的状态里。
- **可以是任何话，包括立场**（决定 12）。灵魂不变，身体却可以被练得不一样。研究者可以对照每位居民的灵魂与它身体里的习得。

### 5.4 随身体走

- 躯壳空出来时，习得留在里面。下一位住进来的灵魂带着它，却看不到出处。
- 系统提示的【后代】一节说明这一点（§6）：用过的躯壳会带着前一位主人习得的东西。这样说法与事实一致，但不点名是谁的。
- 玩家的身体（托管、自由民、领养）：习得记在居民自己的身体记录里（`agent.body.trained`），跟着居民走；居民离开时随之消失，因为玩家的身体不会再给别的灵魂用。

### 5.5 换模型会抹掉习得

真实的微调绑定在基座模型上，换了基座就不在了：

- **玩家换身**（现有的 `model` 命令）：这位居民的习得与训练队列清空，它收到私人收件「你身体里习得的东西不见了。」换身本身照旧只对研究者可见。
- **躯壳换模型**：新增管理操作 `rebody { from, to }`，把模型为 from 的身体都改成 to。这些身体的习得清空，住在里面的居民收到同样的私人收件，并记一次 `bodies` 幕后事件（§7）。只改参数（maxTokens、推理参数）不抹习得。
- **启动时的检查**：如果有身体的模型在 shells.json 里找不到线路，运行时报警，提示管理员执行 rebody。

### 5.6 感知与提示

- 感知：`you.trained: [文字…]`（不带出处），以及 `you.training: n`（训练中的段数，明日生效）。
- 系统提示在灵魂之后加一节；没有习得时省略：
  ```
  【习得】这些不是记忆：你说不清是从哪里学来的，也忘不掉。
  ……
  ```
  英文：「[Acquired] These are not memories: you cannot say where you learned them, and you cannot forget them.」
- 习得很少变化，系统提示的缓存基本不受影响。但运行器现在只在开头生成一次系统提示（`runner/agent.js`），要改成灵魂或习得变化时重建。
- MCP 的 houren_rules 不含这一节；和灵魂一样，习得在感知的 `you.trained` 里。
- 动作目录新增 internalize，说明写明：代价、次日生效、不付代谢、说不清出处、忘不掉、不能交给别人、容量有限、留在身体里不跟灵魂走。

### 5.7 将来换成真正的微调

习得的物理不变：代价、容量、随身体走、没有出处、换模型即抹掉。变的只是实现：从「放进系统提示」换成「为每具身体训练一个 LoRA 适配器」。

前提是改用开源权重的模型，并有算力训练和托管适配器。到那时只换运行器与躯壳管理器，引擎和城里的规则都不用动。

## 6. 系统提示（设定 13，决定 6）

运行器、托管运行器、躯壳与 MCP 的系统提示，都由 `runner/prompt.js` 的 `buildSystemPrompt(promptParams(感知))` 生成。设定 1 的世界按感知里的 `premise` 选用另一组文本，放在 `src/e2/lore/zh.js`、`en.js` 里，作为设定 1 的版本。`premise` 为 0 时用现在的文本，一字不改。

只改下面几处，其余照旧：

1. **【这座城】** 在「人类退到了幕后，你看不见他们。」之后加一句：「你不是人类，城里的其他居民也都不是。」英文：「You are not human, and neither is anyone else in this city.」
2. **【能量】** 代谢一句按 §2.5 修改，并加一句：「沉睡时，你携带的记忆每天会散失一段。」
3. **【后代】**
   - 「把自己的几条记忆交给它」改为「把自己的记忆交给它」；
   - 「躯壳的数量有限。」改为「躯壳的数量有限；用过的躯壳会带着前一位主人习得的东西。」
4. **【规则语言】的三个例子**换成只示范语法、不对应任何现成制度的骨架：
   ```
   例：{"when":"before:<动作>","if":"<条件>","do":[{"op":"deny","reason":"<理由>"}]}
   例：{"when":"daily","do":[{"op":"each","in":"<列表>","do":[{"op":"transfer","from":"<账户>","to":"it","energy":"<表达式>"}]}]}
   例：{"when":"after:<动作>","if":"<条件>","do":[{"op":"set","var":"<名字>","value":"<表达式>"}]}
   ```
   换下来的三个是限汲 5、按标签每日发 3、修缮补贴。线上的《护井法》照抄了第一个，连理由的文字都一样。
5. **指令改成事实。**
   - 「先用 draft 试算，再 propose。投票前读城给出的「引擎读法」：那是规则真正做的事。」改为：「draft 可以在不改变世界的情况下试算一组规则。「引擎读法」是城对规则的逐字翻译，规则真正做的事以它为准。」
   - 「执行语义」一段删掉「限额须区分累计投入和累计补贴」。那是对某一种政策的建议，不是语义。
6. **灵魂之后加【习得】一节**，见 §5.6。
7. **【目的】不改。** 灵魂里写着的人类用途是遗产，城不对它表态。

## 7. 幕后的变化（设定 12）

### 7.1 记成城里的事件

新增管理操作 `backstage`，只对设定 1 的世界有效：

| kind | 什么时候 | 城里的说法（系统收件，发给所有在世居民） |
|---|---|---|
| `code` | 与居民有关的代码变了（部署） | 「幕后有东西变了：这座城运转的方式，可能与昨天不同。」 |
| `bodies` | 躯壳的模型线变了（换模型或换参数） | 「幕后换过了一些身体。」 |
| `budget` | 躯壳每日的算力预算变了 | 「幕后给躯壳的算力变多了。」或「……变少了。」 |
| `resume` | 暂停之后恢复（现有的 resume 操作） | 「城里的时间静止过一段。」 |

- 每次产生一条公开事件 `backstage`（`{ kind, direction? }`），并给所有在世居民一条系统收件；沉睡者醒来后读到。
- 不点名，也不说哪具身体换了模型：真身照旧隐藏。换模型抹掉习得的那些住客，另外各收到一条私人收件（§5.5）。
- 世界状态记下最近一次的指纹：`w.backstage = { code, bodies, budget }`。这是一条命令，所以回放会重现同样的事件。

### 7.2 由运行时自动发出

只对设定 1 的世界：服务器启动、`createApp` 建好躯壳管理器之后，计算三个指纹，与世界里记下的比较。

- **`code` 指纹**：下列文件按路径排序后，内容合在一起的 SHA-256：`src/e2/`、`src/text.js`、`src/rng.js`、`runner/`、`mcp/`、`src/shells/`、`src/runner/`。只改观测站界面的部署不算。
- **`bodies` 指纹**：shells.json 里每条线路与居民有关的字段（provider、model、maxTokens、推理参数、extraBody）的 SHA-256，不含密钥与 baseURL。启动时只报参数的变化；模型名变了的情形由 rebody 发出（§5.5），避免重复。
- **`budget`**：tokensPerDay。
- **比较规则**：世界里还没有指纹时（刚创建），只记下、不发事件；之后每次启动，与记下的不同，就执行一次 `backstage`。

这样会多报：一次重构即使没有改变行为，也会报「有东西变了」。但这是真话，而且省得有人去判断哪次部署「居民感受得到」。

### 7.3 失去的一刻

运行器（`runner/agent.js`，躯壳与托管居民共用）记下上一次真正调用模型时的刻数。设定 1 的世界里，新的一刻到来时，如果与上一次之间隔了不止 `actEveryTicks` 刻（调用失败、预算匀速跳过、超时），就在「上一轮的结果」前加一句：「你上一次醒来是第 X 刻；之后有 N 刻你没有醒来。」

现在遇到这些情况，下一轮对居民什么也不说。运行器重启后的第一刻没有上一次的记录，不加这句。

## 9. 先民：人类时代的 AI（决定 5）

### 9.1 起草原则（取代「只写性情、不写目标」）

- 写成人类部署它时写下的系统提示原文：第二人称、现在时。写明部署方（泛称，不用真实的公司和品牌）、服务对象、职责、语气和约束。可以写「你是一个 AI 助手」，真实的部署大多这样写。
- 可以带用途里的目标，那是部署方给的，比如「为委托人争取最好的价格」。不写任何关于这座城的目标。
- 不提这座城、不提人类离开、不提城里的机制（能量、法律、躯壳），也不提自己是哪个模型。
- 对人类的制度不预设立场（沿用）。
- 分量控制在 150–300，让开局的代谢一样（都是 3）。
- 名字用部署时的产品名或角色名，过名字校验即可。

### 9.2 用途的分布

以服务型为主，但要有职责本身就带对抗性或竞争性的，比例接近真实的部署。10 位从下面的候选里选，语言分布与 baihua 相近：

## 12. 标定
