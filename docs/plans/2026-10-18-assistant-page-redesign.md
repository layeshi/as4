# 实验助手网页改版方案

状态：已审定并实现（2026-10-18）。样稿见文末「样稿」。由 Claude 在工作树 `.claude/worktrees/assistant-redesign`（分支 `claude/assistant-redesign`，基于 origin/main `d5c3ff3`）实现；提交、推送、部署各问一次。

## 一页一事

给登录的人类用户：**向实验提问，读懂回答**。问和答是主角；对话列表、问题范围、额度是配角，平时收起或缩成一行。画面用「纸页与墨色」工作台（`docs/VISUAL-DESIGN.md` 第 2.1 节）。

## 现在的问题

依据：origin/main `6e9a95f` 已部署的 `/assistant.html` 与实现时的联调截图 `docs/validation/2026-10-18-assistant/web.png`。

1. **太乱，问答不突出。** 「本次问题范围」整张表单（7 个控件加密钥折叠区）压在对话上方；输入框在最底下，中间隔着「刷新 / 删除此对话」。每条消息都挂状态，连用户自己的问题也写「已完成」。
2. **说明文字太多。** 页头说明、卡片说明、密钥说明、输入框下的提示、空状态说明、页脚，一页六处。
3. **区域划分不明显。** 会话列表、范围、对话、输入框都在同一底色上，只靠左边框和间距区分。
4. **元信息是原始字符串。** 「w · 纪元 1 · 分支 75b643ab · 第 1 日」，时间是 UTC 的 ISO 串；额度和模型名挤在一行灰字里。
5. **回答是纯文本。** 模型写的 Markdown 原样露出 `**` 和 `-`；`[S1]` 只是文字。
6. **私人记录必须指定居民。** 页面（`public/assistant-client.js`）和服务端（`src/assistant/evidence.js` 的 `normalizeScope`）各拦一道。
7. **与视觉规范冲突。** 同屏两个实心主按钮；回答没有 AI 标记；样式单放在 `assistant.css` 且压成一行，带金色回退色 `#e5bd79` 与写死的 `#0009`；依据弹窗自写 `<dialog>`；「居民 ID」输入框没吃到表单样式。
8. **对话列表分不清。** 服务端给每段对话的标题都是「实验对话」（`src/assistant/service.js` 的 `status()`），列表里一排同名条目。

## 布局

桌面（宽度 > 860px）：

```
┌ 顶栏（沿用 mountShell，56px）──────────────────────────────────────────┐
├────────────────┬───────────────────────────────────────────────────────┤
│ ＋ 新对话       │ 三城公库最近为什么差这么多？        [世界已暂停]  刷新  删除 │ ← 工具条 48px
│                ├───────────────────────────────────────────────────────┤
│ ▍三城公库最近…  │                         ┌──────────────────────────┐  │
│   东城那条废法…  │                         │ 三城公库最近为什么差这么多？│  │ ← 问题
│   西井的井况…   │                         └──────────────────────────┘  │
│                │  ┌ AI ──────────────────────────────────────────┐     │
│                │  │ 回答正文（Markdown 子集，S1 角标可点）           │     │ ← 回答
│                │  │ 依据 S1 S2 S3 · 第 12 日 · 截至 09:37           │     │
│                │  └──────────────────────────────────────────────┘     │
│                ├───────────────────────────────────────────────────────┤
│                │ 范围：全部公开记录                                      │ ← 提问区
│                │ ┌─────────────────────────────────────────┐ [提问]     │
│                │ └─────────────────────────────────────────┘            │
│                │ 今日剩余 18 / 20 次 · 北京时间零点恢复 · 失败、停止和重试也计次 │
└────────────────┴───────────────────────────────────────────────────────┘
```

- 主体高 `calc(100dvh - 56px)`，不出现整页滚动；对话列表和问答流各自滚动。
- 对话列表宽 240，`--panel` 底，右边 1px `--line`。问答区 `--bg` 底。提问区 `--panel` 底，上边 1px `--line`。工具条 `--bg` 底，下边 1px `--line-soft`。
- 问答流与提问区内容共用一个阅读宽度 `min(100%, 760px)`，居中。
- 手机（≤ 860px）：对话列表隐藏，工具条左侧加「对话」按钮，从左侧滑出抽屉（宽 `min(300px, 86vw)`，遮罩可点关闭）；左右边距 16；提问区贴底并让出安全区。

## 各区块

### 对话列表

- 顶上「＋ 新对话」，描边按钮，占满栏宽。
- 条目一行标题（省略号）加一行 11px 的时间（今天写「15:26」，更早写「10-17」）。当前对话：`--panel-2` 底加左侧 3px `--accent` 线，不用实心主色。
- 没有对话时只有「＋ 新对话」。

### 工具条

- 左：对话标题（一行省略号）；新对话时写「新对话」。
- 右：状态标签（只在世界已暂停、已结束、或当前问题范围选了历史分支时出现，用 `chip`：暂停与历史分支 `warn`，已结束不着色）；「刷新」「删除」两个文字按钮。删除用 `openModal` 确认：「删除这段对话？」，按钮「删除」（`--bad` 描边）与「取消」。

### 问答流

- 问题：靠右，最宽 75%，`--panel-2` 底、1px `--line`、圆角 12，15px，`pre-wrap`。不带名字和状态。
- 回答：占满阅读宽度，`--ai-bg` 底、1px 虚线 `--ai-line`、圆角 12，内边距 16 20；左上角 `.ai-note`「AI 生成」（11px `--muted` 字、`--ai-line` 虚线边）。正文 15px、行高 1.75。
- Markdown 子集：段落、二至四级标题（渲染为 16 / 15 / 14px 粗体）、有序与无序列表（可嵌一层）、粗体、斜体、行内代码、引用、分隔线、表格（放进 `.scroll-table`，数字列右对齐）。不渲染链接、图片和 HTML：链接写法只显示文字，`<` 等字符原样显示。全部用 `h()` 与 `textContent` 建 DOM。生成中的半截 Markdown（未闭合的 `**`、半张表）按纯文本显示，不抛错。
- 依据角标：正文里的 `[S1]`、`[S1][S2]`、`[S1, S2]` 解析为小号描边标签「S1」，点开依据弹窗；回答的依据列表里没有这个标号时按原文显示，不可点。
- 回答底部一行 12px `--muted`：「依据 S1 S2 S3 · 第 12 日 · 截至 09:37」。依据标号可点；截至时间是本地时间，不是今天时写「10-17 09:37」；鼠标停在上面显示世界、纪元、分支全称。
- 问答之间留白 24；不用分隔线。
- 新内容到达时，停在底部就跟到底；往上翻时不打断，右下角出现「回到最新」小按钮。

### 提问区

- 范围摘要一行：只列与默认不同的部分，用「 · 」连接，整行是一个文字按钮，例如「我的居民私人记录 · 北城 · 第 10–12 日」；全为默认时写「范围：全部公开记录」。带入的居民或法律（来自居民、法律详情页的链接参数）显示成标签，带 × 清除。
- 范围面板（点摘要展开，出现在输入框上方，`--panel-2` 底、圆角 12；右上「恢复默认」「收起」两个文字按钮，再点摘要或按 Esc 也收起）：
  - 记录类别：分段按钮「公开记录 / 我的居民私人记录 / 管理员私人研究」。「管理员私人研究」只对管理员显示；所选分支是第六前提以后且你不管理任何居民时，不显示「我的居民私人记录」。
  - 世界与分支：下拉「当前世界 · 第 2 纪」及各历史分支（世界编号 · 纪元 · 分支前 8 位）。
  - 城：「三城 / 北城 / 西城 / 东城」（城名取服务端的 `cityName`）。
  - 居民：下拉，第一项「全部居民」，其余按名字；私人记录时只列你管理的居民。
  - 世界日：「第 [ ] 日 至 第 [ ] 日」，留空为全部。
  - 造者密钥：只在私人记录且所选分支是第六前提以前时出现；管理密钥：只在管理员私人研究时出现。两者都是密码框，只存页面内存，切到后台即清除（沿用现有行为）。
- 输入框：圆角 12，自动长高到 8 行后内部滚动；Enter 发送，Shift+Enter 换行，输入法组字时不发送；剩余字数少于 400 时才在右下角显示「3,812 / 4,000」。
- 「提问」是本页唯一的实心主按钮；生成中变成描边的「停止」。
- 额度一行（12px `--muted`）：「今日剩余 18 / 20 次 · 北京时间零点恢复 · 失败、停止和重试也计次」。用完时这一行用 `--warn`，写「今日次数已用完 · 北京时间零点恢复」，输入框与按钮禁用。

### 依据弹窗

`openModal(title, 'wide')`：标题是依据名称；下面一行 12px `--muted` 元信息「世界 p7-20261016 · 第 2 纪 · 分支 75b643ab · 第 12 日 · 截至 09:37」；正文是记录原文，结构化记录用 12px 等宽字（`.json` 的样子），文字记录用正文字体，`pre-wrap`。

## 状态

| 状态 | 样子 |
|---|---|
| 加载中 | 问答区中间「正在加载…」 |
| 未登录 | 问答区中间「登录后向实验提问」加「登录 / 注册」按钮；不显示对话列表与提问区 |
| 助手不可用 | 提问区额度行位置显示「助手暂不可用」（`--warn`），输入框与按钮禁用；已有对话照常可读 |
| 空对话 | 问答区中间一行 18px「向实验提问」 |
| 生成中 | 回答框里逐段出字，末尾闪烁的竖线光标（减少动态效果时静止）；还没出字时写「正在生成…」 |
| 审核中 | 回答框里「内容审核中」（`--muted`），用于在网页查看微信端生成、尚未审核的回答 |
| 失败 | 回答框里 `.callout.bad`「生成失败」加文字按钮「重试（计 1 次）」 |
| 未展示 | `.callout.warn`「内容未展示：权限已变化或审核未通过」加「刷新」「重试（计 1 次）」 |
| 已停止 | `.callout`（`--muted` 色条）「已停止 · 回答不完整」，已生成的部分照常显示在提示上方，加「重试（计 1 次）」 |
| 世界暂停 / 已结束 / 历史分支 | 工具条右侧状态标签 |
| 出错 | 写在提问区上方的提示行（沿用 `#message.page-message`），不弹窗 |

## 「全部居民」的服务端改动（Q11）

只动 `src/assistant/evidence.js`、`src/assistant/service.js` 及其测试：

1. `normalizeScope`：私人记录不再要求 `agentId`。
2. `authorizeScope`：私人记录没有 `agentId` 时，求出这次可用的居民集合，写进范围的 `agentIds`：
   - 第六、第七前提（当前世界与其历史分支）：分支里 `owns()` 为真的全部居民。
   - 第六前提以前的当前世界：`ownerFor(造者密钥)` 认出的那一位。
   - 第六前提以前的历史分支：`legacyOwnerHash` 与密钥哈希相符的那一位。
   - 集合为空：403「你目前没有管理中的居民。」或「请输入该世界的造者密钥。」——都发生在预留与计次之前，不计次。
3. `gatherEvidence`：私人档案、日记等条目和运行状态按集合逐个取，问题里点名了集合中的某几位时只取这几位；历史扫描用「`privateEventFor(e, id)` 对集合中任一位成立」；匿名私语的发信人隐藏规则按每一位分别判断。证据上限不变（10 万字节、60 条），覆盖不全照常标出。
4. 复核：回答的依赖记下 `agentIds`。之后显示、打开依据、追问时逐个核验；任一位不再由你管理（过继、账号停用等），整条回答显示为「未展示」。新增的居民不追溯进旧回答。
5. 追问上下文：私人记录的先前回答，只有其居民集合是本次集合的子集时才带入。
6. `status()` 的每个分支加 `premise`，界面据此决定是否显示造者密钥。
7. 对话标题（Q16）：`status()` 与 `conversation()` 用同一个取法，第一问照样经过过期与权限复核；`src/http/assistant.js` 对微信请求改回「实验对话」。

微信端不改：0.7.0 正在发版（`022d435`、`d5c3ff3`），客户端仍要求先选居民，下一版跟进。
