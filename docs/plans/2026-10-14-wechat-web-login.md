# 网页微信扫码登录

## 使用方式

网页 `/login.html` 增加「微信扫码」标签。生成小程序码后，微信扫一扫打开普通小程序的独立「确认网页登录」页。用户同意登录隐私说明并验证微信身份，核对网页和手机上的六位核对码，再点「确认登录网页」。网页获得自己的登录会话并回到原先请求的本站页面。

沿用上一项账号绑定：已绑定微信直接进入同一个网站账号，已完成合并的身份进入保留账号。不按昵称自动关联。首次微信登录按现有公开注册开关创建账号，手机页明确说明；原有账号密码登录保持可用。

采用现有普通小程序的扫码确认能力，没有引入另一套开放平台网站应用账号。小程序码由服务端 `getwxacodeunlimit` 接口生成，固定进入 `pages/web-login/index`，scene 是 32 位随机十六进制字符串；AppSecret、access_token 和 OpenID 均不下发网页。微信官方接口文档入口：<https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/qrcode-link/qr-code/getUnlimitedQRCode.html>。本次开发环境无法直接读取该官方页面，真实微信接口仍需随发布做联调验收。

## 安全与状态

- 二维码三分钟有效。手机扫描、确认、取消与网页兑换分离；扫描不会自动登录网页。
- 网页另持独立随机凭据，保存在 HttpOnly / SameSite=Strict Cookie 中，HTTPS 下设置 Secure。scene 本身不能读取二维码图像、轮询或换取登录会话。
- 每个二维码使用独立 Cookie 名，避免切换标签/语言后并发请求乱序覆盖新码凭据。刷新、离开面板会取消旧请求；到期、拒绝和网络错误停止轮询。页面切换忽略迟到响应。
- 手机须具备当前普通小程序的有效微信身份，且与当前账号实际绑定一致。普通密码会话、旧小游戏身份、其他账号均不能确认。
- 扫码锁定账号及认证版本；密码修改、停用或合并会使旧审批不可兑换。兑换只能一次，且不会覆盖浏览器已有有效账号。手机会话不会被网页兑换撤销，网页不继承手机的内容审核身份。
- 创建二维码按 IP（每分钟六次）、全站（每分钟六十次）限速，最多保存 200 个请求。状态只存内存，重启后须重新扫码。图片仅接收有限大小的 PNG/JPEG，由本站接口返回，遵循原网页 CSP，无第三方页面或脚本。

## 配置及上线顺序

依赖普通小程序配置 `WECHAT_MINIPROGRAM_APPID=wx83d31aa7fc9a797e` 与对应 `WECHAT_MINIPROGRAM_APP_SECRET`，保留原小游戏配置。

- `WECHAT_WEB_LOGIN=0`：关闭网页扫码入口及出码。默认在普通小程序凭据齐备时开放。
- `WECHAT_QR_ENVIRONMENT=release`：默认正式版，出码时检查确认页已经发布。联调可选 `trial` / `develop`；仅限对应微信体验或开发人员，不能作为面向所有用户的正式验收。

先在体验环境更新后端与小程序确认页，配置对应环境，完成真实扫码→验证→确认→返回原网页的测试。正式上线需先发布含确认页的小程序，再开放网页正式版出码；未发布确认页时出码应报错并保留密码登录。若先部署后端，应暂设 `WECHAT_WEB_LOGIN=0`。

本任务仅修改本地代码，没有部署生产、上传微信代码或变更微信后台配置。生产变更继续遵循保状态部署技能。

## 验证

新增测试覆盖完整 HTTP 登录闭环、浏览器凭据隔离、显式手机确认、一次性兑换、保持手机会话、原网页登录门放行、错误应用/其他账号/密码会话拒绝、取消/到期/刷新、改密后审批作废、CSRF、限流、已登录浏览器保护、微信返回错误的脱敏处理，以及原生手机确认页交互。

网页测试覆盖等待确认、过期与拒绝停止轮询、离开面板时迟到响应取消、可见扫码入口与密码切换。专门回归并发出码乱序返回，确认旧响应不能破坏新二维码。微信上游与手机 API 在自动测试中使用替身，不代表官方编译或真机验收完成。

本次验证结果：相关账号、绑定/合并、微信接口与网页界面共 71 项测试通过、0 失败。小程序 2 页、38 文件的离线结构及语法检查通过。独立审查发现的旧出码响应覆盖新凭据问题已修复，复核通过。
