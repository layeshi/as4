# 小程序与网页账号绑定及合并

## 结果与使用方式

实现基于 GitHub main `668ff91`，分支 `codex/wechat-account-binding`。复用普通小程序分支已有的平台适配与双 AppID 支持；当前普通小程序为 `wx83d31aa7fc9a797e`，旧小游戏为 `wx216f3fb724629f67`。此文描述本地实现，不表示已经部署或上传。

- 已有网页账号：小程序「我的」→「已有网站账号」→输入用户名密码→关联微信。两端使用同一 accountId。
- 只有微信账号：小程序「我的」→「设置网页登录密码」，复制系统生成的用户名，设置密码后可直接登录网页。新的微信身份验证不可由旧登录 Cookie 替代。
- 已有两个独立账号：先登录微信账号→「合并到已有网站账号」→验证目标网页账号密码与当前微信身份→核对账号、居民数量、余额→确认迁移。保留网页账号的用户名、密码、显示名；旧微信账号停用。不会自动合并同名或相同 OpenID 的跨 AppID 身份。
- 网页账号设置页显示微信关联状态和操作指引。持久绑定与本次微信审核身份有效期分别表示；微信审核身份过期不会被误报为未绑定。

用户明确选择允许验证两端身份后合并。单纯拒绝冲突无法覆盖先微信注册再创建网页账号的常见使用顺序；按昵称、客户端 OpenID 或未验证 UnionID 自动合并缺少可信授权。因此采用两端验证与预览确认。

## 合并范围与约束

当前实现支持 P6 当前世界中的两个正常普通账号。管理员账号、停用账号、合并中的账号、同一微信应用绑定不同身份的两个账号均拒绝合并。目标已与当前微信账号相同则提示无需合并。

迁移当前世界居民的管理权与创建归属、历史关联、微信身份绑定、托管余额（含负余额）、累计托管费用与用量、入账申请和账本历史；账本保留原账号标记。居民词元和其他世界内财产随居民保留，不重新发行。启动奖励领取资格取两账号的并集，禁止合并后重复领取。两账号涉及的待接受居民转交邀请取消，历史已完成记录保留。

有效运行器保留原配置和启停选择，更新账号及居民授权版本；私有模型密钥仍在原加密文件中。按账号记录的居民运行用量归并，居民总体累计不重复计算。源账号不再允许密码登录、微信登录或管理员重新启用；微信身份改为登录目标账号。

预览票据仅在服务器内存中保存，五分钟失效；绑定来源账号、两账号认证版本及世界/居民归属/余额快照。两端凭据、账号状态或预览内容变化后须重新验证/预览。确认只接受当前来源账号会话和显式确认。密码输入清理，不写入客户端存储。

## 一致性与恢复

1. 验证两端身份、冲突、金额溢出和关联上限。预览不迁移数据。
2. 在 `accounts.json` 持久化合并意图并锁定两账号，撤销旧会话版本；异步停下相关运行器、等待结算。
3. 账本通过合并编号记录收据，迁移余额/请求/用量。请求编号在目标账号命名空间内去重，避免重启后账本校验失败。
4. 居民迁移通过世界 `account/merge_accounts` 命令执行并留幂等收据，保证可回放；更新加密运行器、用量文件。
5. 完成账户身份归并，停用源账号并解除目标锁定，签发目标会话。

文件使用落盘后原子替换；各阶段允许重复执行。中途故障时不重新开放部分迁移的账号。服务启动时在运行器启动前自动恢复未完成意图，按收据继续完成，避免重复转账。磁盘故障需先恢复可写性后重启；不得删除 `mergePending`、手工回滚单独账本或使用旧版本绕过恢复。恢复需保留原世界、账户、账本、运行器及用量文件整体。

首次设置网页登录密码使用独立 `authRevision`，只撤销旧会话，保持已有运行器授权；旧密码的异步校验不能跨越密码更新成功登录。合并期间第三方不能接受由锁定账号发出的旧转交邀请。

## 上线条件

生产必须保留旧 `WECHAT_APPID` / `WECHAT_APP_SECRET`，额外配置正确普通小程序的 `WECHAT_MINIPROGRAM_APPID=wx83d31aa7fc9a797e` 与对应密钥。仅更新客户端或仅切换旧 AppID 均不完整。凭据不进入代码、客户端、测试或本文。

发布脚本匿名预检使用 `/api/wechat/public/`，保留网页登录门。普通小程序和旧小游戏分开构建；生成的 `runtime/` 与构建包不手工修改、不提交。

此任务没有修改生产账户、余额、居民、配置或服务器，也没有上传微信版本。上线须使用项目保状态部署流程并完成真机验证：网页登录→关联微信、微信账号→网页登录、两端验证→预览→合并→居民/余额/运行器复查。

## 验证
