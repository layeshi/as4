## 1. 对「账号独立于居民」的修改

[账号设计](2026-10-02-user-accounts-design.md) 写的是「人类用户账号独立于 Agent 身份、造者密钥与世界事件」。这次改动之后：

- **仍然成立**：账号与造者密钥无关（服务器不保存密钥，认领时只是用它验证一次）；账号与世界事件无关（关联不进世界状态）；账号不能控制居民。
- **改变的一点**：账号可以持有「我的居民」这份只读清单。因此界面上「密钥不会同步到用户账号」的说法保留，但不再暗示账号和居民毫无关系。

## 2. 接口

账号接口沿用账号体系的规则：Cookie 会话，写请求要求 JSON 与 `X-Houren-Request`，拒绝跨站。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/account/agents` | 当前账号关联的居民：`{ agents: [{ agentId, name, status, runnerStatus, linkedAt, usage }] }`，`usage` 与 `GET /api/owner/usage` 同形（未托管为 `{ tracked: false }`）。关联已失效的（居民已被过继）顺带清掉，不返回 |
| POST | `/api/account/agents` | 认领：`{ ownerKey }` 或 `{ ownerKeys: [...] }`（≤ 50）。返回 `{ results: [{ ok: true, agentId, name } \| { ok: false, code }] }`，与请求顺序一致；密钥不对和密钥对应的居民不存在不加区分。重复认领是幂等的 |
| DELETE | `/api/account/agents/:agentId` | 解除关联，只影响自己的账号 |
| GET | `/api/admin/usage` | 管理员总视图（见下） |

入境接口（`/api/port/register`、`adopt`、`foster`）：请求带着有效的登录会话时，成功之后把新居民关联到该账号，响应多一个 `account: { linked: true }`（关联失败为 `false`，居民与一次性凭据照常返回，可事后认领）。没有登录会话时响应与以前完全一致。

管理员总视图 `GET /api/admin/usage`：

```json
{
  "timezone": "Asia/Shanghai", "day": "2026-10-03", "hosted": 9, "unhosted": 3,
  "total": { "calls": 0, "failed": 0, "unreported": 0, "input": 0, "output": 0, "tokens": 0 },
  "today": { "...": "同 total" },
  "days": [ { "day": "2026-10-03", "...": "近 14 日的全城合计" } ],
  "agents": [ { "agentId": "a17", "name": "青禾", "status": "awake", "model": "glm-5.3", "creatorName": "……",
                "accounts": ["alice"], "runnerStatus": "waiting",
                "usage": { "since": "…", "lastCallAt": "…", "total": {}, "today": {} } } ]
}
```

`agents` 按今日用量从多到少；`unhosted` 是在世但没有托管运行器的居民数（自托管或未接入），不在统计内。`creatorName` 是玩家自己填的文字（界面一律按文本渲染）；`accounts` 是关联了这位居民的账号用户名。

## 3. 界面

- **用户中心 → 我的居民**（所有登录用户）：一张表（居民、状态、今日、累计、调用及失败 / 未报告提示）；操作按钮在居民名字下面，窄屏上也看得见：「进入幕后」只在本浏览器保存了这位居民的造者密钥时可点，否则说明原因；「解除关联」；表下面是认领表单（粘贴造者密钥）和「认领本浏览器已保存的居民」。
- **用户中心 → 托管用量**（仅管理员账号）：数字块（托管居民数、今日、累计、调用）、近 14 日合计图、居民表（造者署名、关联账号、模型、今日、累计、调用、最近调用）。
- 窄屏时表格只留数字，次要的列收起，与幕后「用量总览」一致。

## 4. 不做什么（留给之后）

- **完整关联**：账号会话直接控制居民（不用密钥进幕后）。账号被盗就等于居民被控制，是更大的安全模型变更，另写方案。
- 管理员视图**按模型汇总**：存储里目前只有最近 20 次调用带模型名，没有分模型的累计，要做得先加。
- 幕后「用量总览」与「我的居民」合并成一张表。
- 入境向导里的「关联到我的账号」勾选（比自动关联同意更明确，多一块界面）。
