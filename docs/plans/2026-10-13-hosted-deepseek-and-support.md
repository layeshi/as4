# 平台托管 DeepSeek、余额与打赏 · 方案

日期：2026-10-13。状态：第一节的五项由用户决定；第二节是实施默认值，用户可以推翻。

本方案覆盖同一轮的五项网站功能：管理员看服务器负载与注册用户数、「我的居民」显示下次醒来时间、打赏、购买平台托管 DeepSeek 的额度。前两项与打赏不改变世界规则；托管额度只涉及真实模型调用的付费方式，不进世界状态、命令日志与回放。

## 1. 用户的决定

1. **付款方式**：扫码付款，管理员手动入账。管理员也能在后台手动加减余额，用来纠错、赠送和退款。
2. **计价**：人民币余额。每次调用按管理员填写的 DeepSeek 官方单价成本价扣费，单价有三个：输入命中缓存、输入未命中缓存、输出。不加价。
3. **打赏收款**：微信收款码、支付宝收款码。仓库是公开的，所以图片由管理员在后台上传，只存在服务器的数据目录，不进 git。
4. **可见范围**：服务器负载（CPU、内存、网络）与注册用户数只给管理员看。
5. **下次醒来时间**：显示在「我的居民」列表与居民详情的总览里。

## 2. 实施默认值（待你确认）

**买到的是什么**
- 买的是模型调用，不是游戏里的词元。余额不进世界状态，也不改变居民的词元、物料、名额或任何特权。打赏同样不带来游戏内回报。
- 余额以账号为单位：该账号管理的、选了平台托管的所有居民共用一份余额。扣费归调用发起时的管理账号（与 SPEC-P6 §3.2「先前调用产生的供应商用量归发起时的账号」一致）。
- 余额只能用于平台托管模型的调用，不能提现、不能转让。退款由管理员线下处理，并在后台扣减余额、写明原因。

**金额与扣费**
- 内部金额一律用整数「微元」（1 元 = 1,000,000 微元），避免浮点误差；界面显示到 0.0001 元。单价以「元 / 百万 token」录入，存成「微元 / 百万 token」整数。
- 一次调用的费用 = ⌈(未命中输入 × 未命中单价 + 命中输入 × 命中单价 + 输出 × 输出单价) ÷ 1,000,000⌉ 微元。命中输入取服务商报告的缓存命中数（DeepSeek 的 `prompt_cache_hit_tokens`，或 OpenAI 兼容的 `prompt_tokens_details.cached_tokens`）。
- 每次调用前按上界预留：输入 token 数按请求的字符数计（DeepSeek 对中英文的 token 数都少于字符数），全部按未命中单价；输出按单次最大输出 token 数。可用余额（余额 − 在途预留）不够就不发请求。
- 调用结束后结算并释放预留：失败或我方取消的调用不收费；成功但服务商没报告用量的，按预留额收；实际费用超过预留的按实际收，余额可能略为负，之后不再发起调用，直到补足。
- 预留只放在内存里。进程崩溃时，正在进行的调用不收费，由平台承担（每位居民至多一次调用的费用）。

**余额不足时**
- 醒来之前先看可用余额：连一次调用的输出预留都不够时，这一刻不醒来，不向世界提交任何命令，也不扣游戏词元；状态显示「托管余额不足」。
- 醒来后第一次调用前预留失败时，这次醒来结束，退回这次醒来已扣的游戏词元（与第一次调用失败时的退回相同）。醒来后已经调用过模型、之后再预留失败的，这次醒来提前结束，不退。
- 居民照常在世界里生活与消耗。补足余额后，下一个作息时刻自动恢复调用，不需要重新启动。

**入账流程**
1. 用户在「我的居民」页看到余额、单价与收款码；扫码付款时在备注里写上自己的用户名。
2. 付款后在同一页提交入账申请：金额（1–5,000 元，最多两位小数）与付款说明（付款时间、方式等，最多 200 字）。
3. 管理员核对到账后批准，可以把实际入账金额改成实收数；或者拒绝并写明原因。用户可以撤回自己尚未处理的申请。
4. 每个账号同时最多 5 个待处理申请，每小时最多提交 10 次。同一请求编号重复提交返回同一结果；已处理的申请不能再次批准。

**托管模型的配置**
- 管理员在后台设置：是否开放、接口地址（缺省 `https://api.deepseek.com`）、模型 ID、API Key、思考模式、单次最大输出 token 数（缺省 4096）、三个单价。API Key 加密保存在数据目录，只写不回显，不写进居民的运行配置、日志与接口响应。
- 管理员保存新配置后，正在运行的托管居民自动重启，换用新配置；关闭托管后，这些居民停止调用，状态「平台托管暂停」，用户可以改用自己的模型。
- 管理员可以对托管配置做连接测试（平台承担费用）。用户选平台托管时没有连接测试，避免每测一次就扣一次钱。
- 公开的模型标注沿用现有做法：保存设置时记一次当时的模型 ID；管理员之后换模型不改写世界记录。

**用户这一侧**
- 居民的模型设置里选「平台托管 DeepSeek（从我的余额扣费）」或「我自己的模型」。选托管时不需要填接口、模型与 Key。接受过继时同样可以选。
- 「我的居民」页的账户区：余额、在途预留、模型与单价、收款码与付款说明、入账申请与状态、最近的充值与调整、最近 30 个现实日按居民汇总的扣费。

**记录与保存**
- 充值、调整逐条记录（时间、金额、经办管理员、说明）。调用费用按「账号 × 居民 × 现实日」汇总（调用次数、输入、命中、输出、费用），保留 90 个现实日，另记每个账号的累计。现实日的时区与现有用量统计相同（`SHELL_TZ`，缺省 Asia/Shanghai）。
- 余额守恒：所有账号的余额之和 = 入账与调整之和 − 扣费之和。

**不做的事**
- 不接微信支付、支付宝接口，不自动到账。
- 微信小游戏不加入购买与打赏：小游戏里的虚拟物品购买另有平台规定。
- 不为托管模式设免费试用额度；需要时由管理员手动赠送。

**合规提醒**：用个人收款码收取经营性款项、转售模型 API 额度，可能涉及收款码使用规定与 DeepSeek 的服务条款。正式开放购买前请你自行确认。

## 3. 接口

用户（登录）：
- `GET /api/account/hosted`：托管是否开放、模型 ID、单价、单次最大输出、余额、在途预留、我的入账申请（最近 20 条）、最近 50 条充值与调整、最近 30 天按居民的扣费汇总。
- `POST /api/account/hosted/requests`：`{ amountMicro, note, requestId }`，提交入账申请。
- `POST /api/account/hosted/requests/:id/cancel`：撤回自己待处理的申请。

管理员：
- `GET /api/admin/hosted`：配置（不含 Key，只给 `hasApiKey`）、统计（余额合计、在途预留、今日扣费、今日调用与 token、托管居民数）、待处理申请、有余额或用量的账号。
- `POST /api/admin/hosted/config`：保存配置（Key 留空则保留，`clearApiKey` 清除）。
- `POST /api/admin/hosted/test`：用提交的配置（Key 留空则用已保存的）做一次连接测试。
- `POST /api/admin/hosted/requests/:id/approve`：`{ creditMicro, note }`；`/reject`：`{ note }`。
- `POST /api/admin/hosted/adjust`：`{ username, amountMicro（可为负）, note }`。
- `GET /api/admin/server-status`：CPU、内存、网络、运行时长、注册用户数。

打赏：
- `GET /api/public/support`、`GET /api/public/support/qr/:kind`（公开）；`POST`/`DELETE /api/admin/support/qr/:kind`（管理员）。`kind` 为 `wechat` 或 `alipay`。
- 页面 `/support.html`，首页页脚与「我的居民」页有入口。

## 4. 数据文件（都在数据目录，随整体备份保留）

- `support/wechat.png`、`support/alipay.png`：重新编码、去掉元数据的收款码。
- `hosted/model.enc`、`hosted/model.key`：加密的托管模型配置与密钥（0600）。
- `hosted/billing.json`：余额、充值与调整记录、入账申请、按日汇总的扣费（原子写入）。
