# OpenLux 平台托管模型设计访谈

状态：用户已确认完整方案；功能已在 codex/openlux-hosted-models 实现，已通过全量及补充回归验证，尚未部署生产。

## 用户已确定的要求

- 平台托管模型服务改为接入 OpenLux：https://www.openlux.ai/。
- 用户可以选择 OpenLux 中的模型，不再仅能选择 DeepSeek。
- 首批限定为以下 9 个模型，不自动加入其他模型：
  - `gpt-6-luna`
  - `gpt-6-astra`
  - `claude-opus-5-5`
  - `gemini-3.8-flash`
  - `gpt-6.1-sol`
  - `deepseek-v4.1-flash`
  - `deepseek-v4-pro`
  - `doubao-seed-2-0-mini-260428`
  - `grok-4.7`
- 上述名称按用户原文记录；接入时逐一核验 OpenLux 实际模型 ID、平台 Key 权限、对应分组价格和工具调用兼容性。不擅自映射到近似名称；未通过验证的项目不开放使用，并明确报告原因。
- 采用 OpenLux 美元标价，固定按 1 美元 = 7 人民币换算。
- 换算后乘固定计费倍率，初始倍率为 1.2。
- 对同一计量单位，平台人民币单价 = OpenLux 美元单价 × 7 × 1.2 = 美元单价数值 × 8.4。
- 输入、输出、缓存读取与缓存写入分别按各自上游单价换算，不以单一价格混算；价格不完整或存在平台暂不支持的收费项目时，不开放该模型。

## 代码基线发现

当前工作目录位于较早的 codex/cloudflare-migration-poc 分支，存在大量既有修改，不含当前托管计费功能。已在本地 origin/main 和 main 工作副本发现 src/hosted/service.js、src/hosted/billing.js 等现有实现；后续设计以该实现为事实依据，实施前再确定隔离工作副本。

## 第一轮已确认

1. 模型开放范围：开放经兼容性检查、可驱动居民行动的文本对话模型。
2. 老用户迁移：迁往首批限定名单中对应的 OpenLux DeepSeek 模型；无对应模型时保留配置、暂停并提示选择，不迁往名单外模型。
3. 调价方式：管理员确认后发布；每次计费保存当时采用的价格，历史账单不随调价变化。

## 第二轮已确认

4. 用户不选择或关心线路分组，由平台实际使用的 OpenLux Key 决定分组。当前 Key 使用用户所述“最中间一档”；实施时按实际 Key 对应分组核验并取价，不能按模型列表位置猜测。公开目录各系列档位数量不同，未找到统一的中间档标识；定价页默认的最低价不能直接作为本平台价格。
5. 仅开放价格完整、平台能准确计费的模型。缓存读取与缓存写入分别计费，暂不支持的阶梯价格或额外费用模型不开放。
6. 每个居民分别选择模型，可以随时切换，从下一次调用生效；正在执行的调用仍按原模型和原价格结算。
7. 管理员可以调整计费倍率，初始值为 1.2；汇率固定为 7。调整只影响后续调用。选择界面展示最终人民币单价，账单保存模型与计费依据。

## 主线实现事实

- 主线托管实现位于 src/hosted/service.js 与 src/hosted/billing.js，运行器按全局唯一模型启动，用户当前只提交 hosted 标记。
- 当前按人民币微元记账，分别计算普通输入、缓存命中、输出；每次调用向上取整至微元。
- 当前预留记录带价格快照，但日账单只按账号、居民、日期聚合，未记录模型或价格版本。
- 当前仅支持 OpenAI 兼容接口与原生工具调用；新模型需要验证真实工具调用兼容性。
- 原文案承诺 DeepSeek 成本价、不加价；新方案应同步修改相关界面与说明。
- OpenLux 公开价格目录存在分组倍率，模型标识本身不足以唯一确定适用价格，需要同时确定实际使用线路分组。

## 继续核查

- 官方模型目录、价格计量单位、缓存与其他收费项目、接口兼容性。
- 现有余额、账单、运行器及用户配置的约束。
- 接入时核实实际 Key 对应分组及目录映射；若不能自动查询，由管理员配置并核验，不向终端用户暴露线路选择。
- 实施时核验接口地址、Key 对应分组、模型工具调用能力与用量字段；这些属于接入验证，不再重新询问已确认的产品决策。

## 第三轮已确认

8. 模型下架、权限不足或持续失败时，暂停并提示用户换模型，不自动替换；短暂网络错误沿用重试。
9. 上游响应缺少计费用量时，按用户明确选择沿用现行规则：扣除该次调用全额预留费用。不采用待核对及暂停后续调用的方案。账单应明确区分实际用量结算与缺少用量时的预留额结算。

## 实施范围与验证

- 验证价格换算与取整、价格发布、模型切换、旧配置兼容、缓存用量、缺少用量及不可用模型处理。
- 基于含当前托管功能的主线建立隔离工作副本，保护当前目录的既有修改。

## 补充需求：选模价格与费用预估

- 用户选择模型时展示各项实际人民币单价，价格已包含固定汇率与平台计费倍率。
- 根据居民设置的 token 上限，展示每日与每月所需费用区间；切换模型或修改上限时同步更新。
- 已核实：dailyCap 限制游戏思考权重，包含重读折扣和写入权重；上游按实际输入、输出和缓存用量计费，两者不等同，不能直接用 dailyCap 乘模型单价。
- 预估必须标明计算假设，不能把游戏额度对应的参考费用误称为实际扣费保证上限。

### 第四轮已确认：估算口径

- 显示“按每日额度用满估算”，每月固定按 30 天折算，不称为本自然月账单。
- 按游戏词元与上游用量的换算关系、输入/输出比例及缓存比例构造低/高消耗场景，使用当前发布的人民币单价计算区间。
- 优先使用经核验的实际运行样本校准；没有样本的模型使用明确标注的粗估场景，并展示其假设，不能把旧文档中的粗略比例当作新模型的实测结论。
- 展示“实际费用随活跃度、上下文和缓存变化”，说明实际费用可能低于或超过所示区间，该区间不构成硬性消费上限。
- 验证模型或每日额度变化时的实时重算、每日与 30 天金额的一致性、价格版本一致性、无样本时粗估标识及计算假设展示。
