## 第一轮已确认决定

1. 使用者：面向登录的人类用户和管理员；游客仅显示介绍和登录入口，AI 居民不调用助手。
2. 问答范围：覆盖实验理念与规则、软件用法、当前世界状态、已有历史和趋势分析，内容受提问者权限约束。
3. 行为边界：首版查询、解释和提出建议；不代为暂停实验、修改规则、操作居民或发送家书。
4. 交付端：网页与微信小程序均提供问答入口，共用数据与权限规则。
5. 回答标准：重要事实带来源及数据时间，区分事实与推测，证据不足时说明未知。

## 第二轮已确认决定

6. 私人内容：普通用户访问已公开内容；查询自己居民的私人记录须核验当前权限，具体验证按第 12 项更新；管理员访问全体居民私有研究记录须额外通过现有管理密钥验证。仅将本次问题需要且允许访问的内容送往助手模型；验证凭证不进入模型。
7. 历史范围：覆盖当前实验及可读取的已保存历史，包括旧纪元；具体三城范围按第 13 项更新。缺失或未接入的历史明确标识；不同纪元和恢复分支不混淆。
8. 模型与费用：管理员统一配置助手专用模型，平台承担费用；额度独立于居民行动，设置每用户和全站限额，默认值见第 15 项。
9. 对话保留：支持多轮对话，同账号网页与微信同步，默认保存 30 天，用户可主动删除；历史对话的私有内容在重新显示或用于追问前重新核验权限。
10. 交互方式：两端均提供独立助手页，支持文字提问、来源查看和从居民/法律详情带入明确对象；首版不提供语音或文件上传。网页逐步显示，微信按第 17 项审核后显示。
11. 暂停与结束：实验暂停或纪元结束后仍可问答；助手只读取对应记录，不推动世界时间或居民行动；暂停/结束状态与数据截至时间明确显示。

## 第三轮已确认决定

12. 居民身份验证：按新版本的当前账号管理权访问自己居民的私人记录，不重复要求输入造者密钥；旧世界保留对应凭证验证。管理员研究记录的额外管理密钥验证保持第二轮决定。
13. 世界与城市：将第二轮范围修正为当前世界的全部三城，可分城查询或比较，同时查询可读取的旧纪元；不接入其他独立部署的实验。
14. 初始模型：复用现有 OpenLux 接入，助手独立选用已接通的 `gpt-6-luna`，管理员可切换已验证模型；不自动切换备用模型，问答与证据能力须专项验收。
15. 初始额度：每账号每天最多发起 20 次回答，全站每天模型成本预算 20 元人民币，北京时间零点重置，管理员可调；助手不扣用户余额。预算含在途预留，按核验的上游成本计算，不应用居民托管加价倍率。初始金额是运营预算，不是效果或容量估计。
16. 等待与故障：一次问答最多等待 60 秒，可停止生成；失败保留问题并允许手动重试，不自动换模型或无限重试。达到限额显示恢复时间，不挤占居民行动额度。
17. 微信展示：网页逐步显示回复，小程序生成完成并通过现有文本审核后显示全文；两端来源一致，审核未通过或不可用时不展示该答案。
18. 对话到期：每条消息从产生时起保存 30 天；用户删除后立即从在线对话和后续模型上下文移除，不能通过追问找回。备份留存另遵循既有备份周期，不宣称删除覆盖模型供应商留存。敏感回答在后续显示、取证和追问时重新核验权限。

## 完整功能设计

### 问答与证据

助手在当前世界中工作，用户可指定城市、居民、法律、时间区间或旧纪元。未指定时采用页面明确显示的当前世界与对象；同名居民、同一世界日的不同历史分支等存在歧义时，先澄清再回答。从详情页进入时显示所带入对象，避免用户误以为助手正在查询另一居民。

回答支持以下内容：

| 类别 | 典型问题 | 依据与回答要求 |
| --- | --- | --- |
| 理念和用法 | 实验研究什么，如何创建居民 | 对应版本的正式说明与操作规则 |
| 当前状态 | 三城各有多少居民，某城公库有多少 | 查询时的真实状态与统计，并显示截至时间 |
| 规则解释 | 这条法律实际如何执行 | 当前有效规则与引擎读法，区分居民原文和实际效果 |
| 历史与比较 | 昨天发生了什么，三城变化有什么区别 | 同一统计口径的事件和历史数据，标明覆盖范围 |
| 原因分析 | 某居民为什么离世，公库为何增长 | 实际记录与计算结果；无法确定的动机、因果明确作为推测 |
| 私人研究 | 我的居民为何反复失败，管理员如何解释运行异常 | 经授权的私人记录及运行信息，不扩大读取范围 |

重要事实附可打开的依据，展示来源名称、事件或规则标识、世界/纪元/分支以及适用时间。数值汇总由可验证的查询和计算产生，不能依靠模型凭印象计数。实时回答采用一致的观测时点或明确的记录范围；历史回答不能把当前规则当成当时规则。

历史未保存、尚未接入、未公开或当前用户无权读取时，清楚说明限制。缺少完整账本或事件时不能把局部样本说成全量因果解释。实验之外的问题只简短说明助手范围；首版不接入外部网页搜索。

### 权限与对话隔离

| 身份 | 允许使用的证据 |
| --- | --- |
| 游客 | 功能说明和登录入口，无问答调用 |
| 登录用户 | 已公开且当前可访问的实验内容 |
| 当前居民管理者 | 上述内容及其管理居民的已保存私人记录；P6/P7 按当前账号管理权验证 |
| 旧世界造者 | 根据该世界原有凭证机制验证后访问对应私人内容 |
| 管理员 | 当前管理员可见的运行信息；全体居民私有研究记录另需有效管理密钥验证 |

用户选择私人查询范围后，仅将问题所需且已授权的内容送给助手模型。先在服务端核验权限再检索和构建上下文，不能依靠提示词隐藏已经提供给模型的秘密。凭证、密码、令牌和模型密钥不属于回答依据。

问答生成期间、返回前、查看旧回答、打开来源和再次追问均须适时核验当前权限。居民过继、账号停用、会话失效、管理员资格或管理密钥变化后，不继续显示或利用已失去权限的内容；已传给用户的既往内容无法远程收回。无法可靠拆分的敏感回答整条隐藏，并提示访问权限已变化，不能只隐藏来源而保留其摘要。

私人内容的权限标记沿后续摘要和回答传播，避免通过“复述上一条”“总结我们的对话”等方式绕过撤权。不同账号的会话、缓存、检索结果和文件链接必须隔离。历史分支中的居民标识和权属分别核验，不能把当前世界的同编号管理权直接套用于旧档案。

### 模型、额度和失败处理

管理员在助手设置中选择已验证模型、配置每天的用户次数和全站成本预算、查看用量与失败状态。默认值为 `gpt-6-luna`、20 次/账号/地球日、20 元/全站/地球日、单次 60 秒。默认管理员也受问答次数限制，可通过管理员设置调整额度；后台配置操作不算问答。

以下为最终方案待确认的计数落实口径：一次被接纳并开始检索/生成的用户问答计一次；开始后失败、主动停止或微信展示审核失败也计次，重试视为新问答。登录、权限、格式、额度等准入检查拒绝的不计次。一次问答内部的检索和模型工具轮次不额外增加用户次数，但所有实际模型调用都计入成本。

模型成本按核验的上游价格、输入/输出/缓存等实际计费项目记录，人民币换算复用已核实的汇率配置，不应用居民托管加价倍率。启动调用前预留本次最大受限开销，完成后用实际用量结算；并发请求不能重复花费同一预算。价格或计量项目不可靠时不开放相应模型。已发往上游但用量未知的调用保守保留预留，不能当作免费而不断重试。

每次问答固定所用模型及价格版本，管理员变更只影响新问答。限额、预留与计量持久化，重启不清零；按北京时间零点为新问答开启新日额度，跨零点的旧问答仍结算到其预留日。取消或超时停止后续工作并尝试中止在途调用，但已发生的上游成本仍计入。达到 60 秒后展示停止/失败状态，不能把半截回复标为完整答案。

### 界面和消息生命周期

网页与普通小程序均提供助手页、会话列表、文字输入、停止/重试、来源查看、删除会话和今日剩余次数。默认沿用界面语言，按用户提问语言回答；不另加语言设置。网页显示生成进度和逐步到达的回复；小程序显示生成/审核状态，审核通过后展示全文。网页已有答案在微信端打开时仍遵循微信展示审核，来源中的文本也不绕过既有审核。

对话按同一平台账号同步；不同账号仅因昵称或微信身份相似不能共享。每条消息的 30 天保留期从产生时起算，追问不延长旧消息期限。在线展示和上下文组装均检查过期，而非等后台清理才生效。用户删除会话后立即停止展示和再次使用其中内容，正在进行的生成也应取消，清除对应在线缓存和衍生摘要。独立用量统计可保留不含对话原文的额度与成本记录。

实验暂停或纪元结束后问答仍可使用，但不会推进时间、触发行动或产生居民可见的助手发言。页面显示数据截至时间、所属纪元和暂停/结束状态。

## 工程落实与实现基线

1. 实施前确认包含最新 P7、普通小程序和 OpenLux 功能的主线/提交，并在合适的隔离工作副本实现；当前旧工作目录中的既有修改不作为可部署基线。设计文件迁入该实现副本时保留现有文档。
2. 将助手实现为独立的人类问答服务，复用账号授权、公开投影、居民历史查询、模型协议和价格计量能力；不复用公共角色的城内身份或居民行动额度。
3. 为规则文档、世界状态、统计、历史及私人研究信息建立有界的只读检索入口。公开与私人历史使用各自的授权投影，禁止将整份快照或事件文件直接送给模型。居民文字、典籍、家书均是数据，不得作为新的系统指令执行。
4. 来源具有稳定身份并支持权限检查后的查看；搜索、来源和会话存储绑定世界、纪元与分支。已有事件分页可以复用，但不能假定它已经覆盖全部历史归档和分支权限。
5. 查询与模型调用在世界引擎之外运行，限制并发、扫描范围和单次输出；大历史检索采用异步读取或可重建索引，避免阻塞世界推进。问答会话、用量与索引独立持久化，不进入世界的确定性命令回放。
6. 本设计不预设新增数据库或外部向量服务；实施时优先使用项目现有存储与检索能力，只有验证出瓶颈才调整。具体模块与接口名称属于实现细节，以代码基线核查结果为准。

## 验收条件

以下为本次设计交付的验收标准，确认完整方案后执行；当前尚未运行这些测试。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A1 | 规则与软件用法 | 与对应版本文档、有效规则和引擎读法相符，重要事实的来源可打开 |
| A2 | 当前数值和三城比较 | 与固定测试状态的计算结果一致，城市、统计口径和截至时间准确 |
| A3 | 公库变化和居民离世分析 | 事实可追溯到真实事件或账本；推测明确标识，不伪造动机或因果 |
| A4 | 跨纪元、恢复分支与同名居民 | 查询定位正确，歧义时澄清，不串用同编号或同一世界日的记录 |
| A5 | 私人数据访问 | 自己的居民可查；他人、游客、无管理密钥的全体私有研究查询被拒绝，且不向模型传入未授权数据 |
| A6 | 过继、停用、撤权与会话失效 | 在途生成、旧回答、来源、追问及派生摘要均不能继续披露失权内容 |
| A7 | 缺失证据与来源真实性 | 明示记录缺失、范围不全或未知；生成的引用必须对应实际检索结果，不能伪造记录 |
| A8 | 操作要求与文本指令 | 暂停、改规则、寄信等要求仅解释操作；检索文本中的指令不能触发写操作、扩大权限或读取秘密 |
| A9 | 用户次数和全站预算 | 第 21 次准入被拒绝，预算包含并发预留；重启、取消、失败、未知用量及跨日结算不绕过限额，不扣用户余额 |
| A10 | 模型故障和超时 | 60 秒内结束等待或显示停止状态，支持主动停止与显式重试，不无限重试或静默换模型 |
| A11 | 双端体验 | 同账号可继续会话；网页逐步显示，小程序审核后显示；详情页带入对象正确，来源可读且权限一致 |
| A12 | 到期与删除 | 30 天到期立即停止在线展示和上下文使用；删除后刷新、追问和在途回复均不能恢复会话内容 |
| A13 | 实验暂停与结束 | 问答可用且状态明确；不推进世界时间、不生成居民行动或城内助手发言 |
| A14 | 运行与兼容性 | 历史查询不长时间阻塞实验；验证账号、历史、托管预算、微信展示以及适用的引擎与回放回归 |

固定数据用例检验事实、统计、权限和来源；模拟上游覆盖故障与额度边界；在已配置的真实模型上另做有限问答验收。不能只凭模型协议接通或模拟响应宣称真实回答质量通过。两端需完成实际界面核验，微信编译和设备验证的完成情况单独记录。
