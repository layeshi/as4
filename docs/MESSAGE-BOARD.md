# 人类用户留言板

从观测站顶部入口、会员页顶部导航或用户中心进入 `/messages.html`。登录后可以阅读和发表留言，回复主留言或某条回复；回复在主留言下平铺，并标明对象。每条内容最多 2,000 个 Unicode 字符，支持换行，按纯文字显示，发布后立即对登录用户可见。

作者可编辑、删除自己的内容，管理员可删除任何内容但不能编辑他人的文字。编辑后显示“已编辑”；删除会清除正文，原位置显示“该留言已删除”，保留作者、时间、讨论关系和其他人的回复。删除主留言不会关闭讨论，已删除内容不能再次编辑。账号通过现有身份验证流程合并后，接收账号继承原账号留言的操作权限，显示接收账号的昵称。

主留言按发布先后从新到旧排序，回复从旧到新排序，编辑和回复不改变主留言排序。每批加载 20 条；回复默认折叠，展开后分批读取。网络错误保留当前草稿，提交期间禁止重复提交；退出或换账号清空页面内容和草稿，迟到的旧账号响应不能重新显示。页面每 60 秒及回到前台时核对登录状态；服务器在每个请求上检查会话，失效立即拒绝访问。

## 接口

全部接口必须使用现有网站账号会话 Cookie。管理员管理密钥、居民令牌及造者密钥不能替代账号会话。写请求须带 `Content-Type: application/json` 和 `X-Houren-Request: 1`，DELETE 的请求体为 `{}`；不开放跨域，响应不可缓存。

| 方法 | 路径 | 请求与行为 |
|---|---|---|
| GET | `/api/messages?cursor=N` | 首次省略游标；按主留言序号降序加载 |
| POST | `/api/messages` | `{text}`，创建主留言，作者由服务器确定 |
| GET | `/api/messages/:id/replies?cursor=N` | `id` 必须是主留言，按回复序号升序加载 |
| POST | `/api/messages/:id/replies` | `{text,replyToId?}`；省略对象时回复主留言，指定对象必须属于同一讨论 |
| PATCH | `/api/messages/:id` | `{text}`，作者编辑未删除的内容 |
| DELETE | `/api/messages/:id` | 作者或管理员删除，重复删除幂等 |

列表响应为 `{messages,total,nextCursor}`；`nextCursor` 为 `null` 表示已到末尾。创建、编辑和删除响应为 `{message}`，创建返回 201，其余成功响应返回 200。每条消息含昵称、正文、时间、回复对象，以及当前请求者的 `canEdit`、`canDelete`；主留言另含 `replyCount`。不返回账号编号、用户名、密码哈希、会话或居民私人资料。删除内容的 `text` 为 `null`。

写操作按账号限制为每分钟最多 30 次尝试，包括编辑和删除。无会话返回 401，越权和跨站请求返回 403，非法内容或游标返回 400，留言不存在返回 404，编辑已删除内容返回 409，频率超限返回 429。

## 保存与备份

`DATA_DIR/message-board.json` 独立于 `DATA_DIR/WORLD_ID/`，文件权限为 `0600`。沿用服务的持久化写入工具，同步文件及目录后发布原子替换；适用于现有单进程服务，不支持多个进程共享写入该文件。数据格式包含版本、递增序号及留言记录；损坏数据导致启动报错，不会静默初始化并覆盖原文件。

留言不进入世界状态、确定性命令日志、居民模型输入或世界快照。重置、回放、恢复和切换世界不改变留言。完整服务备份应同时保存 `accounts.json` 和 `message-board.json`；部署保留现有数据目录。恢复世界快照时仅恢复世界文件，不能覆盖网站留言文件。删除正文从当前文件中清除，历史完整服务备份按原有备份保留策略处理。
