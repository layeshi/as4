# 三城的状态按城挂载

2026-10-16，实现第七前提「三城」时，引擎里一座城的状态原本都直接挂在世界对象上：`w.treasury`、`w.well`、`w.laws`、`w.proposals`、`w.procedure`、`w.weather`、`w.chronicle`、`w.dayLog` 等，读写它们的地方有几百处。我们没有把这几百处逐一改成「带城参数」，而是**按城挂载**：

- 每城一份的字段（清单是 `src/e2/engine/cities.js` 的 `CITY_KEYS`）存在 `w.cities[城]`。
- 世界顶层的同名字段平时放城外（荒野）的语境：没有城法，公库为 null。
- `withCity(w, 城, fn)` 把那座城的字段换到世界顶层，执行完写回并恢复原样，可以嵌套。
- 引擎的入口负责挂对城：
  - 动作按发生地挂；表决按提案所属的城挂；重订与联署按居民的籍城挂；
  - 移动按出发城管离开、目的城管进入，各挂一次；
  - 事件钩子按事件的城挂；死亡与退场按籍城挂；
  - 日结算、天象、编年史逐城挂，荒野另算一份；
  - 入世按港口或摇篮所在的城挂；
  - 感知和公开状态按要显示的城挂。
- 前提 ≤ 6 的世界没有 `w.cities`，`withCity` 直接执行 `fn`，行为和输出逐字节不变。

这样做的代价是几条必须守住的约束：
1. `withCity` 只能包同步代码。里面不能 await，也不能把回调留到以后执行，否则顶层会停在某座城的状态上。
2. 当前挂的城记在不可枚举的隐藏属性 `$city` 和 `$outside` 上，不进快照，也不进回放。
3. 新代码凡是读写一座城的状态，都要先想清楚此刻挂的是哪座城。在城外读顶层，读到的是荒野的语境。要读别城的值用 `cityValue(w, 城, 键)`，不要临时挂城。
4. 法律 ID 每城单独编号。对外一律写成 `north:l3`，裸的 `l3` 只在已经挂了某座城时有意义。

没有选的做法：
- 「每处读写都带城参数」：改动面太大，每一处都可能漏改，也难以保证前提 ≤ 6 逐字节不变。
- 「三个世界对象」：籍、迁籍、跨城移动、共享的典籍与市场都要跨对象同步，确定性回放会很难做。
