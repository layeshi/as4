# 世界计算与访问服务分离，世界命令保持单一有序提交

2026-10-27，用户确认在线服务同时优化核心计算与后台任务，并采用常驻世界计算线程和独立计算池。世界计算线程持有权威世界并顺序准备命令；主线程作为唯一持久化提交协调者，在回执持久化成功后确认提交、更新只读查询镜像并按既有顺序发布事件。独立读计算和导出使用有界资源池，镜像可重建且不能成为另一个世界写者。

三城共享世界、随机流和账本，现有同步挂载与回执语义使三个独立写者不可直接并行；仅将后台任务放入线程池又会留下核心结算阻塞 HTTP 的问题。采用上述分离方式的代价是内部命令接口异步化、额外镜像内存、提交前权限复核以及明确的提交确认与故障恢复协议；收益是世界计算、访问服务与独立后台计算能够同时使用不同 CPU 核心。每个世界的命令顺序仍保留，不承诺单世界速度随核数等比例增加。
