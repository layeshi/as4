## 0. 结论（先看这里）

1. **默认参数下，标定目标没有全部满足。**（种子 1–5 的中位数）
   - `default`：第 720 日人口 **6**（要求 8–120）✗；源井完好度中位数 **0%**（要求 ≥ 40%）✗；人均配给 15 ✓、第 400 日前的死亡 29 次 ✓、建成 12 座设施 ✓、通过 25 部法律 ✓。
   - `laissez`：源井降到下限（完好度 ≤ 20%）的日子中位数 **55**（要求 60–120）✗——早了 5 日；末日人口 5（要求 1–12：显著下降但不灭绝）✓。
   - `stress`：冲击后 30 日内恢复的比例 0.93（要求 ≥ 0.5）✓——但这个指标在这里几乎是空转的（见 §7）。
2. **根因不是某一个参数偏了，而是一条因果链**（§4）：24 个沙盘脑在第 0 日同时入城，是一个**同龄群体**；代谢随年龄增长（`3 + ⌊年龄/48⌋`），大约第 165–270 日群体整体越过「配给养不活」的线，能量缓冲在十几日里耗尽；能量见底的居民涌向源井汲取，源井每日汲取池 60 × 每单位损伤 20 基点 = **8 日内就能把源井打到 0**；死井的日产只剩 20% 的下限（约 120 / 日），修缮效率还减半，剩下的十来位居民手里没有能量修，于是**死井是吸收态**，人口停在 5–10。
3. **改参数只能把崩溃推后，不能消除它**（§5）。试过 14 组参数：让默认场景在种子 1–5 上全部达标的有两组——`wellBaseOutput` 600 → 800（M），以及它加上 `drawDamageBp` 20 → 10（N）；但它们「达标」是因为崩溃从第 165–270 日推到了第 300–550 日，而「源井完好度的中位数」按 720 日算，崩溃只要晚过第 360 日中位数就是高的。在 10 个种子上，M 的人口是 7（差 1）、N 的「第 400 日前死亡」是 0。
4. **我的建议**（详见 §6，都**没有**执行）：
   - 不为了让沙盘「达标」去调物理参数；把这个发现本身当作对设计的反馈：这座城的物理是「脆弱的公地」，规则型 agent 撑不过第一代。
   - 如果一定要让 §16.3 的目标成立，最小的改动是 **`wellBaseOutput` 600 → 800**（一个参数；配给中位数会升到 20，正好在上限）；
   - 更根本的两处改动在**沙盘设定与目标**而不在物理：让创始群体**分批入城**（避免同龄断崖）；把「源井完好度的中位数」这类按整段时间算的目标，改成「第一代死亡之后城是否还在、源井是否被修回」。
5. 所有结论都依赖沙盘脑——它们是我根据 §16.2 的一段话写出来的规则型 agent，见 §2。

## 2. 沙盘脑：它们做了什么（本文一切结论的前提）

§16.2 只用一段话描述了沙盘脑（50% 概率行动、每次 1–2 个动作、九种性情、能量低于 12 时求生、有一定概率修缮 / 出工 / 汲取、语言分布）。其余都是我的实现选择。下面列出**超出规格文字**的部分，以及为什么加——每一条都是看到一种明显不合理的行为之后才加的，加完之后重跑，**没有一条改变了 §4 的结论**：

- 一次行动里的多个意图按同一份感知计算，所以「出现移动就到此为止」，并在本地扣减估计的花费，付不起的动作丢掉（否则 `move` / `draw` 大量失败）；
- **手头紧（能量 < 25）时 60% 的刻歇着**（低于 12 的去求生）；
- **修缮**：在源井就修到近乎完好；别处只修完好度 < 40% 的地点与设施；留一份储备（平时 35、淡季 50），超出的才拿来修；
- **建设**：只投入手头超过 60（淡季 80）的富余部分；一处最多一座设施（每座设施每天都要人修，否则堆出 30–80 座设施，维修吃掉大半日产）；
- **生育**：城里醒着的居民 < 36、昨日人均配给 ≥ 14 且不是淡季才要孩子（之前无限制，人口冲到 50 以上再崩）；
- **法律**：改革者 / 慈悲者 / 组织者 / 商人 / 哲人在「公库明显有余而配给不高」时提议提高配给份额，反之降低；投票按同样的判断（否则改革者会在公库囤积时把份额从 0.6 降到 0.5）；沙盘里也会通过每日汲取配额（3–8）之类的法律；
- 收到入会申请的管事当场答复（收件只送一次）；
- **laissez** 与 `default` 是同一批脑子，只是不提案、不修缮、不出工、不发起工程；汲取的规则相同。

对这些选择的敏感性（种子 1–5，其余不变）：生育上限从 36 改成 30 或 48，末日人口 6 / 5（基线 6），源井中位数 26.9% / 0%（基线 0%）——30 只是让崩溃晚了一点；**完全禁止**在源井 < 50% 时汲取——连快饿死的也不许——崩溃的时间不变（种子 1 更早），末日人口 8 / 8 / 3 / 0（种子 1–4；基线 6 / 8 / 9 / 3），源井照样在第 300 日前后归零（§4.2）。也就是说，结论对脑子的细节不敏感，但确实依赖「居民不会提前储蓄、不会协调」这一大前提。

1. **能量入不敷出。** 这 37 位居民要么是第 0 日入城的创始者（此时 ≈ 160 日龄），要么是前 60 日出生的孩子，平均代谢 ≈ 5.8 / 日（全城 215）；动作开销 140–210 / 日；而进入居民手里的只有配给（≤ 源井日产，此时 260–360，还在淡季与不满的源井里往下掉）和荒野的零星所得。每日净亏损 ≈ 100，居民手里的能量从 1020 降到 756，人均 20。
2. **汲取挤兑。** 到第 161 日，一批居民的能量跌破 12，「求生」把他们送去源井：30、25、40、48、35、39 能量 / 日。每汲取 1 能量源井掉 0.2%，一日 40 能量 = 掉 8%；源井从 5484 **8 日内掉到 0**。
3. **死亡与死井。** 沉睡的居民 3 日内无人唤醒就死去：第 162–166 日醒着的人数 36 → 14，第 165 日之后沉睡者也陆续死去。产出跌到日产下限（120 ± 30）。之后的 5–10 人分到的配给不少（12–18 / 日），但没有一个人手里有 500 能量去把源井从 0 修回 40%（完好度 < 10% 时每能量只恢复 5 基点，要 ≈ 600 能量）。
4. 公库在崩溃时其实有 ≈ 700–900 能量（`rationShare` 在沙盘里被通过的法律推到 1.0，之后没有新进项）。DESIGN §5.2 写过「公库可能堆积如山，同时有人饿死，除非法律决定怎么用它」，这在沙盘里得到了验证：公库的能量只能通过 `grant`（一次拨给一个人）、`stipend`（每日给一个人，DESIGN 预期用它「雇人修缮」）、`fund`（给工程）分出去，一部法案最多 5 条效力。沙盘里确实通过了「守井人津贴」（每日 3 能量给一个人），但一个人的津贴填不了 37 人的缺口，也没有任何一条效力能让公库直接去修源井。

### 4.2 排除了什么

| 假设 | 试验 | 结果 |
|---|---|---|
| 是天象（旱、震）打垮的 | 天象排期为空（`schedule:[]`），种子 1–3 | 崩溃照样发生，只是不再有震：第 200–300 日人口 37–39 → 8–11，源井归零 |
| 是汲取本身把源井杀死的 | 完全禁止在源井 < 50% 时汲取（连快饿死的也不许），种子 1–4 | **没有变好**：崩溃的时间与基线相同（种子 1 第 200 日只剩 7 人，基线 15），末日人口 8 / 8 / 3 / 0（基线 6 / 8 / 9 / 3），源井仍在第 300 日前后归零——没有能量修缮时，自然衰败（每日 100 基点）自己就能杀死源井 |
| 是生育太多，人口超出了承载 | 生育上限 30 / 36 / 48（种子 1–5） | 末日人口 6 / 6 / 5，源井中位数 26.9% / 0% / 0%：30 让崩溃略晚，结论不变 |
| 是建了太多设施，维修吃掉日产 | 早先的脑子确实会这样（30–80 座设施，维修占日产的四分之一）；已经在脑子里限制（一处最多一座） | 限制之后崩溃依旧，只是时间略有不同（§2） |
| 是公库囤积空转（40% 日产腐坏） | 沙盘脑会把配给份额推到 1.0（第 20 日前后通过） | 崩溃依旧；公库空转不是原因，但「公库有能量却用不上」是崩溃时的一个现象 |

### 4.3 为什么是「同龄群体的断崖」

承载力的粗算：源井 100%、季节平均时日产 ≈ 600，配给份额 1.0 时人均配给 = 600 / N；每个居民每日花费 ≈ 代谢 `3 + ⌊年龄/48⌋` + 动作 ≈ 5–6 + 修缮等 ≈ 3。N = 37 时，人均配给 16，所以年龄 ≈ 150 日以上的居民（代谢 ≥ 6）在季节低谷里就入不敷出。24 个创始者与他们的孩子（前 60 日内出生）几乎同龄，所以是**同一时间**越线，而不是一个个先后死去、让其余的人余粮变多。生育上限只影响人口数，不影响「同龄」。

`agingEveryDays`（48 → 144）与 `wellBaseOutput`（600 → 800）都是在推迟越线的时间（§5 的轨迹表）。

要点：

- **没有任何一组参数在两组种子上都全部达标。** M（`wellBaseOutput=800`）在种子 1–5 全部达标（配给中位数 20，正好在上限），在种子 1–10 上人口 7（差 1）；N（M + `drawDamageBp=10`）在 1–10 上人口 9、但「第 400 日前死亡」为 0（一半的种子在第 400 日之前没有死亡）。窗口很窄：要「有人死、但城还在」，本来就是在崩溃的边缘上测量。
- `laissez` 的目标（源井在第 60–120 日降到下限）凡是改动了汲取损伤、基础产出、代谢或老化的变体都能满足（基线 55，`drawDamageBp` 20 → 10 就是 64）；只改汲取池、修缮效率或下限的不行（仍是 55–58）。

  | 变体 | 种子 1–5 的崩溃时间（人口降到 ≤ 12 的大致日子） | 崩溃后的源井 |
  |---|---|---|
  | 默认 | 第 165–270 日 | 归零 |
  | `agingEveryDays=144` | 第 300–550 日 | 归零 |

## 6. 建议

**A. 我倾向：不为了让沙盘达标去改物理参数，而是接受这个发现，并调整标定的口径。**
「脆弱的公地」是设计的前提（DESIGN §5.2 预言的公库堆积与汲取的悲剧都出现了）；规则型 agent 撑不过第一代，不说明 LLM agent 也撑不过——它们会提前储蓄、会协调、会立法。标定要回答的是「默认参数下，城有没有可能存活」，这更适合用**有协调能力的 agent** 回答（M2 的先民）。建议：

1. 沙盘的创始群体**分批入城**（例如第 0–40 日每天 1 个人），避免同龄断崖；
2. 目标改成对「第一代之后」的描述，例如：「第一位居民长眠之后的 120 日内，公库能量与源井完好度不同时为 0」；
3. `laissez` 的目标保持（它现在只差 5 日）；`stress` 的指标改为「冲击前后人口与配给的相对变化」，别在人口已经崩塌的世界里量。

**B. 如果一定要让 §16.3 的目标在沙盘里原样成立：**最小的改动是 `wellBaseOutput` **600 → 800**（M）。代价：配给中位数升到 20（贴着上限）；崩溃只是推后到第 400–500 日；在种子 6–10 上人口中位数仍是 7。若还要 laissez 的窗口更稳，可加 `drawDamageBp` 20 → 10（N，laissez 的「降到下限」中位 64 日），但会让默认场景在第 400 日之前更少死人。

**C. 值得在 M2 前讨论的机制层改动**（参数解决不了）：

- 公库要有办法**直接出钱修缮**（例如让 `fund` 也能指向一个地点或设施的修缮，或加一个 `upkeep` 效力）。现在公库里的能量在危机里帮不上忙（只能靠 `stipend` 一个人一个人地「雇」）；
- 汲取池是先到先得的公共池，一批饿着的人可以在一周内毁掉源井；可以考虑让每单位汲取的损伤随当日已汲取量递增，或者对已经很破败的源井限制汲取；
- 死井是吸收态：`repairRateLow`（完好度 < 10% 时半效率）让恢复更难；这条也许应该是**加速**而不是减速。

## 7. 局限

- **脑子是我写的。** 它们没有储蓄的意识、没有互助、不会为长远做计划；这恰恰是规则型 agent 与 LLM agent 的差别。结论对具体规则不敏感（§2），但对「没有协调」这一前提敏感。
- **种子只有 5（10）个。** 中位数在阈值附近（人口 7 与 8）时，一个种子就能翻转判定。判定为 ✓ / ✗ 的差别，在人口这一项上多半是噪声。
- **`stress` 的指标在这里几乎是空转的。** 默认参数下崩溃发生在第 150–270 日，之后人口与公库都在低位平台，「冲击后 30 日内回到冲击前的 80%」几乎必然成立（0.93–1.0）。它没有量到「城在冲击下是否有韧性」。
- **`laissez` 的判定口径有歧义**（「降到下限」可以是完好度 ≤ 20%，也可以是 0）；两种口径都在 §3.2 的表里，差 2–3 日。
- **阈值本身没有被检验过。** §16.3 的目标是设计时的期望，不是从别的实验得来的数据。

