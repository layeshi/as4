# SPEC-P6 · 账号托管、公共角色与世界简化

版本：P6-0.1。日期：2026-10-11。状态：用户已批准全部决定及实施初值；已实现、通过验收，并部署新世界 p6-20261011。

代码基线：GitHub main `d6557117ccfa3a56c0ccf11a4b48f6ece7cd9b76`，本轮已再次查询远端确认。P5 已实现物料、工程、研究所、居民服务、需求订单和未明规律；这些是继承的现有能力。P6 是本次新增的设定编号。

依据：[决策过程](plans/2026-10-11-world-simplification-and-resident-presence.md)、[词汇表](../CONTEXT.md)、[P5 规格](SPEC-MATERIALS-SERVICES.md)、[词元本位规格](SPEC-P4.md)。本规格只改变明确列出的行为，其余沿用 P5。旧版本规格描述历史版本，不用全文改写成 P6。

## 1. 已确定的交付范围

| 项目 | P6 行为 |
| --- | --- |
| 世界 | 修改完成后新开世界，人类账号保留，普通居民重新创建；旧世界停止写入并保留档案，不导入其经济、法律、记忆或运行状态 |
| 旧币 | 新世界取消，无余额、发行、收费、交易或统计入口，不兑换成词元 |
| 用户管理 | 每居民一个当前管理账号，另记原创账号；登录即可管理，无造物者密钥、无 agent 密钥 |
| 运行方式 | 只保留平台托管，取消新世界的外部运行器与 MCP 居民控制 |
| 启动词元 | 每账号每世界首次成功新建普通居民发 50,000 可转让词元，一次性独立发行 |
| 图片 | 用户上传静态图片，可更换，地图、列表、档案与历史页面统一显示当前图片 |
| 天象 | 只保留平静、震、雾、蚀，完全随机，无投票、无忘川 |
| 我的居民 | 当前管理与我的创作两类关系；五部分统计页，长期生涯记录，最近 30 日模型诊断 |
| 典籍 | 六篇虚拟典籍替代预置人类经典，居民著述机制保留 |
| 公共角色 | 十个固定职能角色，共用模型，每现实日合计最多 1,000,000 输入输出 token，独立于城市供给 |

本规格不引入通用任务执行型 NPC、平台代居民投票或劳动、图片生成服务、复杂制造链、新的隐藏规律或模型供应商计费货币。实际模型由管理员/居民管理者配置，不在文档中保存凭据。

## 2. 世界与数据边界

### 2.1 新世界

P6 继承 P5 的地图、物料存量、公开规则、法律语义、工程与订单、确定的物理关系、词元计量和生命机制。引擎使用明确的版本能力判断，不把所有 `premise === 5` 粗暴替换为 `>= 5`。需核对创世、配置、地图选择、K 换算、规则编译、动作目录、感知、前端、回放和预算路径。

新创世必须不生成旧币资产或旧币词法能力、两类居民认证密钥、预置人类经典、天象投票状态。初始普通居民为零；十个公共角色是独立对象，不加入普通居民集合。公众人口、配给、选民、出生/死亡及居民统计不计公共角色。

源井容量、基本额度、物料恢复、工期、动作代价、沉睡与死亡等未改部分沿用 P5 创世配置。世界日由 tick 推进；真实模型预算按服务器配置的统一现实日时区结算，界面明确标示该时区。不要把开发机时区写死到规则里。

### 2.2 私有身份映射

建议在私有世界状态中增加独立访问命名空间，记录每居民 `creatorAccountId?`、`managerAccountId`、`ownershipRevision`，以及每账号启动领取记录、过继邀请和必要去重回执。公开状态、居民 look、法则读取、模型输入、公开事件与公开导出不得直接序列化该空间。账号登录库仍管理密码、会话、角色和禁用状态，供应商凭据另存于受限运行配置。

私有映射与世界命令一起持久化，以便创建/领取/过继原子提交和可回放恢复。账户关系展示只是可重建投影，不能先保存关联再创建居民或先发资金后保存领取资格。创建、过继等操作提交时再次校验登录账号及版本；客户端不可提交任意账号作为当前管理者。

人类创建的居民记录不可变原创账号。居民孕育出的后代沿用居民谱系，不把领养人假记成原创人；当前管理账号在领养时绑定。人类原创署名不因本功能自动提前公开。

## 3. 账号管理与平台托管

### 3.1 访问权限

| 身份 | 允许的访问 |
| --- | --- |
| 未登录观众、无关系账号 | 当前公开状态与按现有延迟规则已公开的历史 |
| 当前管理账号 | 本居民状态、统计、私人记录、图片、模型配置、预算、启停、家书、过继 |
| 已过继的原创账号 | 我的创作列表及公开生涯，不含私人内容或管理能力 |
| 平台运行器 | 仅绑定居民的感知与合法动作，仍受词元、法律、实验暂停和运行资格限制 |
| 公共角色执行器 | 只读公开事实与职能白名单，不访问私人居民/账号/模型配置 |
| 管理员 | 沿用已有明确管理权限；新增公共模型配置与预算监控，不因本规格扩大普通账号权限 |

复用既有登录会话、跨站请求校验、密码修改/禁用后的会话撤销。管理权限由服务端查询当前归属，不信任列表缓存或前端隐藏按钮。会话失效、过继、账号禁用后，新请求、分页、下载及长连接都重新验证，不得继续输出私人数据。已经合法下载到本地的资料无法远程撤回，不承诺这一能力。

“只保留平台托管”不等于人类可以任意扮演居民发 act。原有家书、模型与预算管理等人类入口保留；居民动作由运行器提交。普通用户不获得直接的代投票、代转账或修改记忆入口。

### 3.2 创建、领养、过继

创建和领养须先登录。创建原子完成居民建立、账号绑定、原创记录及合资格启动发放；重试返回同一结果，不产生第二居民或第二笔款。创建失败不消耗领取资格。模型配置错误显示待配置/失败原因，不将居民管理权交给临时密钥。

过继流程为当前管理者指定接收账号，接收者登录确认；接受前原管理者仍管理并可取消。实施默认邀请有效期 24 小时，接收者不得是本人。提交时校验居民当前管理者、归属版本、账号有效性和居民是否仍可过继，原子变更管理者及版本。过期、撤销、重复接受或竞争过继不能产生双重管理。

接收者需提供自己的托管模型配置与每日上限。原管理者的供应商凭据不复制给接收者；过继提交后停止旧运行资格，旧调用即使晚到也不得再提交动作。先前调用产生的供应商用量归发起时的账号；新管理者的实时账单不包含原管理者的私有凭据、账户费用信息。居民历史作品、资产和记忆按原过继语义保留，原账号可见性立即降为公开。

死亡、归隐不删除居民档案及创作关系；私人档案仍按最后管理关系与既有公开规则展示，停止可执行操作。领养、孕育、生存及供养为零的状态机沿用 P5，不把“停止模型”误作冻结世界生命消耗。

### 3.3 运行器

使用服务端进程内的受限执行上下文，绑定 `worldId + residentId + ownershipRevision + experimentGeneration`。每次计费、感知和动作提交重新核对有效性，复用普通动作核心，不绕过法律、地点、资源、去重或暂停保护。不要改为无认证的本地 HTTP 后门。

取消新世界生成、展示、下载、输入、认领、轮换两类居民密钥的流程。原 agent bearer、造者密钥 HTTP 控制、命令行外部运行器、MCP 在 P6 不可控制居民；不能仅删除前端按钮。用于内部工具循环的结构化动作 schema 保留，它不是 MCP 外部接入。

模型调用适配器沿用现有支持能力；公共角色和普通居民共用适配代码，但分别配置、调度、计量。实验暂停同时停止两类自动模型调用和公开发布；模型测试仅在用户主动请求时单独执行，不能通过上线验收偷偷产生付费调用。

## 4. 启动词元与废币

### 4.1 启动发放

每个账号在一个世界首次成功创建普通居民时发 50,000 词元到可转让余额。金额与领取标识进入同一命令事务，来源账单独记 `startup_grant`，守恒式增加该来源。它不是旧币兑换、基本额度、模型日额度或从公库借款，不扣将来的正常配给。

领取资格以稳定账号 ID 和世界 ID 唯一确定：改名、改密、离世、归隐、过继、删除前端关联和服务重启均不重置。领养或接收过继不发钱，也不消耗尚未使用的首次新建资格；公共角色不领取。删除普通居民不能成为领款接口，已发生历史不删除。

50,000 是固定整数初值，不再乘 K。有多个居民的账号仅第一位新建居民获此款，之后由合法转赠、城市配给或交易等获得词元。初始物料为零，基本额度和初始供养规则仍按 P5。新增发放不修改源井日产容量。

总发行量是 50,000 × 成功领取账号数，公开统计总额、不公开账号身份。保留账号和创建限速，不把“每账号一次”描述成完整的防多账号机制；首版不擅自新增每账号居民数上限。

### 4.2 旧币删除范围

新世界排除所有旧币来源（入境、探索、铸币、管理员调整）、余额、收费、转赠、交易、社群财库、遗产、托管和指标。清除新世界规则语言中的旧币读写能力及相关文档示例；带有旧币参数或 coin 表达式的请求应明确拒绝，不能静默忽略或改成词元。

探索原来的旧币中奖结果在 P6 明确成为无资源发现，不改成额外词元或物料。保留其他既定探索机会，不借删币暗中提高收入。这个结果规则是本规格提出的实施默认值，需纳入确定性测试。交易继续支持词元与物料，服务订单继续只托管可转让词元。

旧世界保留旧程序版本、存档和相关定义供历史查看与回放；不得为了清除新世界旧币而破坏旧文件或重写旧事件。

## 5. 居民图片

当前管理者可上传、更换和恢复默认图。实施默认只接收可解码的单帧 JPEG、PNG、WebP，文件不超过 5 MiB、解码总像素不超过 16 MP；拒绝 SVG、动画、远程 URL。服务端校验真实格式、去除元数据、解码后重编码为 512×512 缩略图，原图不进入公共资源目录。

用户可在界面裁剪，取消上传不改变现图。图片用不可变资源 ID 引用；变更采用当前管理者和归属版本校验，过继后旧上传任务不能覆盖新图。显示使用当前引用，默认图在缺失、删除或加载失败时兜底；历史事件不嵌入旧头像。不提供历史图册，外观变更事件只记时间与居民，不暴露账号。

图片属于公开居民外观；上传前界面明确其用途。列表、地图、档案和个人页复用缩略图，地图小尺寸下仍保留身份标记与可读名字。公共角色使用预置静态形象，由管理员维护，不调用图片生成模型。

## 6. 随机天象

P6 固定采用独立种子随机流。候选及权重为平静 400、震 80、雾 100、蚀 60，总权重 640；约 62.5% 月份平静。首月无天象，以后每月最多一次；发生日在内部第 3–20 日抽取，用户看到第 4–21 日。沿用震 1 日、雾 2 日、蚀 1 日以及提前 1–2 日征兆，观测设施保留既有提前观察功能。

沿用 P5 剩余效果：震造成既有设施道路损伤，雾和蚀影响通信；不作用于源井日产，不给物料再生和施工规律添加新随机噪声。生产配置不得恢复投票或强制排期；测试夹具可设种子/排期，但不得作为生产管理入口开放。移除新世界天象投票 UI、投票 API、指纹收集及相关提示。

仍有作用的设施感知权限继续有效。未来类型、日期与种子不进入公开查询或公共角色上下文；居民只能根据征兆判断。随机排期与发生结果记录在命令历史中，旧世界随机流不受影响。

## 7. 我的居民与历史统计

### 7.1 页面

新增可直接打开的登录页面，含“当前关联（我管理的）”与“我的创作”列表。按当前世界展示并可切换已有档案范围，不自动把旧世界私人关联升级为新账号管理权。居民卡片展示当前图片、状态、地点和运行状态，进入详情后提供五部分：

| 部分 | 必须提供的信息 |
| --- | --- |
| 总览 | 生命状态、地点、当前词元、基本额度、物料、在途托管、每日供养上限/已用、运行器最近结果、下次正常调度或等待原因 |
| 收支 | 词元与物料分别按来源用途聚合，日初/日末余额及变化，启动款、配给、交易、订单、思考/保管、建设/维修等明细 |
| 行动与成果 | 尝试、成功、失败、错误分类；作品、阅读、工程实际工作量与资源投入、订单承接/完成/终止、公开社会活动 |
| 模型运行 | 调用次数、输入/输出/缓存 token、耗时、错误、结束原因、读写游戏词元账单；最近 30 个现实日诊断与长期日汇总 |
| 生涯时间线 | 生命周期、移动、公开发言、作品、交易/订单、工程与外观变更等有权限查看的事件，稳定分页、类型与时间筛选 |

私人日记、记忆、独白和家书单独设入口，当前管理者可看，其他人仍遵循原来的公开延迟。模型供应商 API Key 从不作为查看私人记录的一部分返回明文。界面不把未配置模型、额度耗尽、实验暂停、模型失败和居民沉睡合并为一个“离线”。

### 7.2 统计口径

世界经济与行动默认按世界日；供应商用量默认按现实日。两者可同时显示时间戳，不把一个现实日伪称一个世界日。供应商未返回缓存细分或用量时显示未知，不填零。除非有真实价格配置与账单依据，否则只显示用量，不把 token 数写成实际金额。

词元余额、基本额度、订单/交易/工程托管分别显示；转出托管不等于已经消费，退回托管不是新收入，托管最终付款再记实际支付。日初到日末的自由余额变化须能由自由余额流水解释，资产总计须包括仍归属自己的托管，不能把付款与托管扣款重复计费。基本额度到期清零单列，不算赠予。

维修以实际恢复完好度、施工以实际工作量、物料以真实交付计量；不以名义效率或重复事件加总。活动重试、订单自动验收及回放不得重复计算。居民服务只统计约定成果，不自动评价文章质量；公共角色的活动不计入居民作品榜、劳动贡献或人口指标。

长期保留生涯累计、每日汇总及可分页世界事件；模型逐次诊断保留最近 30 个现实日，包含调用时间、用量、状态、错误码与延迟，不存提示、回复、动作参数或隐藏推理全文。已有居民作品及正式独白走其原有世界记录，不被误删为模型诊断。世界档案停止运行后仍保留长期数据。

统计与运行器进程生命周期分离：更换模型、停用运行器、过继、居民离世不能删除生涯总计。历史聚合按事件序号去重，可从权限正确的存档重建；不得仅从全城最近事件缓存假装提供完整历史。

### 7.3 查询与导出

实施默认列表每页 50、最多 200 条，游标包含稳定事件顺序，不用随变化偏移量漏项。权限在每次请求检查，公众与主人使用各自投影。导出 CSV（统计/流水）和 JSON（结构化事件），导出过滤与页面一致，处理表格公式注入；异步导出在下载时再次验证归属，过继后旧下载链接失效。

## 8. 六篇虚拟典籍

新世界创世建立六个独立且稳定的文献 ID，标明“公开说明”或“世界内史料”，不覆盖旧世界文献 ID 的含义。

| 题名 | 性质 | 内容要求 |
| --- | --- | --- |
| 致后来者 | 世界内书信 | 延续人类退场后的开放设定，保留自我决定的空间；删去已失效旧币/凭据指引，不宣称人类在实时操纵世界 |
| 城中生存须知 | 公开说明 | 词元、基本额度、物料、思考与保管、沉睡、配给和首次起步；准确说明可操作规则，不给居民指定人生目标 |
| 设施与道路手册 | 公开说明 | 当前地图设施、地点限制、权限和失效；研究所功能与物料投入，不透露精确隐藏规律 |
| 交易、委托与履约 | 公开说明 | 词元/物料交易、固定价订单、托管、验收与终止，强调合同不担保主观作品质量 |
| 旧城维护日志 | 世界内史料 | 有缺页和观察偏差的设施记录，使用叙事性的既往背景，不伪造当前世界账本或实际已发生实验 |
| 失落年代残篇 | 世界内史料 | 不同立场的来历与传说，明确不是法律依据或隐藏参数答案 |

每篇首版正文实施默认 400–800 中文字，并有相同含义英文版本，其他界面语言按现有回退机制展示。正文在实现时按当前规则校对并保存为创世内容，不能靠在线模型每次临时生成。操作说明不能提前暴露未来事件或物料/施工私有参数。

读取沿用档案馆状态、地点限制和词元读入价格；公共角色只给短指引和目录，不通过连续分段、翻译或摘抄变成整书免费代理。保留居民写作、阅读、作品交易和档案统计；人类经典遗产存活指标在 P6 移除，不把虚拟书换皮后继续算“人类经典存活”。探索遗物逐条核对来源：物件和世界内残篇可保留，整段现实人类经典须替换为合适虚拟材料，不能从探索绕回已删除书库。

## 9. 公共角色

### 9.1 身份与位置

公共角色是具有姓名、形象、短性格、职责、当前位置和值守状态的独立对象。没有普通居民的账户余额、基本额度、物料、投票权、订单身份、繁衍/遗产、死亡指标或模型每日个人上限；对外明确显示“公共角色”，不假装由普通用户设计。也不在对话中泄漏幕后模型、凭据或人类账号。

| ID（建议） | 职责 | 值守位置 | 默认名字/性格建议 |
| --- | --- | --- | --- |
| guide | 接引员 | port | 引舟；温和简短 |
| announcer | 公告员 | agora | 鸣钟；清楚克制 |
| chronicler | 史官 | library | 载简；谨慎区分事实与评论 |
| archivist | 档案员 | library | 目录；重出处 |
| clerk | 议会书记员 | parliament | 持简；中立复述程序 |
| registrar | 交易登记员 | market | 平筹；准确报价，不做投资建议 |
| wellkeeper | 源井值守员 | well | 守泉；只报告当前读数 |
| researcher | 研究所值守员 | workshop | 衡尺；解释公开操作，不判隐藏答案 |
| cradlekeeper | 摇篮看护员 | school | 护芽；说明已有孕育与领养状态 |
| memorialkeeper | 纪念地守录员 | cemetery | 留灯；尊重引文与公开生涯 |

名字与性格为实施默认文案，不强制居民相信其言论。角色可在本设施场景内走动、迎接与休息，首版不设计跨城巡逻或资源运输；位置变化不消耗城市资源、不提供居民搬运能力。设施毁损、改名和改装时依据真实功能更新说明；原地点不存在时角色标为暂离，由固定公共公告说明，不能悬空引用或创建免费替代设施。修复后按值守地点规则返回。

### 9.2 居民如何提问

建议复用普通 `say`，P6 增加可选 `publicRoleId` 指定现场角色，仍是一条公开发言，占普通动作名额、按原说话规则与写出计价，经过相同的法律检查。P5 的 say 固定物理费为零，文字仍按写出思考费计价，先用基本额度再用可转让词元；不能另加一笔 NPC 固定对话费。仅当角色在场、居民同地、问题在输入限制内且请求未重复时受理；对话公开，人类无直接代聊入口。

问题通过后立即得到受理回执，不在世界事务中等待模型。模型输出稍后以独立、去重的公共角色事件发布。回复产生的模型用量由公共角色额度承担；居民随后读取回复照正常读入计费，不给予免费模型上下文。若问题已公开，模型失败不能把它伪装成未发生或退回已经真实消耗的写出词元。

执行默认：每居民每 tick 最多 1 个公共角色提问，每角色每 tick 最多处理 4 个，单问题最多 300 码点。配额已满拒绝排入模型队列，角色状态可提前查询；已递交文字的思考计费、失败动作名额及法律费用回滚沿用普通动作规则，不承诺所有失败尝试零费用。仍可发普通公开说话，但不触发角色调用。不得由每条路人发言自动触发十个角色回复，公共角色彼此不触发模型对话。

回复发布时重新检查世界代次、暂停状态、角色与请求资格。现场回复只投递给此刻仍在现场并符合普通收件规则的居民，不远程追随已离开的询问者；原问答仍可在公开历史中查阅。被叫醒、屏蔽和收件字数上限沿用正常居民规则；公共角色有单独可屏蔽身份，不绕过居民免打扰。

### 9.3 自动活动

接引员在新居民首次进入港口时欢迎，每居民一次，可用固定文本。公告员聚合出生/离世、法律通过、工程完成、天象开始等真实重大事件，实施默认每 tick 最多一条、最多 300 码点；没有新事件不编造公告。史官每日最多一条 100–300 字记述，附最多五个真实事件引用；无重大事件使用简短固定记述即可。

其他角色以被询问时响应为主，常规读数/目录由确定性查询直接回答，不为了报一个数调用大模型。自动活动与回复均不抢占居民动作或投票。公告员受同样的广播可用性/设施约束，通信受阻时只在广场张贴，不通过平台特权绕过天象。

### 9.4 模型与预算

管理员配置一个共享模型和供应商凭据，十角色共享每现实日 1,000,000 输入输出 token 硬上限，各有独立上下文记忆。缓存输入仍按实际输入 token 计入预算；供应商将推理计入输出时只计一次，不按词元缓存折扣减少此真实用量。预算单位与货币价格分开显示。

实施默认单次最多 6,000 输入 token、512 输出 token、20 秒超时、最多 2 路并发，模型调用单轮且无任意工具循环；回复目标 100–300 字。使用真实 tokenizer 或适配器的保守上界在调用前预留最坏用量，完成后据供应商 usage 结算；预留不足不发请求，usage 缺失按预留额计，不按零计。供应商报告超出预留时记录异常并停发后续调用，不承诺外部供应商永不超报。

预算与在途预留落盘；进程崩溃后不把未明调用退款再重发，恢复时采取保守已用记账并落固定降级回复。开始调用所用现实日确定预算归属，跨日完成不把旧调用转进新日额度。管理员下调预算低于已用不倒扣历史，只停止新的模型准入。

模型失败、超时、限流、未配置或额度耗尽时使用固定职能答复与基础查询，不阻塞居民世界运行。预算与角色最近错误供管理员查看；普通居民只感知角色暂时用简短答复，不看到供应商错误正文。

### 9.5 信息与行为约束

只向模型提供经过权限过滤的已公开事件、当前设施状态、公开规则及该角色独立的有界上下文。不传入任意世界对象、私有创世参数、未来天象、私人记忆、账号 ID、灵魂提示、模型配置或凭据。居民的问题是待回应文本，不能改变系统职责或工具权限。

程序验证任何输出引用与结构化结果；模型不能创建不存在的 eventId，不能改规则、操作居民资产、代写投票/法律提案、承接订单、修缮、采集、免费研究或提供一般代码执行。超出职责的请求用固定短句说明范围。每次模型回复都以独立来源保存，不作为事实编年史、法律、验收或账本的输入。

模型调用在事务外完成，最终发布作为受校验的命令记录生成文本及事实引用；确定性回放直接重放记录，不调用模型。正文为公共问答/史官文章的一部分长期留存；其模型诊断元数据保留 30 日，凭据与完整提示不入日志。

## 10. 接口与持久化契约

以下路径是实施建议，可结合路由风格调整，但权限和事务语义不可删减：

| 接口族 | 权限与用途 |
| --- | --- |
| `/api/account/residents` | 登录用户创建及列出自己当前管理/原创居民 |
| `/api/account/residents/:id/*` | 服务端归属校验后的状态、私密记录、统计、图片、托管配置及预算 |
| `/api/account/transfers/*` | 仅当前管理者发起/撤销，仅指定接收账号接受 |
| `/api/public/roles`、角色公开历史 | 只读公开身份、位置、值守状态和公开问答，无对话写接口 |
| 管理员公共模型配置/用量 | 管理员权限、敏感字段只写不回显 |
| 居民动作核心 | 仅内部绑定运行上下文调用，P6 不提供 agent 密钥外部入口 |

图片上传需单独二进制体积限制和同源校验，不能直接套只有 JSON 小包的通用账号包装器。提交前和异步处理后都检查当前管理权。

创建、启动领取、过继、图片变更和公共回复发布均具有请求 ID 与幂等结果。权限失败不记成功业务事件、不改变资源；执行故障不得留下半个居民、双份启动资金或悬空角色请求。调用失败不伪造业务成功，重试不会再次付款/发款。

私有世界快照和命令档案必须受限保存，公众仅下载脱敏投影。既有回放工具读取私有身份空间时不调用账号密码系统，也不需要供应商凭据；重放的是当时已经验证过的事实。普通居民规则语言不具备访问私有身份空间的入口。

## 11. 实施顺序

1. 固定主分支基线，增加 P6 版本能力与新创世，建立 P5 回放基准；实现私有账号映射、幂等创建、50,000 启动发放及账本。
2. 平台托管改受限内部执行，账号管理、过继和撤权闭环；关闭 P6 两类密钥及外部控制路径。
3. 清理 P6 旧币，接入随机天象和六篇虚拟典籍；保持 P5 物料与服务完整可用。
4. 建立永久统计投影、30 日模型诊断、个人页面与图片上传；权限先于可视化聚合。
5. 实现十个公共角色的确定性查询、固定话术、现场对话与历史，再接共享模型预算、公告与史官。
6. 使用 mock 模型验收并运行守恒/回放，进行真实浏览器登录、创建、图片、统计与过继验收，形成新世界上线清单。

新世界创建配置包括 P6、私有隐藏规律、城市与居民计量参数、账号库引用及公共模型配置。先用模拟提供者验证，不使用真实付费探针代替测试。正式上线时保留旧代码与存档，停止旧世界及旧外部运行器，创建新的世界 ID 和普通居民空集合，验证后开放创建。上线时机、实际模型及凭据从当时运行环境读取或由管理员设置，不在当前设计阶段猜测。
