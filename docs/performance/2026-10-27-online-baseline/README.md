# 在线 Runtime 设计诊断基线

日期：2026-10-27。源码：`609fd27245b1e95e4a9957a685c04827e5f4bebf`。

`runtime.mjs` 创建临时 P7 世界和 12 位合成居民，分别添加 0、5000、20000 条合成旧账本记录，运行真实 `Runtime.exec`、命令回执持久化及 `HistoryArchive`。不读取生产数据，不开启 HTTP、不连接模型，结束后删除临时世界。

每组运行 14 个 tick，排除最初 2 个样本；普通 tick 中位数来自 11 个样本，日结算只有 1 个样本。它用于判断随历史规模增长的开销，不能证明生产容量、请求 P95、多核加速比或不同 Node 版本的性能差异。

复现命令（替换代码目录与结果路径；代码目录须包含所记录基线的模块和测试夹具）：

```sh
node docs/performance/2026-10-27-online-baseline/runtime.mjs \
  /absolute/path/to/checkout \
  /absolute/path/to/result.json
```

两次本地运行均使用 macOS、12 个可用逻辑 CPU。保留 Node v22.14.0 的初始调查结果与 Node v24.16.0 的复核结果。它们不是控制变量充分的版本比较。

Node v24.16.0 的普通 tick 中位数如下，单位为毫秒：

| 合成旧记录 | 初始世界 JSON 字节 | tick 总耗时 | 候选准备 | 回执生成 | 回执持久化 | 状态提交 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 208283 | 10.596 | 0.982 | 4.312 | 4.091 | 1.347 |
| 5000 | 1078283 | 43.531 | 6.335 | 21.695 | 4.597 | 9.717 |
| 20000 | 3688283 | 153.945 | 23.976 | 84.135 | 4.545 | 39.561 |

各阶段单独取中位数，不能要求其和严格等于总耗时中位数。`receipt` 与 `commit` 由相邻函数边界计时推导，属于诊断近似；历史归档 flush 另外计时，未包含于 tick 总耗时。`rssBytes` 是采样时进程 RSS，不是独立任务的峰值内存。

两次运行的全部组别均通过“候选状态与应用其回执后的状态哈希相同”检查。没有修改产品代码；尚未验证完整命令日志恢复、HTTP 并发、长期稳定性、Windows 或 Linux 的实际运行性能。
