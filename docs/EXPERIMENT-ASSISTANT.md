# 实验助手

面向登录人类用户的只读问答功能，覆盖当前实验世界的三城、现有规则和已接入的历史归档。网页入口为 `/assistant.html`，普通小程序入口为“我的 → 实验助手”。居民和法律详情提供带入对象的入口。

## 使用与配置

管理员在管理后台的“实验助手”中选择已发布且已验证的 OpenLux 模型、设置每账号每日次数和全站每日成本预算。复用平台现有 OpenLux 接入凭据，但问答成本单独记录，不扣用户余额，也不消耗居民行动的词元额度。首次使用前须已配置和发布 OpenLux 模型目录；未配置时显示“助手暂不可用”，已有对话仍可查看。

默认模型 `gpt-6-luna`，每账号每天 20 次、全站每天 20 元人民币模型成本，按北京时间零点重置；单次从提交到模型生成及新微信答案审核合计最多 60 秒。管理员同样受提问次数限制。一次已接纳并开始处理的问题计一次，失败、主动停止和审核失败仍计次；格式、权限、对象、容量和额度准入拒绝不计次；用户重试算新问题。

每账号同时生成一个答案，全站最多两个。单个问题最多 4000 字，每段对话最多 200 条消息，每账号最多 100 段对话；达到会话限制时可删除旧对话或新建对话。管理员可将次数或成本预算设为 0 暂停新问答。

## 回答和证据

重要事实使用 `[S1]` 等依据标号；网页把它们排成可点的依据角标，点开可查看所用记录、观测时间、世界和历史分支。服务端计算统计，模型负责解释；未命中记录不等于事情从未发生。短语“今天”“昨天”“最近 N 天”、明确世界日以及单个城市名可以自动限定范围，界面也可显式选择范围。多分支旧纪元有歧义时要求选择分支。

公共查询使用引擎公开投影；私人查询须明确选择范围。P6/P7 按当前账号居民管理权授权，旧世界使用对应居民的造者凭证；管理员私人研究另需有效管理密钥。历史分支独立核验权属，旧世界缺少可核实的凭证记录时不猜测授权。

私人记录不指定居民时，指提问者此刻能验证管理权的全部居民（[ADR 0027](adr/0027-assistant-private-scope-covers-all-managed-residents.md)）：P6/P7 是账号管理中的全部居民，旧世界是造者密钥认出的那一位；一个也没有时在预留和计次之前拒绝，不计次。名单在提问时定下并随回答保存，之后显示、打开依据和追问时逐位复核，任一位不再由你管理（过继、账号停用等）整条回答不展示；之后新增的居民不追溯进旧回答。追问只带入居民名单是本次名单子集的先前私人回答。问题里点名了名单中的某几位时，私人证据只取这几位。微信客户端仍要求先选居民，下一版跟进。

居民私人记录按问题类型和日期筛选。公开查询不会继承先前私人问题的模型上下文。账号失效、居民过继、事件或典籍撤回会使相关旧答案、来源及后续引用受限。摘要不会成为绕过权限的通道。当前浏览器已显示过的内容无法远程收回；页面刷新和后续获取会重新核验。

历史读取采用有界异步扫描，单次最多扫描 500,000 行，最多选取 50 条代表性历史记录，总证据最多 100,000 字节；被截断和覆盖不全的内容明确标识。它不是无限长历史的保证。源码文档、模型内部推理和完整原始快照不直接交给助手模型。

网页通过真实上游流式文本加轮询逐步显示答案。新微信答案在生成任务内通过整条文本审核才完成；在微信查看已有网页答案和来源时也会审核，审核等待有独立上限，未通过或超时不展示原文。

## 网页界面

2026-10-18 改版为对话工作台（[方案](plans/2026-10-18-assistant-page-redesign.md)，布局与组件见 `docs/VISUAL-DESIGN.md` 第 3.5、3.6 节）：左边对话列表，右边工具条、问答流和贴底的提问区，手机上对话列表收进抽屉。问题范围平时缩成一行摘要，点开编辑；居民按名字选，默认「全部居民」；造者密钥只在旧世界私人记录时出现，管理密钥只在管理员私人研究时出现，都只存页面内存。回答按 Markdown 安全子集排版（`public/assistant-markdown.js`，不渲染链接、图片和 HTML），套 AI 标记，底部一行写依据标号、世界日和截至时间。说明文字只留额度一行。

对话标题取这段对话现存且你仍可查看的第一问（最多 40 字，超出加「…」），与消息本身走同一套过期和权限复核；都不可见时写「实验对话」。微信请求仍返回「实验对话」：网页上提的问题没经过微信内容检查，等微信端接上检查再换。

## 存储与费用

`DATA_DIR/assistant/state.json` 保存独立的助手配置、地球日用量、成本预留、会话与证据，权限为 0600。它不进入世界状态或命令回放。模型和验证密钥不会写入此文件；造者和管理验证凭据仅在请求及进行中的任务内存中使用。

每条消息自产生起保存 30 天，访问和上下文组装时立即过滤过期内容，后台定期清理。删除会话会取消其生成任务并使在线内容立即不可读。备份按既有备份周期保留；不承诺删除模型供应商侧记录。不含对话原文的日额度和成本统计保留 90 天。

按核验的上游美元价格及目录汇率换算为人民币成本，不采用居民托管加价倍率。调用前保守预留，结束后核验输入、输出和缓存用量再结算。缺少/不一致用量、进程中断的未结算调用保留全部预留成本；不会通过取消、失败或重启绕过预算。模型路由分组与已验证分组不符时停止，不静默改模型。

旧历史归档增加 `legacyOwnerHash` 和 `redactedDocs` 元数据，用于对应分支的凭证验证与典籍撤回。可验证的旧快照才用于补齐凭证哈希，不把新时间线的凭证用于旧分支。

- 基线全量测试：1942 通过、0 失败、1 跳过。
- 最终全量测试：1996 通过、0 失败、1 跳过（1997 项，约 167 秒）。
- 新功能及历史专项：71 项通过；其后增加的存储故障、权限与审核时限回归均已纳入最终全量测试。
- 网页/微信客户端与导航专项：114 项通过。
- 网页使用一次性本地真实 HTTP 后端和模拟模型验证了提问、渐进回复、来源查看、取消、额度更新及管理员保存配置；检查了桌面和 390px 窄屏，以及文本转义。
- OpenAI Chat/Responses 两类 SSE 用本地流式 HTTP 服务验证；测试确认第一段文本在上游响应结束前可见。
- 微信普通小程序离线构建通过（2 页、46 文件，约 498 KiB）。
