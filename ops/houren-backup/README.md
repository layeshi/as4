# 现有生产定时备份校验修复

这些脚本用于已有 `/usr/local/lib/houren-backup` 安装，并继续使用该目录现存的 `deploy_utils.py`。不是初始化世界或新服务器安装工具。

`hourly-backup.py` 保留原来的锁、隔离副本、完整数据及配置归档、失败重试和权限；改为在部署锁内读取实际运行服务的环境与版本，不使用旧前提环境文件拼出的配置。`backup_active_environment.py` 对 active/PID/cwd/current 前后核对，任何异常直接拒绝，不输出环境值。

`offline.mjs` 只能指向服务器受限的**可丢弃副本**。命令和事件完整流式回放，并核对快照边界。历史归档只读校验和解密，不打开 Runtime；当前世界恢复、关闭后核对命令字节、快照状态、事件输出及边界。完整命令支撑的缺失事件后缀可恢复，损坏或额外事件拒绝；不调用模型，不启动调度器。

历史 P6 归档的账号状态可在归档后变化，所以严格检查历史世界内所有权，当前账号匹配仅为信息；`validBindings=null` 明确表示历史账号状态未作当前有效性断言。活动 P6 世界仍严格校验当前账号版本与绑定。

## 验证与安装

本地 Node 回归：`node --test ops/houren-backup/offline.test.mjs`。Python 模拟测试：`python3 -m unittest discover -s ops/houren-backup -p test_active_environment.py`。

安装前三个脚本时必须一起安装，并先完成目标服务器 Node/Python 专项及真实全 DATA_DIR 隔离副本验证；保存原脚本、属主和权限。在原部署锁内切换脚本，暂时停用备份定时器防止加载半套脚本；任何退出都恢复原定时器状态。随后实际运行一次备份，验证服务退出状态、归档可解包和文件摘要。

在线备份复制多个文件，不是停止点的原子副本；它通过命令尾恢复和账户／运行器绑定检查验证可恢复性。严格停止点备份仍应由项目保状态部署流程完成。私有环境、账号、凭据、原始日志和存档均只留服务器受限目录，不进入仓库。

2026-10-13 的本地独立复核为 Node19项、Python8项通过；服务器全数据和真实备份验收状态另记发布记录，不能用合成测试代替。
